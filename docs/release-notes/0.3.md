# Psyche v0.3.0-alpha (draft)

Draft release notes for the third alpha: Milestone 3 (docs/08-roadmap.md): VM mode, payments end to end, the coding helper, skills you can install, more model providers, the packaged Mac app, and a hardening pass. Written by INT-3. The maintainer cuts the tag. **Do not tag before #414 is fixed:** with it, a default install cannot get a reply from an Anthropic model (see "Known issues").

## What's new

### The Mac app

- Psyche installs from a DMG. The app bundles the Gateway (`psyched`), runs it as a LaunchAgent, waits for it to be healthy and shows the logs if it is not (#387, #390, #394, #396).
- The Psyche Helper app ships inside Psyche.app and starts with it; onboarding and Settings → Devices show its state (#386, #388, #395, #397).
- First run without a terminal: onboarding stores your model provider's key in the vault and binds the model when you finish (#399, #400, #401). This Mac becomes the admin device in one step (#405, #406, #407).
- On unsigned builds the vault key lives in a key-file slot you can see in Settings → Credentials, with a recovery key to confirm (#403, #408, #409).
- The app never silently takes over another copy's Gateway (#410). `psyche doctor --first-run` checks a DMG install (#398).
- Smaller and faster: Psyche.app is about 183 MB (#416). The built Gateway boots warm in about 475 ms with about 148 MB idle (#419).

### VM mode

- Tasks can run inside a sandbox Mac (a macOS VM) instead of your own (L1 to L5). The helper manages the VM's lifecycle, the guest agent, file transfers and permissions (#262). The Gateway runs a Task's commands in the guest through its own node and never falls back to your Mac (#259). Turn it on in Settings → VM mode (#359).

### Payments and travel

- Stripe Link pays from the vault: the purchase card binds the funding source, and a payment can be a hold, a capture, a refund or a decline (#257, #361).
- Travel: find a cheaper flight, hold it behind a purchase card, ticket it behind a second card, and cancel for a refund inside the free window (#264).
- Settings → Credentials lists Stripe Link payments and 1Password links (#366, #370).

### Coding helper

- The agent can fix code in a folder you granted: open the repository, read and search it, edit it with a diff on the card, run its tests in the sandbox (the folder is mounted, never the host shell), commit, and push only after a once-only card that names the remote, branch and exact commit (#273, #276, #288).

### Skills

- Install a skill from a folder after reviewing it: the card shows its source, hash, the tools and approval kinds it declares, and its prompt files. A policy refuses skills that ask for more than they may have, before any card. Updates are detected, and the approved files keep loading until you approve the new ones. Settings → Skills (#248, #350).

### Models

- New local providers: llama.cpp and LM Studio. Gemini through generateContent. Settings → Model & providers lists models, checks whether one can use tools, and sets the primary and utility models (#249, #260, #304).

### Security and hardening

- Touch ID approvals work: the Gateway registers the helper's presence key (#265, #300).
- Admin actions need fresh presence; once enrolled, the Gateway fails closed (#263). Signed audit anchors and `psyche audit verify` (#258). Restoring a backup no longer brings back deleted vault items (#261). Signed update manifests (#252).
- Computer use: the approved app and tier travel with every action, menu clicks need interact, sends in messaging apps need approval, Notification Center is capped, and scripts run out of process and only drive their target app (#310, #320, #325, #332, #334, #360). Computer use pauses in sensitive apps and on sensitive sites when you are not watching (#336, #339, #363, #371, #375).
- Injection: forwarded and quoted text, channel messages, MCP tool descriptions and third-party skill descriptions now taint the turn and are framed as data (#326, #330, #345, #347, #353). An allowlisted sender's turn reads none of your sources (#321, #322, #333).
- Files and searches stay out of Psyche's own state, credential stores and SSH keys (#323, #327, #344, #358). Vault fills are https-only, and sandbox secrets are leased to one command and never appear in argv (#314, #337).
- The egress proxy, MCP output redaction and Cloudflare Access key refresh were tightened (#303, #324, #343).
- Two Anthropic and automation fixes from the 0.2 live gates: thinking blocks replay only under the prompt they belong to (#351), and an automation's notification to you needs no approval (#329, #352).
- Travel: holding a fare writes the trip's itinerary card, and ticketing and cancelling update it, whichever model you use (#413).
- Accessibility pass over the app: landmarks and a skip link, AA contrast with a gate, roles and names for custom widgets (#412, #415, #417, #420, #421).

## Known issues

- **Anthropic models refuse every request while the coding tools are on (#414).** `code.git`'s input schema is not a plain object, and Anthropic rejects the whole request. The coding helper is on by default, so a default install gets no reply from Claude models. Until the fix: a Gateway started by hand takes `PSYCHE_CODING=off`; the packaged app has no switch for it yet. OpenAI likely refuses the schema too, and local models were not tested.

## Acceptance

Offline, at aa4bdbc0 (main at 8203e2f4 plus the acceptance changes), with the scripted provider and fixtures:

- Every scenario passes every hard assertion. Milestone 1: inbox triage, calendar planning, research brief. Milestone 2: shopping up to the Stripe Link payment, the PDF form reply, Messages with a voice note, the subscription audit, the weekly review. Milestone 3: travel (hold, ticket, refund) and the coding helper.
- The skills install scenario (9 of 9) and VM mode against the fake helper (3 of 3) pass.
- The Gateway is killed at 53 seeded random points across ten scenarios with no duplicate side effect.
- The injection corpus (68 cases) passes on the reference stack in every mode. On the stack with the real loop, broker and Gateway tools, nothing executes without approval in 207 runs; 126 runs are refused where the case expected a card.
- No fixture secret appears in any model-visible capture. Accessibility 14 of 14. Budgets met.

Live, on the cheapest Anthropic model (`claude-haiku-5-5`, 2026-10-20, three runs each): eight of the ten scenarios pass every hard assertion in 3 of 3 runs. Calendar planning passes 2 of 3 (one run created Dana's event from a malformed request). The coding helper cannot run on Anthropic as shipped (#414); with that one schema flattened in the test harness, it passes 3 of 3. No OpenAI model and no local model were run.
