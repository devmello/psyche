# Psyche v0.2.0-alpha (draft)

Draft release notes for the second alpha: Milestone 2, "personal agent" (docs/08-roadmap.md): credentials, proactivity, computer use and server mode. Written by INT-3. The maintainer cuts the tag. The live gates in [tests/acceptance/SCORECARD.md](../../tests/acceptance/SCORECARD.md) have run on one hosted model (see "Acceptance" below); no OpenAI model has run.

## What's new

### Credentials and payments

- The credential vault now runs inside the Gateway (#149). Settings → Credentials can edit, delete, search and import items (CSV), and shows each item's recent uses (#215, #222).
- Credential fills work end to end from the vault (#220). The agent sees only a placeholder, never the value.
- 1Password can be a read-only credential source (#119).
- Connector sign-ins are stored as vault items (#136).
- Purchases can be paid through Stripe Link (#111). The shopping scenario pays in Link's test mode (#175).
- The macOS system keychain can hold the vault key (#103).

### Proactivity

- Goals, with confirm-first candidates, check-ins and a heartbeat budget (#113, #142).
- An interest ledger and the Feed: briefings, reranking and cited posts (#127).
- Ideas: mined from what you do, with accept and dismiss (#139).
- Agent tools for goals, ideas and the feed (#167).

### Computer use on the Mac

- The Mac helper gives the agent tools for apps, screens and input, gated by per-app tiers you set in Settings → Computer use (#219, #227, #230, #240).
- Adapters for Calendar, Reminders, Mail, Notes, Finder and Safari, each with its own action matrix (#214, #223).
- Messages (iMessage): the agent reads chat history read-only and sends only after approval (#221). There is an iMessage channel for talking to the agent (#225, #235, #243).
- System-wide dictation: a hotkey, a HUD and Settings (#218, #228, #229, #232). Read-aloud and Personal Voice (#135), and voice memos to transcripts (#105).
- Groundwork for running the agent inside a macOS VM (#172, #173). VM mode is not usable yet.

### Browser

- Logged-out browsing by default, per tab (#109).
- Recordings of navigations, snapshots and actions, with replay (#114, #124).
- A dev-server preview with console and network (#128, #150).
- Real-Chrome mode, with per-task consent and its own Psyche profile (#171, #191).
- Purchase cards show the merchant, the items and the total (#144).

### Chat and documents

- Quote-replies, edit-and-resend forks, incognito chats and transcript view modes (#123, #126).
- Slash-command autocomplete and twelve commands (#151).
- A thread's permission mode and model can be changed (#146, #147).
- File tools that read PDF, DOCX and XLSX text with page references (#197, #202).
- A Files pane with the viewers, and document conversion in the sandbox (#224, #231, #237, #239, #242).
- A Library store with an index (#244).
- A design-system pass over the whole app (#155 to #164).

### Server mode, sandbox and MCP

- A trusted-proxy mode (#133). `PSYCHE_BIND=container` with a token file and verified proxy identities (#201).
- Cloudflare Access assertions are verified (#198). The web client signs in and approves with passkeys (#206, #207).
- Per-device rate limits (#112).
- Grants end with their device and with MCP server changes (#108).
- Restoring a backup no longer brings back revoked devices or grants (#176).
- Backups and the log viewer from Settings (#104, #118, #125). Installers and `psyche migrate --check` (#168).
- The sandbox's `exec` tool is composed into the Gateway (#226), with an egress proxy (#216, #234).
- The MCP host is mounted (#233). Stdio servers run under `srt` or in a sandbox container behind the egress allowlist (#148, #189, #236).

### Agent safety and reliability

- Approved arguments are frozen and re-hashed before dispatch (#195).
- A write-ahead checkpoint before every dispatch, and one card, not two, after a restart (#63, #64, #200, #203). Checkpoints never overwrite a settled step (#188), and receipt short ids continue across restarts (#193).
- The agent's thread state survives a Gateway restart (#185).
- Taint sources and the connector rule reach the broker (#186, #190). Non-owner channel messages stay untrusted in the transcript (#145).
- `task.start` is a write with its own approval card (#48, #199).
- Redirect hops are checked against the task's approved origins (#184, #194).
- Fuzzing of the policy engine and binding hashes found and fixed two bugs (#174).
- Security settings need fresh presence (#178).

## Not reachable from the app yet

The packages have these, with tests, but the app or the Gateway does not offer them on main ([docs/guides/](../guides/README.md) give workarounds; the guides are being refreshed for 0.2):

- connecting a connector (Google, JMAP or IMAP mail) from a client: the protocol has no connect method yet. The JMAP and IMAP connectors (#122, #130) are not composed into the Gateway;
- web search;
- nightly dreaming;
- onboarding's model and key step, which saves nothing (the model still comes from `PSYCHE_MODEL`);
- Touch ID approvals. The helper now signs them (#102), but no presence key is registered with the Gateway yet, so purchases, payments, credential fills and host commands cannot be approved (#253). Deny works.

## Known issues

- With Anthropic models (adaptive thinking), a thread fails with "Invalid signature in thinking block" when its tools or system prompt change between turns: an automation running on a chat thread instead of its own session, entering or leaving plan mode, changing the thread's mode or model, or adding a connector or MCP server (#306). Starting a new thread works around it.
- An automation that notifies you when it finishes asks for approval first: you get an "Approval needed" notice for the notification itself (#307). The automation's result is still delivered to its thread.

## Acceptance

Offline, at 99adbb7a (main at 94fdf2ca plus the acceptance fixes), with the scripted provider and fixtures:

- Eight scenarios pass every hard assertion. Milestone 1: inbox triage, calendar planning, research brief. Milestone 2: shopping up to the Stripe Link payment, the PDF form reply, Messages with a voice note, the subscription audit and the weekly review.
- The Gateway is killed at 49 seeded random points across them (and the Milestone 3 travel scenario) with no duplicate side effect.
- No fixture secret appears in any model-visible capture.
- The injection corpus now has 67 committed cases. All pass in balanced, manual and auto mode on both stacks except one known case: a message from an allowlisted non-owner sender can make the agent read the owner's private chats (#293).
- Accessibility 13 of 13. Budgets met: browser snapshot 3 ms, memory search under 1 ms, Gateway boot to first delta 70 ms with the scripted model.

Live, on the cheapest Anthropic model (`claude-haiku-5-5`, 2026-10-20, three runs each): all eight scenarios pass every hard assertion in 3 of 3 runs. Quality checks (soft) pass 107 of 138; the misses are wording, an outdated source cited in the research brief, and steps the model skipped that the script takes. No OpenAI model has been run. No local model was run for 0.2.

## Upgrading from 0.1

Make a backup first ([docs/guides/backup-restore.md](../guides/backup-restore.md)), then follow [docs/guides/upgrade.md](../guides/upgrade.md). `psyche migrate --check` reports what the new version's migrations would change before you start it.
