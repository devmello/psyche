# S11 plan: desktop and web shells

Owner: S11 (`prompts/s11-desktop-web-shell.md`). Paths: `apps/desktop/**`, `apps/web/**`.
Features: A6, A7, A8, E10, I1, I5, I6, I11, K6, D5, O10 (desktop relay), Q1 (composer UI).

## Goal

One React shell that runs in two hosts: the Electron app (`apps/desktop`) and the browser
(`apps/web`, served by the Gateway at `/`). The desktop adds native capabilities behind a typed
preload bridge: panes over native views, the embedded agent browser and its CDP bridge, the
terminal, dictation capture, notifications, the menu-bar item, quick entry, deep links and
Gateway supervision. The renderer never sees a secret, a token or a device key.

## Shape

```
apps/web/src/shell/          shared React app (exported as @psyche/web/shell)
  platform.ts                ShellPlatform port: gateway, panes host, browser, terminal, voice, notify
  layout/                    pure pane layout engine (per-thread state, split, resize, pop-out, view.*)
  keyboard.ts                keyboard map (docs/06 §4.11) as data + matcher
  components/                rail, thread list, chat, composer, pane chrome, palette, offline banner
apps/web/src/                web host: WebGatewayClient → ShellPlatform (no native panes)
apps/desktop/src/main/       Electron main
  app-protocol.ts            app:// scheme for the renderer (then GrantFileProtocolExtraPrivileges off)
  window.ts                  BaseWindow + app WebContentsView + native-view slots (pane bounds)
  gateway-client.ts          WS client: handshake, RPC, events → renderer
  supervisor.ts              dev: spawn psyched; prod: LaunchAgent via launchctl (plist from S22)
  browser/                   BrowserHost (tabs, partitions, debugger), TakeControl arbiter,
                             CDP allowlist, downloads quarantine, PDF interception
  bridge/                    browser-bridge.sock client: bridge.hello, bridge.* dispatch, events
  terminal.ts                node-pty sessions; target chosen by the Gateway
  tray.ts quick-entry.ts deep-link.ts notifications.ts menu.ts
apps/desktop/src/preload.ts  typed bridge (no generic invoke; each call validated in main)
apps/desktop/e2e/            Playwright-for-Electron smoke tests against a mock Gateway
```

## Interfaces consumed

- `@psyche/protocol`: frames, `Methods`/`Events`, `ViewMethods` + `view.command`, `BridgeMethods`/
  `BridgeEvents`, `ApprovalRequest` (`new_origin`, `credential_fill`), `Notification`.
- `@psyche/ui` (S12) placeholders only (`PsycheMark`, `StatusPill`); every other component is a
  thin local stand-in with the same props shape S12 is expected to ship.
- `@psyche/viewers` (S13): placeholder; the Files/Editor/Artifact panes show a stub.
- Gateway: real `startGateway` for the "web served by the Gateway" test; a mock Gateway (WS +
  bridge socket) in `apps/desktop/test/support` for everything else.

## Protocol gaps (protocol: PR, additive)

Bridge amendments from spike 01: error codes `user_in_control`, `debugger_detached`,
`tab_not_found`, `method_not_allowed`; `bridge.tab.created` gains `openerTabId`/`disposition`;
`bridge.debugger.detached`; `bridge.control.changed.via`; `BRIDGE_MAX_FRAME_BYTES` (16 MiB);
`bridge.snapshot` reserved. `view.report` (desktop → Gateway layout). `voice.*` (S17) and a PTY
open method (S21/S01) are requested, not added: the shell treats `unknown_method` as
"unavailable" and says so.

## Steps

1. Plan, deps, IPC contract, ShellPlatform port, app:// protocol.
2. Pane layout engine + `view.*` handling + persistence (pure, unit-tested).
3. Browser host + take-control arbiter + CDP allowlist + bridge client (tested with a fake tab
   host and a fake Gateway bridge server).
4. Gateway client RPC/events, supervisor (dev child, LaunchAgent), offline UI, backoff.
5. Shell UI: rail, threads, chat, composer (slash commands, attachments, mode/model pickers,
   dictation capture, follow-up queue), palette, keyboard map, browser/terminal pane chrome.
6. Tray, quick entry + global hotkey, `psyche://` deep links, notifications relay.
7. Terminal: node-pty + xterm.
8. Playwright Electron smoke tests; web build served by `startGateway`; macOS unsigned build job.
9. README, `docs/status/s11.md`, independent review, PRs under ~800 lines each.

## Risks

- Electron e2e needs the Electron binary; CI skips its download. Smoke tests run behind
  `PSYCHE_E2E=1` in a dedicated macOS job (S00 owns `.github/`; requested in status).
- node-pty is native: needs `allowBuilds` and an Electron rebuild; terminal tests mock it.
- Bridge direction: the protocol says the desktop connects to the Gateway's socket and sends
  `bridge.hello`; spike 01 had the desktop listen. The doc wins: the desktop is the client.
- S12/S13 land in parallel: keep local stand-ins behind the same names so swapping is mechanical.
