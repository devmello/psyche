# S21 plan: sandbox image and `SandboxRunner`

Goal: K1–K3 and K8 (base) from [03-feature-spec.md](../03-feature-spec.md). This means a nonroot container image and a `SandboxRunner` that runs bounded, receipted commands in a per-scope container with no network. The runner supports Apple `container`, Docker and Podman, and it never falls back to the host shell.

## Inputs

- Contract: `packages/protocol/src/contracts/SandboxRunner.ts`; fake and conformance suite in `@psyche/testing`.
- Architecture §9, security §5.1/§5.2/§5.4, ADR-008.
- Spike 02 (in progress on the spike-02 session's worktree, `spikes/sandbox-backends/results/*`):
  - Flags per backend pass the contract on Apple `container` 1.5.0 and on Docker 29.4 (OrbStack).
  - Signalling the host `exec` client does not stop the process in the container. Interrupts must kill the process group from a second exec.
  - `container cp` fails on Apple, while streaming over `exec -i` stdin works (367 MB/s).
  - Apple volumes come up `root:root`, so a one-shot root `chown` is needed.
  - Apple has no `--pids-limit` or `no-new-privileges`. Use `--ulimit nproc=128:128` and an image without setuid binaries.

## Steps

1. `deploy/sandbox-image/`: a multi-stage Dockerfile. Stage `core` is node 24 trixie-slim plus bash, python3, uv, git, rg, jq and curl. `base` adds pandoc, poppler, pdftk-java and ffmpeg; `full` adds LibreOffice. Also `versions.json` (pinned base digests, published digests) and `build.sh` / `publish.sh` (buildx multi-arch, cosign).
2. `packages/sandbox`:
   - `backends/`: per-backend run/exec/volume argv builders (pure, unit-tested) and detection (injectable probes; order Apple → Docker → Podman on macOS 26+, Docker → Podman elsewhere; explicit override).
   - `cli.ts`: spawn the fixed CLI with argument arrays, capped capture, host watchdog.
   - `runner.ts`: `ContainerSandboxRunner` (contract + `openPty` + `files` + `dispose`). It reuses warm containers, tears down idle ones, enforces per-scope concurrency and restarts stopped containers.
   - `exec`: an inline bash wrapper with a pid file, `setsid` and `timeout -k 2`. Env goes over stdin so it stays out of host argv. Interrupts kill the process group. `filesChanged` comes from `find -cnewer marker`.
   - `files`: an inline Python helper inside the container. It walks from a `/workspace` dir fd with `O_NOFOLLOW` per component and rejects symlinks and special files. Writes are atomic (tmp + fsync + rename); caps are 256 KB for text and 10 MB for import/export.
   - `pty`: an inline Python PTY relay inside the container (no host node-pty), framed stdin for data and resize, and an async-iterator output.
3. Tests: unit tests with no Docker (flags, detection order, caps, path rules, framing). Integration tests run the OpenMuse smoke checks on every detected backend and skip with a message when none is found. The conformance suite runs against the real runner.
4. `pnpm sandbox:smoke` CLI, README, `docs/status/s21.md` with measured cold/warm starts.

## Interfaces

- Implements `SandboxRunner` unchanged. Extras are on the concrete class (`openPty`, `files`, `dispose`) until a consumer asks for them in `protocol`.
- Egress proxy: the caller passes `{ network, url }`. `network` is a backend network with no internet route where the proxy is reachable; `url` is the proxy URL as seen from inside. `network: "proxy"` without this config rejects with `unavailable`.

## Risks

- Podman is untested on this machine (not installed); its flags mirror Docker's.
- CI builds the `core` image stage on every Linux run (a few minutes).
- Prompt vs doc: the prompt asks for 64 KB output caps, while architecture §9 and the contract say 128 KB, so the doc wins. The prompt's `outcome: "timeout"` is `timedOut: true` plus `outcome: "uncertain"` in the contract.
