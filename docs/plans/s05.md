# S05 plan: Permission Broker and audit

Owner: S05. Packages: `packages/permissions`, `packages/audit` (plus migrations for `approvals`, `grants`, `policy_rules`, `receipts` and their `packages/db/src/schema.ts` mirror, as `packages/db/README.md` asks of every table owner). Branch `ws/s05-permissions-audit`.

## Goal

The only component that can authorize a side effect (architecture §4.6, security §3), and the hash-chained audit log plus receipts store (architecture §4.12, data model §5, security §15). M1 = prompt "Mission"; done = prompt "Definition of done".

## Steps

1. **`@psyche/audit`**: strict canonical JSON (RFC 8785 value domain: throws on NaN, ±Infinity, -0, `undefined` in arrays, non-plain objects, BigInt, lone surrogates; no NFC folding, design-13), `sha256`; `auditEntryHash`; redaction (`redactForAudit`: secret keys dropped, body-like keys reduced to `{sha256, bytes}`, secret-pattern strings replaced, an optional `CredentialBroker.redact` hook); stores (`MemoryAuditStore`, `FileAuditStore` writing `audit/YYYY-MM.jsonl`, 0600 files in a 0700 dir, chain continuing across months, optional signed anchors every N entries); `createAuditLog` implementing the `AuditLog` contract plus `query` (kind / kinds / prefix / actor / subject ids / time range / seq range / order) and `export`; receipts store (`MemoryReceiptStore`, `SqliteReceiptStore`) with queries by task, tool call, approval and kind.
2. **Binding hashes** (`permissions/src/binding/`): `bindingHash(kind, fields)` over the strict canonical JSON; per-kind field builders following security §3.5 as the normative table, with the extra fields 04 §4.2 and S23 ask for (exec `sandboxId`, `stdinSha256`; email `replyTo` / `from` / `sender` / `inReplyTo` / `references` and the final MIME hash; form `action`, `method`, hidden fields, submit ref; credential fill field kind and element type; file write mode); canonical targets (origin: lowercase, IDNA → punycode, default port stripped, trailing dot removed, userinfo and opaque origins rejected; email addr-spec extraction and IDN; argv kept exact); grant keys per kind (exact recipient set for email, design-11). Property tests with fast-check: any change to a bound field changes the hash.
3. **Policy engine** (`permissions/src/policy/`): `policy.json` (TypeBox schema, exported JSON schema, example) with deny / ask / allow rules (`tool`, `tool(glob)`, `origin:`, `path:`, `recipient:`, `app:`, `account:`, `command:`), connector matrices, app tiers with fixed caps, site rules, folder grants, sensitive categories, TTLs. Evaluation exactly in the security §3.3 order with a decision trace: hard prohibitions → user deny rules (+ plan mode) → hooks (deny/ask only; a rewrite restarts at step 1 and floors at ask) → taint escalation → standing grants → mode default (security §3.2 table) → classifier (auto mode, tentative `allow` on `write`).
4. **Hard prohibitions** (`permissions/src/prohibitions.ts`), one check and one unit test each: visible password / secret typing, CAPTCHA, card / bank / government-id entry, financial transfers and trades, permanent deletion without the owner's typed confirmation word, instructions from content (`initiator: content`), third-party account creation without approval, loopback origins that are not the owner's project (resolved-address and listener-ownership checks behind interfaces, Gateway ports refused, design-03), settings / grant ledger / pairing / Psyche state edits from a tool call, Safari / Passwords / Keychain reads, placeholders outside fill-capable tools.
5. **Approvals and grants** (`permissions/src/broker.ts`): the `PermissionBroker` contract over a `PermissionStore` (memory and SQLite). Single-use hashed answer tokens per surface, chat surfaces stripped for device-only kinds and `destructive`, chat answers limited to `once`, approver checks through an `ApproverDirectory` (device scope `operator.approvals` or an owner-identity channel sender), optional presence verification (design-04), 400 ms arm delay, answer rate limit, first answer wins, late / replayed answers audited. Grants: `once | task | site | session | always` with TTLs, use counters, `maxUses`, last used binding; `session` stored as its own scope with the boot id (design-28); `task` grants end with the Task; MCP grants bound to the `tools/list` hash with `revokeMcpGrants`; device revocation revokes the grants it created. `reissue()` uses the persisted call and decision context, so taint survives a restart and a re-issued request never auto-allows (design-09). Delivery through `Notifier`; events `approval.created | decided | expired | invalidated`, `grant.created | used | revoked`, `receipt.created`; never answer tokens in events.
6. **Classifier hook**: `ActionClassifier` interface, input built only from owner messages and action metadata; `RulesClassifier` default; `ModelClassifier` over the `ModelProvider` contract behind `classifier.model`; 8 s timeout, fail closed to `sensitive`; circuit breakers (two `prohibited` pause the Task, three consecutive `sensitive` downgrade it to `balanced`).
7. **API handlers**: `approvals.*`, `grants.*`, `audit.*` for the Gateway to mount; `decidedBy` comes from the authenticated connection, never from params.
8. **Tests**: conformance suites from `@psyche/testing`; decision matrix (mode × side-effect × taint × grant); each prohibition; binding properties and golden vectors; expiry and re-issue; replay; scopes and expiry; MCP revocation; audit chain and tamper detection; redaction; S23 design cases 03, 04, 07–09, 11–14, 20, 28 where they land in these packages.
9. README for both packages, `docs/status/s05.md`, doc updates (04 §4 tables and event names).

## Interfaces used

`PermissionBroker`, `AuditLog`, `Notifier`, `CredentialBroker.redact`, `ModelProvider` (classifier), `Clock` from `@psyche/protocol`; fakes from `@psyche/testing`. No other session's branch.

## Risks

- **Doc contradictions** (S23 README, S18 status): chat approval of `destructive` (I follow architecture §4.6 and the contract: device-only), binding tables (05 §3.5 normative, 04 §4.2 extras added), email grant key (exact recipient set), `session` storage (own scope + boot id), Task taint inheritance (caller supplies taint; derived artifacts carry it via `taintSources`). Recorded in `docs/status/s05.md`.
- **Protocol gaps**: no `audit.*` methods, no `grant.*` events, no presence assertion field or `presence_*` error codes in the contract. Implemented locally behind extended types; additive `protocol:` requests listed in the status file.
- **PR size**: the M1 scope is far above 800 lines. Commits are split by concern so the PR can be reviewed commit by commit.
