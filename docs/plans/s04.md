# S04 plan: tasks and scheduler

Session S04 owns `packages/tasks/**` and `packages/scheduler/**`, plus its own tables' migrations in `packages/db/migrations/` (data model §3 and §8). Feature ids: D1–D3, D6, O1, O4 (O2, O3).

## Goal

Durable background work that survives crashes, restarts and laptop sleep: a SQLite-backed `TaskEngine` with leases and checkpoints, an in-process worker pool that drives `AgentLoop` turns, and a SQLite-backed `Scheduler` with cron / interval / one-shot automations, heartbeat, watches and catch-up after sleep.

## Steps

1. **Migrations**: `tasks`, `task_checkpoints`, `task_actions`, `input_requests` (PR A) and `automations`, `automation_runs`, `watches` (PR B), with drizzle mirrors in `packages/db/src/schema-s04.ts`, added to the `schema` object so the parity test covers them (a small additive edit to `packages/db/src/schema.ts`).
2. **Task engine** (`SqliteTaskEngine implements TaskEngine`): every mutation runs in one `BEGIN IMMEDIATE` transaction on better-sqlite3, so two workers (two connections, or two loops in one process) cannot both win a claim. Lease = `lease_owner`, `lease_until`, `lease_token`; the token changes on every claim, so a stale holder's `renew` / `release` fails with `conflict`. Claiming an expired `running` task turns its in-flight `replaySafe: false` checkpoints `uncertain` (never replayed) and resets in-flight safe ones to `pending`. Extensions beyond the contract: run mode (`attended | unattended`) and budgets on the task, `parkForApproval` / `resolveApproval`, `reconcile` for uncertain steps, `attachResources` (browser session, sandbox), and a resume queue that tells the next turn what changed (answers, approval outcomes, recovery).
3. **Worker pool** (`TaskWorkerPool`): N slots claim tasks, run one `AgentLoop.startTurn` per claim, renew the lease on a heartbeat, map `tool_call` events to checkpoints (`replaySafe` from the tool's side-effect class) and Activity lines, enforce budgets (steps, tokens, wall time), and park on `approval_requested` / `question`. A cancelled or paused task aborts the turn: `AgentLoop.cancel(runId)` and `PermissionBroker.revokeRunAuthority(runId)` run immediately. An approval watcher awaits `PermissionBroker.awaitDecision`; approval → re-queue, denial → re-queue with the denial, expiry → the step goes back to `pending` and the task re-queues (security §3.7), restart re-issue → the parked approval id is rebound.
4. **Events and API**: `task.updated`, `task.action` (and later `automation.run.*`) through an injected sink stamped with `stateVersion`; `tasks.*` handlers typed from `TasksMethods` for the Gateway (S01) to mount.
5. **Scheduler** (`SqliteScheduler implements Scheduler`): schedules are a 5-field cron expression (cron-parser 5, IANA timezone, DST-aware), an ISO-8601 duration (interval, heartbeat, watch) or an ISO-8601 instant (one-shot reminder). Durable `next_run_at`; one host timer armed for the earliest due automation and re-armed after every change; `wake()` / timer firing calls `tick`, which coalesces every missed tick into one run (`coalesced = n`). Runs: session target `main | isolated | named:<id>` resolved through an injected resolver; the unattended-run contract is prepended to the prompt with the job's scratch note; the run is launched as a Task (`createdFrom: automation`, unattended); `NO_REPLY` is a first-class outcome; delivery to thread / channel (Notifier) / webhook (through the broker, with a receipt) / none; history in `automation_runs`.
6. **Heartbeat**: a system automation built from `{everyMinutes: 30 | 60, activeHours, timezone}` as a cron expression, with `lightContext` in its options.
7. **Watches**: page change / text present / price threshold against an injected `fetch`; alert only on a transition (dedupe), exponential backoff on failures.
8. **Upcoming** (O4): one query over automations, reminders, briefings, heartbeat and watches with next run times; `automations.*` handlers.

## Interfaces used

`TaskEngine`, `Scheduler`, `AgentLoop`, `PermissionBroker`, `Notifier`, `Clock` (protocol contracts), tested against `FakeAgentLoop`, `FakePermissionBroker`, `FakeNotifier`, `FakeClock`, `describeTaskEngineConformance`. Additive `protocol:` PR: `automation.run.started` / `automation.run.finished` events, an `AutomationRun` schema, `automations.runs` (history) and `automations.upcoming` methods.

## Risks

- `stateVersion` ownership: the Gateway event bus (S01) should own one global counter; S04 takes it as an injected function and falls back to a local counter.
- The loop (S02) decides when a turn checkpoints; S04 derives checkpoints from `tool_call` events, which only knows tool names. Replay safety comes from the tool registry.
- Who creates an `InputRequest` for `ask_user` in a task: S04 adopts the loop's id when the loop already created one.
- Watches use a regex selector over fetched text, not CSS selectors (no DOM in the Gateway).
