# S08 plan: browser subsystem (`packages/browser`)

**Goal.** The agent-owned browser behind `browser.*` tools: one `BrowserDriver` API, a CDP driver over the desktop bridge (default, ADR-007) and a Playwright driver (server/headless and real Chrome). Covers I2–I4, I7–I9 and I15, plus the M1 parts of I10 and I12.

## Shape

```
src/
  origin/      canonical hosts, OriginPolicy (per-task read-only / read-writable sets), reputation hook
  snapshot/    CDP AX tree + DOMSnapshot → pruned text tree, ref registry, paging, sparse detection
  cdp/         CdpTarget (send/on) and PageController: snapshot, actions, waits, dialogs, network, secure fields
  bridge/      NDJSON connection (16 MiB frames), Unix-socket server (0600, hello secret), BridgeCdpTarget
  drivers/     CdpBridgeDriver, PlaywrightDriver (both use PageController), shared session/tab state
  downloads/   magic-byte sniffing, LibraryWriter interface, quarantine import + receipt
  credentials/ vault fill (CredentialBroker.resolve → Input.insertText), never read back
  recording/   opt-in screencast → Library frames + replay index
  tools/       ToolSpecs + executors, ActionGate (PermissionBroker: new_origin, browser_submit, credential_fill)
  testing/     fixture site DSL → HTML server (Playwright) and mock desktop/CDP page model (CDP driver)
  conformance/ describeBrowserDriverConformance, shared by both drivers
```

**Key decision.** The Playwright driver drives each page through a CDP session (`context.newCDPSession`) with the same `PageController` as the bridge driver. Refs, boxes, pruning and action semantics are then identical by construction, which is what I2's "same tool tests pass on both drivers" needs. Playwright owns process, profile, popup, download and dialog lifecycle.

**Policy split.** The driver enforces hard rules on every hop (blocked schemes, userinfo, blocklist, private network, origins outside the task set). It throws `approval_required {kind: "new_origin", origin}` and never decides permissions itself. The tool layer asks the `PermissionBroker`, which applies taint and grants, then widens the policy and retries.

## Steps

1. Origin canonicalization and policy, with edge-case tests (IDN, ports, userinfo, trailing dot, `*.`, IP forms).
2. Snapshot builder over CDP payloads; ref registry with monotonic ids, never reused.
3. PageController plus a mock CDP page model generated from the fixture DSL.
4. Bridge connection/server, then the CDP driver (tabs, popups, control state, downloads).
5. Fixture site (20 pages) and HTTP server; conformance suite; CDP driver passes it.
6. Playwright driver; same suite behind `PSYCHE_BROWSER_TESTS=1`.
7. Tools, ActionGate, credential fill, recording, budgets, README, status.
8. `protocol:` PR: optional driver methods, bridge amendments from spike 01.

## Interfaces used

`BrowserDriver`, `PermissionBroker`, `CredentialBroker`, `ToolRegistry`/`ToolExecutor` and the bridge schemas, all from `@psyche/protocol`, tested against `@psyche/testing` fakes. `LibraryWriter` is local until a protocol contract exists.

## Risks

- The desktop allowlist (spike 01, amendment 4) must permit what the driver sends. The list for S11 is in `docs/status/s08.md`.
- OOPIF content is invisible without `Target.*`, which the desktop denies. Cross-origin frames stay hidden, which is the documented default.
- Playwright tests need a local Chromium. They are skipped unless `PSYCHE_BROWSER_TESTS=1` and a browser is found.
