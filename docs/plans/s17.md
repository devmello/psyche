# Plan — S17 Speech and voice notes (2026-10-19)

## Goal

`packages/speech`: the TypeScript side of dictation (Q1), text-to-speech and read-aloud (Q3), voice memos (Q4) and voice notes across channels (N11). Done when the prompt's definition of done holds: engine selection policy, whisper.cpp transcription on a fixture clip (gated on the model being present), Kokoro synthesis fixture, a transcoding matrix verified with ffprobe, streaming partial/final ordering and vocabulary injection are tested, and the README and `docs/status/s17.md` describe engines, models and formats.

## Shape

| Module | What it does | Docs |
| --- | --- | --- |
| `policy.ts` | Engine registry and selection (Mac node → whisper.cpp on the Gateway → Web Speech in the web client), configured by a `speech` settings object; separate STT and TTS orders | arch §5, ADR-014 |
| `stream.ts` | Partial/final discipline shared by every engine: monotonic finals, volatile partials replaced, abort | arch §5 |
| `vocabulary.ts` | Custom vocabulary from the agent name, contacts and recent topics; bounded, de-duplicated, rendered into a whisper `--prompt` | Q1 |
| `engines/node.ts` | `SpeechEngine` over a `NodeClient` (`speech.transcribe`, `speech.stream.*`, `speech.synthesize`, `speech.voices`): the Mac helper's SpeechAnalyzer / Parakeet / AVSpeechSynthesizer | arch §6 |
| `engines/whisper.ts` | whisper.cpp through the upstream `whisper-cli` binary (argv only, no shell); chunked streaming with a VAD gate; `--prompt` vocabulary | ADR-014 |
| `engines/kokoro.ts`, `engines/cloud.ts` | Local Kokoro-82M (ONNX) and OpenAI / ElevenLabs voices (keys from the vault through an injected resolver) | Q3 |
| `engines/web.ts` | Web Speech in the browser client (last resort; injected `SpeechRecognition` constructor) | arch §5, 06 §5 |
| `models.ts` | Model download manager: pinned URLs and SHA-256, temp file + rename into `$PSYCHE_HOME/models/` | — |
| `transcode/` | ffmpeg runner (injectable, so the Gateway can wrap it in `srt` / the sandbox), channel format table and size caps, PCM → OGG/Opus, MP3, CAF; inbound decode → 16 kHz PCM → transcription | N11, 4.10 |
| `voice.ts` | `voice.*` dictation sessions (start, push audio, partial events, stop/finalize, cancel) that the Gateway exposes to desktop and web clients | Q1, arch §11 |
| `readAloud.ts` | `speech.readAloud(messageId)`: synthesize, store a Library audio item, emit playback events | Q3 |

## Interfaces

- Implements `SpeechEngine` (protocol). Consumes `NodeClient`, `SandboxRunner` (optional ffmpeg host), `ResolvedSecret` (cloud keys).
- Needs, but the protocol lacks: `voice.*` method and event schemas (arch §11 lists the family). Plan: an additive `protocol:` PR with `voice.start/push/stop/cancel` and `voice.partial/final` events; this package defines matching local types until it merges.
- Needs a Library writer and a message reader for read-aloud: local `LibraryWriter` / `MessageSource` interfaces injected by the Gateway (no contract exists yet; noted as a request in the status file).
- Node capability shapes for `speech.*` are proposed here for S14 (status file).

## Risks

- whisper.cpp Node addons may be unmaintained → spawn `whisper-cli` instead (verified by research subagent).
- Kokoro in Node usually pulls `phonemizer` (espeak-ng, GPL) → check licenses; fall back to a runtime that keeps GPL code out of the package, or document the gap.
- ffmpeg's CAF muxer and Opus: verify locally; iMessage's Opus-in-CAF requirement is community-reported only.
- CI has no models and maybe no ffmpeg: gate those tests on presence and document the gate.
