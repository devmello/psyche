# S12 — UI kit plan

## Goal

`packages/ui` is the React kit that psyche-desktop and psyche-web host (docs/06-ui-design.md is the spec). It renders typed Gateway data deterministically: every message block in data model §9.1, the approval and question cards, the agent header and sheet, every screen in UI design §3, the avatar system and the theme. It talks to the Gateway only through a small client interface and typed hooks, so the shells (S11) plug in their WS client and stories and tests plug in a mock.

## Steps

1. **Protocol gaps** (`protocol:` PR, devmello/psyche#7): `questions.*`, `receipts.*`, `artifacts.get`, `feed.*`, `ideas.*`, `goals.*`, the four matching events, and the caller's own `answerToken` on approval reads. Everything else builds against the local copy until it merges.
2. **Foundation**: Tailwind 4.3 CSS entry (`@psyche/ui/styles.css`), shadcn v4 base-nova components on Base UI 1.9 vendored in `src/components/ui`, fixed semantic scales (amber, tomato, grass, sky) and the shadcn name mapping (UI design §4.10).
3. **Theme generator** (`src/theme`): seed → 12-step accent and gray scales for light and dark in OKLCH with colorjs.io (Radix algorithm: seed at step 9, bezier easing between anchors), alpha variants, `--accent-contrast`, WCAG 2 gate with lightness nudging (step 11 ≥ 4.5:1 and step 12 ≥ 7:1 on step 2, contrast text ≥ 4.5:1 on step 9). `ThemeProvider` applies the CSS, `data-theme`, density and reduced motion.
4. **Data layer** (`src/data`): `GatewayClient` interface (`request`, `subscribe`, connection state), a normalized store fed by events with `stateVersion` gap detection and refresh, typed hooks (`useThread`, `useThreads`, `useApprovals`, `useQuestions`, `useTasks`, `useFeed`, `useIdeas`, `useGoals`, `useNotifications`, `useSettings`, …) with optimistic updates reconciled by `stateVersion`, and a `MockGateway` that validates every request and event against the protocol registry.
5. **Avatar system**: 12 original SVG creatures (default: the pale moth), sizes 20/28/40/64/160, states idle / working / needs-you / error / paused / offline, reduced-motion static frames, a generated-image slot.
6. **Message blocks and cards**: Markdown (Streamdown, Shiki with the JavaScript regex engine so no WASM under the shells' CSP), tool rows with three disclosure levels, plan and pinned checklist, approval card, question card, artifact / file / receipt / task blocks, wrap-up box, follow-up queue, reply quote, export menu, and the thread on assistant-ui's external-store runtime.
7. **Agent header and sheet**: Activity, Approvals queue, Upcoming, Soul & Memory (editor slot for `packages/viewers`).
8. **Screens**: Feed, Ideas, Goals, Library, Search, Notifications inbox, Settings sections, Onboarding, thread list and rail, command palette.
9. **Quality gates**: Storybook 10 stories for every component and state; every story rendered in Vitest (jsdom) with axe-core, so a11y runs in CI with `pnpm -r test`; a Playwright screenshot baseline over the static Storybook (`test:visual`, needs a browser, not in CI yet); theme generator tests over 20 random seeds in both modes; hook tests against the mock Gateway.

## Interfaces

- Consumes `@psyche/protocol` types, registry validators and events. No runtime import from other packages; the viewers (S13) arrive as render-prop slots (`renderEditor`, `renderFilePreview`).
- Exposes `@psyche/ui` (components, screens), `@psyche/ui/theme`, `@psyche/ui/data` (hooks and `GatewayClient`), `@psyche/ui/testing` (`MockGateway`, fixtures) and `@psyche/ui/styles.css`.

## Risks

- Scope is very large for one PR; the kit lands as a series (foundation and theme, data layer, blocks, sheet and screens, settings and onboarding) so each stays reviewable.
- Visual regression needs a browser; CI has none, so the baseline is generated locally until S00 adds a Playwright job.
- assistant-ui's runtime moves fast (0.x); the thread uses only its external-store runtime and primitives, so blocks stay ours.
- Approval answers depend on the Gateway delivering the surface `answerToken` (protocol PR above); the card shows "answer from another device" when no token is present.
