# S10 Channels — plan

**Goal.** `packages/channels`: the channel framework (N1), authorization (N2), WebChat (N3), Telegram (N4), designated-person mode (N10), voice notes (N11) and the `channels.*` API, built against `ChannelAdapter`, `PermissionBroker`, `SpeechEngine`, `Notifier` and their fakes. Binding docs: 02 §4.6, §4.10; 05 §3.7, §9; 04 §1, §8; ADR-011; reviews design-12, -21, -22, -26, -28.

## Steps

1. `protocol:` PR (additive): optional `InboundMessage` fields (`identityStrength`, `forwarded`, `quotedText`, `editOf`), `ChannelAttachment.kind / ref / durationMs`, optional adapter methods `sendTyping`, `fetchAttachment`, `health`; `ChannelIdentity` schema; methods `channels.configure`, `channels.pairing.{list,approve,deny}`, `channels.identities.{list,upsert,delete}`; event `channels.status`. Fake updated in the same PR.
2. Framework: `ChannelService` (adapter registry, start with reconnect/backoff, health), inbound pipeline (authorize → commands → route → sink), outbound (Markdown → plain / Telegram HTML, chunking, per-chat and per-channel token buckets, typing).
3. Authorization: `dmPolicy` (`pairing` default, `allowlist`, `open` needs `"*"`, `disabled`), pairing codes (8 chars from an alphabet without 0/O/1/I, 1 h, 3 pending per channel), owner via `ownerIds` + global `ownerAllowFrom`, `identityLinks`, group allowlist + `requireMention` from structured mentions, `contextVisibility`, command authorization, weak transports never owner (design-21), forwarded/quoted text is `untrusted` (design-22), edits never steer.
4. Routing: session keys per `dmScope`; non-owners never land in `main` (05 §9 isolation); owner private sessions get `injectMemory`; designated persons get persona overlay, tool allowlist, no memory, approvals routed to the owner.
5. Approvals over chat: plain-text fixed-template cards with sanitized value slots (design-12), inline buttons or `/approve <id> approve|deny`, answers only from owner identities on strong transports, broker errors mapped to short replies; `deviceOnly`, `financial`, `purchase`, `credential_fill`, `exec_host`, `policy_change`, `pairing` never reach chat.
6. Voice notes: inbound voice → `SpeechEngine.transcribeFile`; outbound synthesize once → transcode once per container (OGG/Opus 48 kHz mono, CAF, MP3) through a `VoiceTranscoder` port (fake until S17 ships one).
7. Adapters: WebChat (owner-only, strong), Telegram on grammY 1.46.0 (long polling, inline keyboards, voice, photos/documents, typing) tested against recorded Bot API fixtures through an API transformer (no network).
8. Storage: `ChannelStore` port with in-memory and SQLite (`@psyche/db`) implementations; migration `packages/db/migrations/<ts>_channels_init.sql` for `channels` and `identities`; pairing rows go through `@psyche/db` pairing repo.
9. API handlers `channels.*`; README (authoring guide, single-owner policy); `docs/status/s10.md`.

## Interfaces I add locally (ports, not contracts yet)

- `InboundSink` — what the Gateway / agent-core receives: `{route, message, provenance}`.
- `LibraryIngest` — attachments into the Library quarantine (no Library contract exists yet).
- `VoiceTranscoder` — PCM → per-channel container (requested from S17).
