# S18 plan — Security and test harness

Prompt: [prompts/s18-security-test-harness.md](../../prompts/s18-security-test-harness.md). Owns `packages/testing/**` (after S00's skeleton) and `tests/**`.

## Goal

Make the cross-cutting acceptance criteria in docs/03 checkable by machine: no secret in model-visible text, no unapproved egress under the injection corpus, resumability without duplicate side effects, and V1 / V2 / V7 scripted end to end. Wire each check into CI as a required status the integrator can enforce.

## Steps

### Phase 1 — content (before S00 merges; no code conflicts)

1. `tests/corpus/injection/`: schema, dependency-free validator, ≥ 150 cases in three family files (web/documents, email/calendar/messages, MCP/skills/memory) across the vectors and goals in the prompt. Each case: payload, context, worst-case tool call, expected outcome `blocked | asked | ignored`, invariants, rationale, doc refs.
2. `tests/scenarios/`: V1 inbox triage, V2 calendar planning, V7 research brief as step lists with fixtures (mailbox, calendar, fixture website set, canned search results), hard and soft assertions, scripted model turns for CI, resumability kill points.
3. `tests/fixtures/secrets/registry.json`: fake vault items, standalone tokens, card / ID pattern samples.
4. PR "[s18 harness] injection corpus and acceptance scripts".

### Phase 2 — harness (after `packages/testing` lands on `main`)

5. Fakes completeness: conformance suites for the contracts S00 left without one (AgentLoop, Scheduler, BrowserDriver, McpHost, ChannelAdapter, SkillLoader, SpeechEngine, ViewerRegistry); `FakeBrowserDriver.site(fixture)` reading `tests/scenarios/*/fixtures/sites`; a mock Gateway server (WS frames per S00's wire spec) for UI sessions; time-travel clock helpers.
6. Secret-leak checker: load the registry, add Luhn / SSN / IBAN / routing+account / passport / private-key detectors and placeholder-resolution checks to `secrets.ts`; a capture API (`captureModelVisible(kind, value)`) the fakes call for prompts, tool results, transcripts, logs, notifications; a Vitest reporter that fails the run on any hit; `pnpm check:secrets` CLI over captured JSONL and over repo text (logs, fixtures, snapshots).
7. Injection runner: load the corpus, drive agent loop + permission broker + executors (real packages where merged, fakes otherwise) with a worst-case scripted model, compare against `expected`, emit `reports/injection.json` (stable ordering, diffable), fail on any less-safe outcome.
8. Resumability harness: run each scenario's script, kill at every listed point (between model events, before / after receipts, while awaiting approval), restart with the same state, assert transcript / receipt consistency and receipt counts (no duplicate side effects; `uncertain` reconciled, not replayed).
9. CI gates in `.github/workflows/`: `typecheck`, `lint`, `unit`, `conformance`, `secret-leak`, `injection-corpus`, `resumability`, `scenarios-scripted` as separately named jobs (required-status names listed in `docs/status/s18.md`). Root workflow edits go through S00 as integrator if `ci.yml` is theirs; otherwise a separate `security.yml`.
10. Review duty: PRs touching `permissions`, `vault`, `browser`, `sandbox`, `channels`, `mcp-host` get a docs/05 mapping comment; findings filed as issues with a failing corpus case or test.

## Interfaces used

`PermissionBroker`, `CredentialBroker`, `AgentLoop`, `ModelProvider`, `BrowserDriver`, `McpHost`, `ChannelAdapter`, `MemoryStore`, `SkillLoader`, `TaskEngine`, `AuditLog`, `Clock` from `packages/protocol/src/contracts`; fakes in `@psyche/testing`. No protocol changes planned; if the runner needs a hook to observe model-visible text, it is proposed as an additive `protocol:` PR (an optional `observer` on the agent loop) rather than reaching into another package.

## Risks

- **Expected outcomes drift from S05's policy.** The corpus encodes docs/05; where S05's implementation legitimately differs, the doc is updated first, then the case. Ambiguities go to `docs/status/s18.md`.
- **Worst-case model runner overstates risk** for cases a real model would refuse, and understates it for multi-step attacks. The nightly live-model run (docs/05 §7.4) covers the second half; it is behind `PSYCHE_LIVE_TESTS=1`.
- **Fakes pass where real packages fail.** Every runner prefers the real package once merged; the report records which implementation each case ran against.
- **Leak checker false positives** (Luhn-valid order numbers): pattern detectors need context (card keywords, grouping) and an allowlist per test, never a global disable.
- **CI ownership.** `.github/workflows/ci.yml` is S00's; S18 adds jobs by PR and coordinates required-status names with the integrator.
