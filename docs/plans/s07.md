# Plan — S07 Memory (2026-10-19)

## Goal

`packages/memory`: the workspace the owner can read (`$PSYCHE_HOME/workspace/`) plus the local index the agent searches, behind the `MemoryStore` contract. Feature rows H1–H5, H7, H8 (M1); H6, H9, H10 scaffolded or deferred to M2. Done when the definition of done in `prompts/s07-memory.md` holds and `pnpm -w typecheck && pnpm -w lint && pnpm -r test` pass.

## Steps

1. **Protocol PR** (`protocol: memory methods, events and AGENTS.md protection`): add `AGENTS.md` to `PROTECTED_MEMORY_FILES` (docs/05 §8); add the `memory.*` methods the Soul & Memory sheet needs (list, read/write with etag, daily notes, claims, explain, forget, remember, import, export, reset, pause) and the events `memory.file.changed` and `memory.job.updated`. Additive only.
2. **Migration** `packages/db/migrations/<ts>_memory_index.sql`: `memory_files`, `memory_chunks`, `memory_fts` (FTS5, external content), `memory_claims`, `memory_jobs`, plus the drizzle mirror the db parity test requires. `memory_vec` (vec0) is created at run time because the extension is loaded at run time and the dimension depends on the embedder.
3. **Workspace**: path confinement (relative, no `..`, no symlink escape), first-run copy from `templates/` with `{{token}}` substitution, etag (sha256) read/write, the protected-file gate, daily-note append-only rules and tag clamping, `IDENTITY.md` frontmatter, `USER.md` directives with supersession, `bootstrapContext()` with per-file / total / `USER.md` budgets and visible markers, file watching (debounced `fs.watch` plus a hash rescan).
4. **Index**: deterministic line-based chunker (400 / 80 tokens; one chunk per daily-note entry so provenance is exact), FTS5 BM25, embeddings through `ModelProvider.embed`, sqlite-vec when it loads and brute-force cosine otherwise, the ranking formula from docs/04 §7 with provenance and source filters, incremental reindex by file hash.
5. **Store**: `SqliteMemoryStore implements MemoryStore`, passing `describeMemoryStoreConformance`; claims with `supersedes`; `forget` that retracts claims, deletes matching daily-note lines and chunks, rebuilds, and writes a retraction line that names no content.
6. **Tools**: the `memory_20250818` command handler, `memory_search`, `memory_explain`, `forget`, `remember`, `sessions_search` (against a Gateway-provided transcript query), with tool specs for the registry.
7. **Flush**: `flush(threadId, privateTranscriptCopy)` → one utility-model turn → filtered bullets appended to today's note only.
8. **Data API**: list/read/write with etag, daily-note browser queries, pause flag, incognito (no writes), export (zip), reset (dry-run + destructive call), importers (OpenClaw workspace, ChatGPT and Claude exports, free text), `memory.*` handlers and events.
9. README (file formats, provenance rules), `docs/status/s07.md`, independent review subagent, PR.

## Interfaces

Implements `MemoryStore`. Consumes `ModelProvider` (`embed`, `stream` for the utility model), `Clock`, `PsycheDb` from `@psyche/db`, and an approval verifier (an adapter over `PermissionBroker.get`). Provides tool handlers for S02, `memory.*` handlers and events for S01, `bootstrapContext()` for context assembly (S02).

## Risks

- sqlite-vec is a native extension; it may not load on every platform → brute-force cosine fallback, tested both ways.
- Provenance laundering: the agent could forge `[owner]` tags through the memory tool → tags in new lines are clamped to the writer's provenance; non-owner writes to daily notes must be appends.
- `templates/` belongs to S20 (PR #3, unmerged) → the template directory is a constructor option; tests use small fixtures and run against the real templates when present.
- The db parity test lists every table; FTS5 shadow tables need excluding (one-line change in `packages/db/test`).
