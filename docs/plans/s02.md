# S02 plan: agent runtime (`packages/agent-core`)

Goal: the loop that turns a user message into model calls, tool calls, approvals, questions, plans and receipts (C1–C5, C8, C9, C11, B7), built against the contracts in `packages/protocol` and tested with the fakes in `packages/testing`.

## Steps

1. **Protocol PR** (`protocol:` prefix, additive): `AgentLoop.explainContext?` with `ContextSection` / `ContextExplanation` (C11); `ToolRegistration.describeCall?` so an executor's package can state the per-call side effect, approval kind, target and binding fields (security §3.5); `MemoryStore.flush?` for the pre-compaction flush (B7, architecture §4.8). Fakes updated in the same PR.
2. **Tool registry**: `ToolRegistry` implementation, `defineTool` (TypeBox schemas are JSON Schema; params validated with `Value.Check`), `mcp__<server>__<tool>` naming helpers, `activeTools(mode, runMode, toggles)` (plan mode → `sideEffect: none` only; unattended → no `ask_user`).
3. **Context assembly** (C2): base prompt → persona files via `MemoryStore` (20k/file, 4k `USER.md`, 60k total, visible missing/truncated markers) → skills index → tool list for the mode → today/yesterday daily notes → compaction summary → transcript with provider-native parts untouched. Every assembled prompt is kept per run for `explainContext` (C11).
4. **Loop** (C1): pi-agent-core semantics. `steer` skips the remaining tool calls of the current batch and injects guidance; `followUp` runs after the turn would end; `finishTurn → end | continue`; hooks in architecture §13 order; step and token budgets; cancellation revokes run authority through the broker.
5. **Permission path**: every call → `before_tool_call` hooks (block / suspend) → `PermissionBroker.decide` with the turn's taint and `newTarget` → `ask` parks the run on `awaitDecision` (attended) or queues the approval and notifies (unattended) → `verifyBinding` before dispatch → receipt for write+ actions.
6. **Provenance and taint**: results take the executor's provenance, never downgraded below the spec's `provenanceOut`; any `untrusted` result (or provider-executed tool result, or an `[untrusted]` daily-note line) taints the turn; taint survives compaction.
7. **Built-ins**: `ask_user`, `update_plan`, `wrap_up`, `exit_plan_mode`, `memory`, `task.start`, `schedule`, `notify` (each registered only when its contract is supplied).
8. **Compaction** (B7): token estimate against the model's context window → `MemoryStore.flush` on a private copy → `before_compaction` → utility-model summary of older turns; the summary keeps an `untrusted` flag when it summarized untrusted content.
9. **Composer commands** (C9): `parseComposerInput` → `ComposerIntent` for the Gateway and UI.
10. Tests with scripted `FakeModelProvider`; golden prompt for a fixture workspace; README with hook diagram; `docs/status/s02.md`.

## Interfaces used

`AgentLoop`, `ToolRegistry`, `ModelProvider`, `PermissionBroker`, `MemoryStore`, `SkillLoader`, `TaskEngine`, `Notifier`, `Scheduler`, `Clock`. Agent-core defines (locally, consumed by the Gateway): `ThreadStateStore` (transcript, summary, checklist per thread), `HookRegistry`, `ComposerIntent`.

## Decisions

- Attended approvals and attended `ask_user` park inside the turn (run status `awaiting_approval` / `awaiting_input`) and resume when the broker decides or `answerQuestion` is called. A run with a `taskId` hands questions to `TaskEngine.requestInput` and ends with outcome `awaiting_input`; the task engine starts a new turn with the answer.
- Unattended runs: `ask_user` withheld; `ask` decisions become queued ApprovalRequests plus a notification and the tool result says the action was deferred; text is buffered so `NO_REPLY` produces no message; an empty final fails.
- Hooks run before `decide`; they can block or suspend, never allow, so the broker still sees every call.
- The prompt says "zod → JSON Schema"; the protocol is TypeBox, whose schemas are JSON Schema already, so tools are declared with TypeBox (doc wins: `ToolSpec.inputSchema` is JSON Schema).

## Risks

- Tool names with dots (`task.start`) are not valid for every provider; the model router (S03) has to map them.
- `MemoryStore` has no delete/rename, so the `memory` tool's `delete` / `rename` commands return an error until S07 adds them.
- The transcript store is in-memory by default; the Gateway (S01) supplies a persistent one.
