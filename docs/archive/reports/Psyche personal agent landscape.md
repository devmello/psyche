# Clone Muse's surfaces onto a local gateway

Psyche should copy Meta Muse's product shape almost wholesale — one persistent conversation with side chats, a user-named creature avatar whose header opens Activity, Approvals, Upcoming and Identity, a left rail of **Chat, Search, Feed, Ideas, Goals and Library**, deterministic approval cards with "Allow once / for this task / for this site / Always / Deny" scopes, per-connector Allow/Ask/Deny matrices, and user-editable SOUL, IDENTITY and MEMORY markdown files — while refusing the parts reviewers punished (training on by default, hourly dossiers on non-users, delete-that-doesn't-forget, silently inferred goals, human-staffed phone calls). It should build that face on the architecture every credible open-source peer has converged on: **a single long-running TypeScript gateway** (loopback WebSocket plus SSE, SQLite, markdown memory, a skills directory, channel adapters, a scheduler and an approval ledger) with the macOS app as a thin, signed **Electron 44 shell plus a Swift helper** for TCC-gated work, and the identical gateway running in Docker on a Linux server behind Tailscale. Electron is the only mature shell that yields an embedded, persistent, agent-owned browser (WebContentsView plus CDP) the user can take over; Vercel AI SDK v7 plus a home-grown router covers multi-model including Ollama; Apple's Virtualization.framework gives the optional "Mac inside the app" (hard-capped at two guests, provisionable unattended only on macOS 27); Apple `container` or Colima plus Anthropic's `srt` cover Linux sandboxes; MCP spec 2026-07-28 with three trust tiers and tool-definition hashing covers connectors; OpenClaw's pairing/allowlist model covers designated-person channels; Stripe Link Agent Wallet covers payments. The single most important field lesson is restraint on proactivity: **ChatGPT retired its autonomous Pulse feed in June 2026 and OpenClaw removed inferred commitments in v2026.8.1**, so Psyche's Feed, Ideas and Goals must be bounded daily batches of evidence-linked candidates the user confirms, and every consequential action must pass through a Sentinel-style approval bound to the exact operation. One correction to the brief: the project described as "opendots" (Documents → PDF → reviewed reply → receipt, Gmail/Calendar adapters, nonroot Docker computer, Rich Threads) is **CopilotKit/openmuse ("OpenMuse")**, created one week after Muse launched; CopilotKit/OpenDots is the separate clone of OpenAI's Dots, and both are analysed below.

## Muse's winning moves are its surfaces and trust UX, not its cloud VM

Meta launched Muse on **September 8, 2026** in the US on iOS, Android, muse.ai and WhatsApp, "free for most of what people need" with $20 Power and $100 Maximum tiers, a payment card required even for the free tier, and a usage meter that "shows the percentage of usage remaining" ([Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/); [TechCrunch](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/)). The Mac app followed on September 18 and can work with files, messages, calendar, notes and mail "all within their native applications" ([TechCrunch](https://techcrunch.com/2026/09/18/metas-muse-hits-mac-letting-the-ai-take-actions-on-your-computer/)); an iPad app arrived October 7, by which point Sensor Tower counted **6.6 million installs** and TechCrunch was describing a "text-heavy interface" ([TechCrunch](https://techcrunch.com/2026/10/07/metas-muse-launches-on-ipad-just-a-month-after-its-mobile-debut/)). Every user gets a per-user cloud VM: Muse "has its own computer with a file system and terminal," "a full web browser," "runs background work on a schedule and in response to events," and "notifies the user only when results are meaningfully new or need input" ([Meta: How We Designed Muse](https://introducing.muse.ai/)). The paid tiers are token-metered weekly pools rather than feature gates (Power is quoted at 500M tokens per week, Maximum at 3B) ([saascrmreview](https://saascrmreview.com/how-to-use-meta-muse/)), which is the first thing Psyche should imitate structurally: show a visible usage and cost meter per model, not plans. Muse Spark (first released April 8, 2026) is the only model and there is no picker — "There is one model, and it is your Muse assistant" — and "Your agent is the same everywhere" across devices ([Signal Drifts](https://signaldrifts.substack.com/p/how-to-muse-the-ai-agent-that-does)); Meta's Muse Glimmer 30B (Apache 2.0, August 10, 2026) is explicitly "designed for local agentic use cases" and is the obvious local default for a Muse-like app ([Hugging Face](https://huggingface.co/blog/muse-glimmer)).

The information architecture is the most consistent thing across every hands-on source. On the Mac the window has a left rail of **Chat** ("conversations, with side chats for separate tasks"), **Search** ("finds things within Muse"), **Feed**, **Ideas** ("suggested workflows and tasks"), **Goals** and **Library** ("documents, artifacts, and media you've sent or received"), and a bottom-left menu whose Settings hold Computer use, File system access, Permissions, Devices and Data controls ([The Rundown](https://app.therundown.ai/guides/how-and-why-to-set-up-meta-muse-desktop)); phones put five tabs at the bottom — Chat, a news-style Feed, a light-bulb Ideas tab, a check-mark Goals tab and a media Library — with the thread list (main chat plus side chats) top-left ([Signal Drifts](https://signaldrifts.substack.com/p/how-to-muse-the-ai-agent-that-does); [creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)). The agent lives in the chat header: "A snippet of current work appears under the avatar. Tapping the avatar opens the full activity log and the permissions the user has approved" ([Meta: How We Designed Muse](https://introducing.muse.ai/)), and that sheet exposes four icons — a task list (most recent first; tap a task to see every action), approvals, upcoming items such as reminders, and a fingerprint icon for "Soul and memory" ([creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)). The Identity area holds three files — Memory ("information you share"), Soul ("who your Muse is, including core truths, boundaries and personality") and Identity ("your Muse's name, creature, vibe or tag line") — and "All three files can be edited or deleted directly"; the Library carries a "System Files" section with everything uploaded or created ([saascrmreview](https://saascrmreview.com/how-to-use-meta-muse/)). Meta's David Singleton framed this as policy: "We want you to be able to see the markdown files Muse writes" ([TIME](https://time.com/article/2026/10/06/meta-muse-ai-agent-privacy/)). On the Mac, first run asks separately for Screen Recording and Accessibility (each skippable), then offers per-app access to Mail, Messages, Notes and WhatsApp, and each Mac app can be set to **Off, Read only, or Read and interact** ([The Rundown](https://app.therundown.ai/guides/how-and-why-to-set-up-meta-muse-desktop); [AI Agents Library](https://www.aiagentslibrary.com/blog/how-to-use-meta-muse/)); holding the function key dictates into any app ([Signal Drifts](https://signaldrifts.substack.com/p/how-to-muse-the-ai-agent-that-does)).

The design principles are documented unusually well. Product design lead Alex Cornell's guiding question was "How would this work if you were talking to another human?", which produced one persistent main chat treated as "an ongoing relationship," side chats for scoped tasks, and a **three-level progressive disclosure of agent activity** — "a simple emoji for casual users, a task list for anyone who wants more detail, and raw logs for engineers" — with the explicit stance that "Showing chain-of-thought is often a latency workaround. Muse is fast enough to work quietly and simply deliver results" ([Lenny's Newsletter](https://www.lennysnewsletter.com/p/how-i-ai-how-meta-designed-muse-with)). Meta's own write-up adds that the system prompt opens with "Your purpose is to make your user's life better," that "The design centers on one long conversation, not turn-by-turn exchanges. Users can interrupt or send several tasks at once," that proactive messages must be "worth the interruption" (users can turn proactivity off, lower it or raise it), that the team used "fixed UI for structured approval cards with accept and reject actions, and for secure credential storage" to avoid banner blindness, and that "Users create, name, and style their own avatar" because talking to a corporate logo felt odd ([Meta: How We Designed Muse](https://introducing.muse.ai/)). The rest is "generative UI": the structure stays fixed (avatar, feed items, idea cards) while content and small animations vary per person ([iMasters](https://imasters.com/design-ux/how-meta-designed-muse-to-not-feel-like-an-ai-app)). Persona customisation is complete: the default avatar "Jolly" is cream-coloured with beady eyes, users change name and attire, Zuckerberg's wears a toga ([NBC New York](https://www.nbcnewyork.com/news/national-international/meta-muse-ai-agent/6552007/)), and a pencil icon accepts plain-language edits such as "change avatar to a pink hippo" ([creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)). The Soul file "changes how the agent behaves, not just what it knows" ([saascrmreview](https://saascrmreview.com/how-to-use-meta-muse/)), and Meta's instructions tell the agent "You are not a chatbot" and "You are becoming someone" ([TIME](https://time.com/article/2026/10/06/meta-muse-ai-agent-privacy/)). Reviewers rewarded this: Claire Vo called it "the best-designed personal agent" she had tested ([Lenny's Newsletter](https://www.lennysnewsletter.com/p/muse-review-the-personal-ai-agent)), while the admitted weak spot is that "It is unclear to users when a topic should 'leave' the main thread" ([iMasters](https://imasters.com/design-ux/how-meta-designed-muse-to-not-feel-like-an-ai-app)).

Feed, Ideas and Goals are three views over the same background machinery. The Feed is "Short posts your agent writes for you on a schedule," including briefings and reminders, and "You control what it writes about" ([Signal Drifts](https://signaldrifts.substack.com/p/how-to-muse-the-ai-agent-that-does)); users heart and comment on posts ([creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)), and a new account "may need to generate its first feed" ([The Rundown](https://app.therundown.ai/guides/how-and-why-to-set-up-meta-muse-desktop)). Ideas "are generated from goals, patterns, and past conversation" and "appear as onboarding tips, in the Ideas tabs, and as proactive suggestions tied to goals" ([Meta: How We Designed Muse](https://introducing.muse.ai/)); tapping one opens a "Let's do it" popup with a toggle to run it as a recurring task such as weekly concert searches or daily fare checks ([creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)). The Goals tab "shows everything Muse is tracking and its plans toward each goal," and the agent "Returns to the user when something changes or when it needs approval" ([Meta: How We Designed Muse](https://introducing.muse.ai/); [Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)), with categories such as health, finance, career, relationships and productivity ([MindStudio](https://www.mindstudio.ai/blog/meta-muse-ai-agent)) and goals deleted from a three-dot menu with confirmation ([saascrmreview](https://saascrmreview.com/how-to-use-meta-muse/)). The exported runtime shows how this is produced: an hourly memory job, a nightly "dream" that "Reviews recent conversations and writes guidance under `~/dreams/`," and jobs that "Maintain relationship pages, review recurring workflows, and prepare ideas or goal briefings" ([mouse.dev](https://mouse.dev/blog/muse-runtime-export/)).

Approvals are where Muse is most worth copying exactly. Architecturally, "Muse proposes actions, but only Sentinel can grant permission"; each request resolves to allow, deny or ask, and when asking, "execution stops and a pending approval is created," the dialog "appears in the client UI, not via their conversation with Muse," and grants are "strict capabilities, not conversational suggestions" that can be "one-time, session-scoped, task-scoped, time-bounded, or perpetual" ([Meta research post](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). In the app the options read **Allow once, Allow for this task, Allow for this site, Always allow, Deny**, and Settings > Permissions offers "Always ask" or "Ask for some actions" ([AI Agents Library](https://www.aiagentslibrary.com/blog/how-to-use-meta-muse/)), where "Ask for some" means approval for writes and important reads ([rywalker](https://rywalker.com/research/meta-muse)). Each connector exposes per-action Allow/Ask/Deny controls ([The Rundown](https://app.therundown.ai/guides/how-and-why-to-set-up-meta-muse-desktop)), email access is chosen as read-only or send-capable ([Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)), connector tokens live in an isolated container the agent cannot read, browser logins are captured by a client UI that sends credentials "straight to authd," the browser sub-agent sees an accessibility-tree snapshot and cannot run page JavaScript, and checkout "requires human approval showing the exact purchase details each time" with a **single-use card tied to one merchant, one amount and a limited time window** ([Meta research post](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)). The browser view offers "Open browser," "Take control of the browser" and "Stop the task," a status pill shows the current action, and closing the view does not stop the task ([AI Agents Library](https://www.aiagentslibrary.com/blog/how-to-use-meta-muse/); [creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)). Clarifying questions are plain conversational interviews — a subscription audit asks what to unsubscribe from, a movers task asked for addresses, bedroom count and stairs ([creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md); [Engadget via Yahoo](https://finance.yahoo.com/technology/article/metas-muse-is-an-impressively-capable-ai-agent-despite-some-hiccups-173310662.html)); no source documents selectable-answer chips, which is one place Psyche can improve on Muse. Users still complain it "asks for too many approvals" ([Hacker News](https://news.ycombinator.com/item?id=49802871)), which argues for the "Ask for some" default with standing grants rather than "Always ask."

What Psyche should not copy is equally clear. "Help improve our AI models" is on by default ([Learn AI with Mariah](https://learnaiwithmariah.com/guides/meta-muse-6-things-to-try/)); deleting a conversation does not erase what Muse learned ([Atlanta News First](https://www.atlantanewsfirst.com/2026/10/09/metas-new-muse-ai-agent-raises-privacy-concerns/)); TIME found hourly-updated dossiers on users and on non-users they mention and a design that infers goals users have "not said out loud" ([TIME](https://time.com/article/2026/10/06/meta-muse-ai-agent-privacy/)); some phone calls were quietly placed by human contractors ([Reuters via WHBL](https://whbl.com/?p=1009458)); an undocumented `endo_voyager_dictation_endpoint` preference let local code redirect dictation traffic, capture audio and steal the auth token until a hot-fix on September 22 ([Unite.AI](https://unite.ai/meta-hot-fixes-muse-zero-day-that-let-attackers-hijack-the-ai-agent)); Amazon blocked Muse as "an unauthorized AI agent" ([Fortune](https://fortune.com/2026/09/22/metas-muse-ai-is-exploding-in-popularity-and-drawing-heated-backlash/)); and reliability misses included a fabricated phone number and a years-closed restaurant ([Engadget via Yahoo](https://finance.yahoo.com/technology/article/metas-muse-is-an-impressively-capable-ai-agent-despite-some-hiccups-173310662.html)). The retention curve — day-14 retention around 22% ([LetsDataScience](https://letsdatascience.com/news/meta-muse-posts-early-retention-metrics-20041f82)) after 5 million US downloads in 22 days ([Crypto Briefing](https://cryptobriefing.com/meta-muse-app-store-retention/)) — says the surfaces drive trial and the proactive layer must earn habit honestly. The memory internals are nonetheless a good data model to borrow: `/home/hatch` holds `SOUL.md`, `IDENTITY.md`, `USER.md`, `MEMORY.md`, `AGENTS.md`, `TOOLS.md`, dated files under `memory/`, `dreams/`, and `/opt/hatch/skills/` with about 68 skill directories, while Postgres tables `memory.entries`, `memory.embeddings` (384-dim) and `memory.claims` with `supersedes_claim_id` back a "forget" skill that stages claim IDs for retraction and rebuilds the index ([mouse.dev](https://mouse.dev/blog/muse-runtime-export/)). Psyche should keep that supersession model but make "forget" actually delete.

## Peers converge on one gateway, thin shells and four card types

The Claude desktop app is the most instructive proprietary peer because its internals are inspectable. Version 2.42304.0 is an **Electron 44.7.2** shell whose native capabilities come from two N-API addons (`@ant/claude-swift`, a Swift addon handling VM management, dictation, quick entry, tray and watch recording, plus a Rust napi-rs binding) and signed helper executables (`app-cu-helper`, `disclaimer`, `permission-fixer`, `chrome-native-host`); it embeds the Claude Agent SDK and downloads separate Claude Code binaries for the host and for the VM, and its IPC is generated Electron channels renderer-to-main, N-API main-to-native, JSON-RPC over vsock host-to-guest, and Unix sockets for the browser shim and Chrome native host ([Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app)). Its Chat surface is literally the claude.ai SPA loaded from Anthropic's CDN, while the Code tab is a native pane workspace of "chat, diff, browser, terminal, file, plan, tasks, subagent, and iOS Simulator" panes, with Dispatch, Scheduled/Routines, Projects and Customize in the sidebar ([Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md)); October 2026 added nested sessions that "appear under the original in the sidebar and report back," a `/btw` side chat pane, saved Environments and a session rail with a context card ([Claude Desktop changelog](https://claude.com/docs/cowork/changelog.md)). The reusable idea is that the agent itself manipulates the workspace through host-provided tools — `ccd_sidebar`, `ccd_session_mgmt` (`export_transcript`, `search_session_transcripts`), `ccd_view`, `ccd_session.hand_off_to_session` (fork with a remaining plan), `ccd_turn.update_plan` (a task list pinned under the latest message) and `wrap_up` (a recap plus one question with reply buttons) ([tool manifest observed in-session](file:///Applications/Claude.app/Contents/Resources/app.asar)). The host renders **four card types from tool traffic**: permission cards from `control_request`, question cards from `AskUserQuestion` (1–4 questions, 2–4 options each, optional multi-select, an "Other" row, optional markdown/HTML previews), plan-approval cards from `ExitPlanMode`, and the plan list/next-step box from `update_plan`/`wrap_up` ([Agent SDK: user input](https://code.claude.com/docs/en/agent-sdk/user-input.md); [Tools reference](https://code.claude.com/docs/en/tools-reference.md)). Permissions flow through one pipeline — hooks → deny rules → ask rules → mode → allow rules → `canUseTool` — and `AskUserQuestion`, MCP tools flagged `anthropic/requiresUserInteraction` and `rm` on critical paths are never auto-approved ([Agent SDK: permissions](https://code.claude.com/docs/en/agent-sdk/permissions.md)). Scheduling has three tiers (cloud Routines at a 1-hour minimum, Desktop local tasks at 1 minute, in-session `/loop`), plus Dispatch from the phone with child-task states Running, Awaiting input, Awaiting answer, Completed, Error and Archived ([Run prompts on a schedule](https://code.claude.com/docs/en/scheduled-tasks.md); [Dispatch guide](https://claude.com/docs/cowork/guide/dispatch.md)).

Its three "dangerous" subsystems are instructive as much for their failures as their designs. The built-in browser is an Electron pane with its own storage partitions, driven by a Playwright-style tool set (`read_page` accessibility tree, `find` returning `ref_N` handles, `computer`, `form_input`, console and network readers) on top of a `playwright-core` dependency, gated per site by Allow once / Always allow / Deny cards plus safety classifiers on write actions "in every mode," with sign-ins kept in the app's own profile ([Built-in browser (3P docs)](https://claude.com/docs/third-party/claude-desktop/browser.md); [Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md); [app package.json](file:///Applications/Claude.app/Contents/Resources/app.asar)). Computer use runs on the real desktop through the Swift addon, needs Accessibility and Screen Recording, applies fixed app tiers (browsers and trading platforms view-only, terminals and IDEs click-only, everything else full), per-app session grants, hides other apps, excludes the terminal from screenshots, downscales screenshots to about 1372×887 and consumes a global Esc so prompt injection cannot dismiss dialogs ([Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md); [Computer use from the CLI](https://code.claude.com/docs/en/computer-use.md)); the decompiled AX dispatcher even carries a `secureField` refusal code, so password fields are refused below the model ([Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app)). The Cowork sandbox is an Ubuntu 22.04 VM on Apple's Virtualization.framework with a Go root daemon over vsock, gVisor networking that blocks `socket()`, and a host MITM proxy with an SNI allowlist ([Pluto Security](https://pluto.security/blog/inside-claude-cowork-how-anthropics-autonomous-agent-actually-works/)); the July 2026 "SharedRoot" chain combined a guest kernel CVE with a read-write host mount to reach files across the Mac for roughly **500,000 users**, and new Pro/Max sessions have defaulted to the cloud since October 6 ([The Hacker News](https://thehackernews.com/2026/07/claude-cowork-flaw-could-let-ai-agent.html); [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)). Memory is three-layered (per-repo auto memory as a `MEMORY.md` index of which only the first 200 lines or 25 KB load, account memory with sensitive categories excluded, and project memory) ([How Claude remembers your project](https://code.claude.com/docs/en/memory.md)); connectors are remote MCP servers with per-tool Always allow / Needs approval / Blocked settings or local `.mcpb` desktop extensions whose sensitive `user_config` lands in the OS keychain ([Get started with connectors](https://claude.com/docs/connectors/overview.md); [modelcontextprotocol/mcpb](https://github.com/modelcontextprotocol/mcpb)).

OpenMuse is the open-source project that actually matches the brief's "opendots" description: GitHub code search resolves the phrases "requested form values," "exit receipts," "reviewed reply" and "server-only project key" to `CopilotKit/openmuse` ([GitHub code search](https://github.com/search?q=repo%3ACopilotKit%2Fopenmuse+%22requested+form+values%22&type=code)), an MIT, alpha, single-owner template created **2026-09-15** (one week after Muse) with 5,240 stars ([GitHub](https://github.com/CopilotKit/openmuse)). Its README feature table is a near-verbatim Muse map: Chat with inline email, browser, PDF, plan and finance cards and a visible follow-up queue; an "Agent computer" with persistent browser profiles, a takeover console and an optional isolated Linux terminal with saved command receipts; Activity with durable task plans, input requests, pause/resume/cancel/retry and approvals; Ideas with source evidence to edit, accept or dismiss; Goals and Tracking with recurring public-page checks; Documents ("Email attachment → PDF → requested form values → filled copy → reviewed reply → receipt"); Gmail and Calendar via Google OAuth with "reviewed event creation/update/deletion"; Personal context with "Editable name, tone, avatar, and memories"; and Rich Threads with a stable main conversation and side chats ([OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md)). The architecture is an Expo/React Native client speaking AG-UI to a Hono API plus CopilotKit runtime, a durable task worker on PGlite or PostgreSQL where "task workers coordinate through SQL leases," a token-protected Playwright worker, and an optional Docker "computer" that runs as UID 1000 with a read-only root, all capabilities dropped, network `none`, 512 MB RAM, one CPU and 30-second command limits — explicitly "not a full VM or a hostile-tenant guarantee" ([OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md); [SECURITY.md](https://github.com/CopilotKit/openmuse/blob/main/SECURITY.md)). Its two durable contributions are the review→receipt contract — "A proposal is bound to the account, reviewed content, and applicable provider version. The server requires a recorded approval before dispatching a send or calendar change. An uncertain network outcome is retained for reconciliation" — and the prompt-injection stance "Website, email, and document content supplies evidence, not permission to act" ([SECURITY.md](https://github.com/CopilotKit/openmuse/blob/main/SECURITY.md); [OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md)). Its biggest compromise is that conversation persistence depends on the hosted CopilotKit Intelligence service, which "is a separate service and is not included in this repository's MIT license," and that SDK telemetry "defaults to full capture" ([OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md); [docs/RICH-THREADS.md](https://github.com/CopilotKit/openmuse/blob/main/docs/RICH-THREADS.md)); its roadmap still lists live Google acceptance, voice, payments and "stronger VM isolation" as unchecked ([ROADMAP.md](https://github.com/CopilotKit/openmuse/blob/main/ROADMAP.md)). CopilotKit/OpenDots (created 2026-09-29, the day OpenAI announced Dots; 5,577 stars) is the team-shaped sibling — Spaces, specialist Dots with saved role instructions, a Pages library, Slack via the Channels SDK, WebRTC calls with timeline receipts, and per-Dot "computers" through OpenBot whose browser, file and shell permissions "start disabled," with human-in-the-loop cards labelled **Approve & save** and **Approve & run** and interrupted schedules that "wait for an explicit retry" ([OpenDots README](https://github.com/CopilotKit/OpenDots/blob/main/README.md); [docs/COMPUTERS.md](https://github.com/CopilotKit/OpenDots/blob/main/docs/COMPUTERS.md); [CopilotKit blog](https://www.copilotkit.ai/blog/introducing-opendots)). OpenAI's own Dots are the proprietary reference for that shape: a cloud computer you can open and "Take over" then "Return control," and a review step that decides whether the dot proceeds, needs approval or hands the step to you ([OpenAI Dots docs](https://developers.openai.com/codex/dots?nav=overview)).

OpenClaw is the dominant open-source runtime by every metric — **392,410 stars**, MIT, release v2026.10.5 on October 18 ([GitHub](https://github.com/openclaw/openclaw)) — and supplies the spine. One long-lived Gateway per host binds `127.0.0.1:18789`, owns all channels, sessions and the agent loop, and speaks a typed WebSocket protocol (first frame `connect`, then `req`/`res`/`event` frames validated against JSON Schema generated from TypeBox, which also generates the Swift models) with idempotency keys on side-effecting methods and device pairing in which every client presents a device identity and signs a challenge nonce ([OpenClaw architecture](https://docs.openclaw.ai/concepts/architecture)). The agent's identity is plain markdown in a workspace — `AGENTS.md`, `SOUL.md`, `USER.md`, `IDENTITY.md`, `BOOTSTRAP.md`, `MEMORY.md` and `memory/YYYY-MM-DD.md` — injected under hard budgets of 20,000 characters per file and 60,000 total ([Agent workspace](https://docs.openclaw.ai/concepts/agent-workspace)). Channels authorise senders with a per-channel `dmPolicy` of `pairing` (default; unknown senders get an 8-character code that expires in an hour, three pending at most), `allowlist`, `open` or `disabled`, with a separate owner concept (`commands.ownerAllowFrom`) and `session.identityLinks` to merge one person's identities across channels ([Access control](https://docs.openclaw.ai/gateway/security/access-control); [Pairing](https://docs.openclaw.ai/channels/pairing)). Companion devices join as nodes exposing `camera.*`, `screen.record`, `system.run` and computer use, while "channel messages arrive at the Gateway, not at nodes," and the macOS app is a menu-bar companion requiring macOS 26.2 that attaches to a launchd-managed Gateway ([Nodes](https://docs.openclaw.ai/nodes); [macOS app](https://docs.openclaw.ai/platforms/macos)). Skills are `SKILL.md` directories, with a Skill Workshop in which agents create and version their own skills ([Skills](https://docs.openclaw.ai/tools/skills)); exec approvals are bound to "cwd, exact argv, env (when present), and resolved executable identity" with `askFallback` defaulting to deny ([Exec approvals](https://docs.openclaw.ai/tools/exec-approvals)); and the core loop deliberately has no plan tool, with unattended runs told that "The final reply must be the deliverable rather than a plan" and that "A completed model run is not proof that the requested task succeeded" ([Payloads](https://docs.openclaw.ai/automation/cron-jobs/payloads)). Its 2026 security history is the cautionary tale: CVE-2026-25253 let a crafted link make the Control UI auto-connect to an attacker's `gatewayUrl` and leak the token for one-click RCE, "exploitable even on instances configured to listen on loopback only" ([The Hacker News](https://thehackernews.com/2026/02/openclaw-bug-enables-one-click-remote.html)); the ClawHavoc campaign planted **at least 1,184 malicious skills** on ClawHub, mostly delivering the Atomic Stealer through fake "Prerequisites" ([Antiy CERT](https://www.antiy.net/p/clawhavoc-analysis-of-large-scale-poisoning-campaign-targeting-the-openclaw-skill-market-for-ai-agents/)); the repo carries 722 published advisories ([GitHub advisories](https://github.com/openclaw/openclaw/security/advisories)); and its own scorecard still rates the project "Alpha (68%)" ([Maturity scorecard](https://docs.openclaw.ai/maturity/scorecard)).

OpenAI's desktop story converged the same way from the other direction. Atlas (Chromium, opt-in agent mode with a blue-highlighted cursor) shipped October 21, 2025 and was shut down on August 9, 2026 after being folded into a single desktop app ([Wikipedia: ChatGPT Atlas](https://en.wikipedia.org/wiki/ChatGPT_Atlas)); the Codex app merged into the ChatGPT desktop app on July 9, 2026, which now offers a Chat/Work toggle where Work "carries a larger task to a reviewable result," pauses "to request information or approval," and hides shell and git details unless you switch to the Codex view ([Using ChatGPT in the desktop app](https://learn.chatgpt.com/docs/use-chatgpt); [Wikipedia: Codex](https://en.wikipedia.org/wiki/Codex_(AI_agent))). Under it sits a Rust core behind an App Server protocol, OS sandboxes (Seatbelt on macOS, bubblewrap plus seccomp on Linux) with `read-only`, `workspace-write` and `full access` modes and the clean framing that "Approvals determine when Codex pauses before an action, while the sandbox determines which files and network resources commands can access" ([Codex: Agent approvals & security](https://developers.openai.com/codex/agent-approvals-security)); automations land in a Triage inbox with Approve/Revise/Reject ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/04/08/codex-desktop-automations/)); a Guardian reviewer subagent scores approval events 0–1 while the sandbox stays "the hard boundary Guardian cannot override" ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/10/17/guardian-subagent-v0160-risk-based-approval-framework-codex-cli/)); and computer use gives "each agent thread its own cursor context" so it works in the background, with a per-app Always-allow list but "No browser profile isolation" ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/04/17/codex-app-computer-use-macos-background-gui-automation/); [Computer use docs](https://learn.chatgpt.com/docs/computer-use)). Atlas also left a security lesson: memories poisoned in ordinary ChatGPT chats later steered the browser agent, and "the first mode selected becomes the default for later agent sessions" ([Zenity Labs](https://labs.zenity.io/post/exploring-the-risks-of-chatgpt-s-atlas-browser)).

Browser-agent frameworks have standardised two mechanics Psyche should adopt verbatim. Page representation is an accessibility tree with stable element references — Playwright's aria snapshots and `page.getByRef()` ([Playwright release notes](https://playwright.dev/docs/release-notes)), Playwright MCP's `browser_snapshot` refs ([microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)), Anthropic's `read_page`/`find` → `ref_N` — with screenshots reserved for layout questions. Secrets never reach the model: browser-use maps placeholders to real values per domain pattern, filters them from text and injects them "directly into form fields after the LLM call," pairing that with `allowed_domains` and `use_vision=False` ([browser-use docs](https://docs.browser-use.com/open-source/examples/templates/sensitive-data.md)); Stagehand's `%var%` variables "will not be shared with LLM providers" ([Stagehand docs](https://docs.stagehand.dev/v2/basics/act)); Skyvern substitutes at type time, masks secrets in later screenshots and reads from 1Password or Bitwarden vaults ([Skyvern docs](https://www.skyvern.com/docs/credentials/introduction)). Two caveats travel with them: a decoy domain in the URL userinfo bypassed browser-use's allowlist (CVE-2025-47241) ([Debian tracker](https://security-tracker.debian.org/tracker/CVE-2025-47241)), and Playwright MCP's origin lists "are not a security boundary" and ignore redirects ([microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)).

## Psyche's spine should be a loopback gateway, an Electron shell and a Swift helper

The architecture that falls out of the evidence is the one OpenClaw, Hermes Agent, Khoj and VS Code Server all use: a long-running local server that owns state, with thin clients attached. OpenClaw's Gateway is "the single source of truth for sessions, routing, and channel connections," serves its web UI from the same port as its WebSocket API, and is kept alive by launchd on a Mac while the menu-bar app merely attaches — "quitting the app does not stop the Gateway" ([OpenClaw architecture](https://docs.openclaw.ai/concepts/architecture); [bundled gateway](https://docs.openclaw.ai/platforms/mac/bundled-gateway.md)); VS Code Server is the same shape for editors ([VS Code Server](https://code.visualstudio.com/docs/remote/vscode-server)). For Psyche that means a `core/` process in TypeScript on Node 24 or Bun (Hono serving the Vite-built SPA plus `/api`; SSE for agent streams because it traverses Tailscale Serve and reverse proxies without special casing, which tRPC v11 itself recommends over WebSockets for subscriptions; one WebSocket for low-latency shell control such as hotkeys, tray state and approvals; SQLite for sessions, tasks, the approval ledger and the memory index), a `ui/` React app, and a `shell-mac/` client that installs or attaches to the core as a launchd agent instead of spawning it as a child ([tRPC subscriptions](https://trpc.io/docs/server/subscriptions)). The identical core binary ships in Docker Compose for the server mode. OpenClaw's TypeBox → JSON Schema → Swift pipeline is the concrete recipe for keeping the TypeScript server and any Swift code in sync ([OpenClaw architecture](https://docs.openclaw.ai/concepts/architecture)).

The shell decision is forced by the embedded-browser requirement. Only Chromium-based shells expose the Chrome DevTools Protocol an agent needs: Electron 44.9.0 (Chromium 152, Node 24, macOS 13+) gives `WebContentsView` per tab, `webContents.debugger` for in-process CDP and `playwright-core` compatibility ([Electron releases](https://releases.electronjs.org/); [Electron 44 blog](https://www.electronjs.org/blog/electron-44-0); [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view); [Debugger](https://www.electronjs.org/docs/latest/api/debugger)), whereas Tauri 2 and a native Swift shell both render in WKWebView, which exposes only Safari's Web Inspector ([WebKit blog](https://webkit.org/blog/13936/enabling-the-inspection-of-web-content-in-apps/)), Tauri 3's CEF runtime is a 3.0.0-alpha ([docs.rs tauri-runtime-cef](https://docs.rs/crate/tauri-runtime-cef/latest)), and Electrobun's `bundleCEF` option brings Electron-class size without documented CDP exposure ([Electrobun](https://github.com/blackboardsh/electrobun)). Claude Desktop, Goose's desktop app (Electron 43 with React 19) and Cherry Studio all chose Electron ([Goose desktop package.json](https://github.com/block/goose/blob/main/ui/desktop/package.json); [Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app)); OpenClaw is the precedent for the alternative — a SwiftPM menu-bar app over a Node gateway with a separate managed Chromium ([OpenClaw apps/macos](https://github.com/openclaw/openclaw/tree/main/apps/macos)). The cost of Electron is weight (about 85 MiB compressed per Electrobun's comparison) ([Electrobun](https://blackboard.sh/electrobun/)) and the need for a Swift layer anyway, because App Intents, Keychain access-control items, Foundation Models, the Accessibility and ScreenCaptureKit APIs and `UNUserNotificationCenter` interruption levels are Swift-only: use node-swift (a Node-API bridge with a `#NodeModule` macro) or napi-rs for in-process calls and a separately signed helper bundle with its own bundle ID so TCC grants attach to a stable identity ([node-swift](https://github.com/kabiroberai/node-swift); [NAPI-RS](https://napi.rs/); [OpenClaw mac permissions](https://cdn.jsdelivr.net/npm/openclaw@2026.7.1-2/docs/platforms/mac/permissions.md)). Sign and notarize from day one — `safeStorage`, notifications, `setLoginItemSettings` and the auto-updater all require a valid signature ([Electron code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)) — and copy Claude's fuse posture (`RunAsNode` off, asar integrity on) ([Pluto Security](https://pluto.security/blog/inside-claude-cowork-how-anthropics-autonomous-agent-actually-works/)).

For the UI, build on **assistant-ui** (MIT, `@assistant-ui/react` 0.15.29, published near-weekly) because its ExternalStore, DataStream, AG-UI and "AssistantTransport" runtimes make it backend-agnostic and it ships tool-call rendering with inline human approvals ([assistant-ui](https://github.com/assistant-ui/assistant-ui); [pick a runtime](https://www.assistant-ui.com/docs/runtimes/pick-a-runtime)), on shadcn CLI v4 where Base UI is now the default base with Radix still supported through the unified `radix-ui` package ([shadcn changelog](https://ui.shadcn.com/docs/changelog)), on Tailwind v4.3 ([Tailwind blog](https://tailwindcss.com/blog/tailwindcss-v4-3)) and on Streamdown for streamed markdown ([Streamdown](https://raw.githubusercontent.com/vercel/streamdown/main/packages/streamdown/README.md)); Vercel's AI Elements registry "will be deprecated at the end of November 2026" in favour of a shadcn/ui version, so adopt its Conversation, PromptInput, Reasoning and Tool components through shadcn rather than the standalone CLI ([AI Elements](https://elements.ai-sdk.dev/overview)). AG-UI (MIT) is the right wire vocabulary if Psyche ever wants to host third-party agent backends, since it already covers streaming, generative UI, shared state and human-in-the-loop interrupts and is what OpenMuse and OpenDots use ([AG-UI](https://docs.ag-ui.com/introduction)); CopilotKit's own runtime is MIT in TypeScript but its roadmap centres on the paid Intelligence layer ([CopilotKit](https://github.com/CopilotKit/CopilotKit)). LibreChat (MIT) and Hugging Face chat-ui (Apache-2.0) are the licence-clean whole-app references; Open WebUI's licence forbids removing its branding above 50 users and LobeHub's community licence requires a commercial licence for derivatives ([Open WebUI license](https://docs.openwebui.com/license/); [LobeHub LICENSE](https://cdn.jsdelivr.net/npm/@lobehub/chat@1.143.3/LICENSE)).

For models, use **Vercel AI SDK v7** (`ai@7.0.143`, Apache-2.0, ESM-only on Node 22+) as the provider layer and own the router. v7 brings `ToolLoopAgent` with a default `stopWhen: isStepCount(20)`, `toolApproval`, typed `runtimeContext`, a `prepareStep` hook that can swap the model per step, an `@ai-sdk/mcp` client and a normalized usage object with `cacheReadTokens`, `cacheWriteTokens` and `reasoningTokens` ([AI SDK 7](https://vercel.com/blog/ai-sdk-7); [ToolLoopAgent reference](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool-loop-agent); [generateText reference](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text)), but its most-upvoted open issue is the absence of cross-provider retry and fallback ([vercel/ai issues](https://github.com/vercel/ai/issues?q=is%3Aissue+state%3Aopen+sort%3Areactions-%2B1-desc)). OpenClaw and Goose both built that layer themselves — `provider/model` refs, `agents.defaults.model.primary` plus ordered `fallbacks`, auth-profile rotation with 30 s → 1 m → 5 m cooldowns, turn-local failover, and strict (no silent fallback) user-pinned `/model` picks — and Psyche should copy those semantics using `prepareStep` as the seam ([OpenClaw model failover](https://docs.openclaw.ai/concepts/model-failover); [OpenClaw models](https://docs.openclaw.ai/concepts/models)); Cherry Studio's `@cherrystudio/ai-core` shows the AI-SDK-plus-registry path working in a desktop client ([Cherry Studio aiCore](https://github.com/CherryHQ/cherry-studio/blob/main/packages/aiCore/README.md)). Store provider-native assistant turns opaquely: Claude thinking blocks carry a `signature` and "Modified thinking blocks are rejected with a 400 error" ([Claude thinking docs](https://platform.claude.com/docs/en/build-with-claude/thinking)), and OpenAI and Gemini impose the same round-trip rule on encrypted reasoning. Current frontier IDs and prices are `claude-fable-5-1` ($10/$50 per MTok), `claude-opus-5-5` ($4/$20), `claude-sonnet-5-5` ($2/$10) and `claude-haiku-5-5`, all 1M context with adaptive thinking ([Claude models overview](https://platform.claude.com/docs/en/about-claude/models/overview)), `gpt-6-astra`, `gpt-6.1-sol` and `gpt-6-luna` on the Responses API ([OpenAI models](https://developers.openai.com/api/docs/models)), and Gemini 4 Argon (GA October 13, 2026) on the Interactions API ([Gemini changelog](https://ai.google.dev/gemini-api/docs/changelog)); reuse LiteLLM's community price table rather than running LiteLLM ([LiteLLM token usage](https://docs.litellm.ai/docs/completion/token_usage)). For local inference target **Ollama** first (MIT, MLX runner on Apple Silicon since June 2026, OpenAI-compatible endpoints plus an Anthropic-compatible `/v1/messages` with tools and thinking) ([Ollama blog](https://ollama.com/blog); [Anthropic compatibility](https://docs.ollama.com/api/anthropic-compatibility)), llama.cpp's `llama-server` as the portable fallback ([llama-server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)), and LM Studio only as a user-chosen backend given its proprietary "personal and/or internal business" terms ([LM Studio terms](https://lmstudio.ai/terms)); mlx-lm's server "is not recommended for production" ([mlx-lm SERVER.md](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md)). Realistic local agent models for a 32–64 GB Mac are Qwen3.8-27B (Apache-2.0, 18 GB on Ollama) ([Hugging Face](https://huggingface.co/Qwen/Qwen3.8-27B); [Ollama](https://ollama.com/library/qwen3.8)), Gemma 4 31B (τ² average 76.9%) ([Hugging Face](https://huggingface.co/google/gemma-4-31b-it)), gpt-oss-20b (14 GB) ([Ollama](https://ollama.com/library/gpt-oss)), GLM-4.7-Flash 30B-A3B (MIT, τ² 79.5) ([Hugging Face](https://huggingface.co/zai-org/GLM-4.7-Flash)) and Muse Glimmer 30B (18 GB, "built for always-on local agents") ([Ollama](https://ollama.com/library/muse-glimmer)); Llama 4 has not been updated since May 2025 ([Hugging Face](https://huggingface.co/meta-llama/Llama-4-Scout-17B-16E-Instruct)). Mirror Muse's "one brain" UX — a single default model with advanced per-role overrides (utility, decision, image, PDF) as OpenClaw does — rather than a picker in every composer.

The agent loop is the cheap part to reuse; the durable task engine is not. **pi-agent-core** (MIT, 116k-star monorepo, v1.3.0) is the loop OpenClaw started from and offers `steer()` (interrupt while tools run) and `followUp()` (queue after the agent would stop), `beforeToolCall`/`afterToolCall` hooks and TypeBox-typed tools ([pi](https://github.com/earendil-works/pi); [pi-agent-core README](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)); AI SDK's `ToolLoopAgent` is the alternative; the Claude Agent SDK gives the whole Claude Code harness but "is governed by Anthropic's Commercial Terms of Service" and "Anthropic does not allow third party developers to offer claude.ai login or rate limits," so it cannot be the core of a BYO-subscription app ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). What no library provides is the personal-agent task model — plan → input requests → review → dispatch → receipt → reconciliation — with SQL leases that survive restarts; OpenMuse tests "Real PGlite restart, two-worker lease races, expired-lease recovery, cancellation, pause/resume, missing inputs, approval fairness, and saved outcomes" and refuses hidden retries after an uncertain external write ([docs/VERIFICATION.md](https://github.com/CopilotKit/openmuse/blob/main/docs/VERIFICATION.md); [OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md)). pi-durable (crash-resumable conversations and tasks on SQLite, tools marked `replay: "safe"`) is the closest library but is "Experimental. The API changes without notice" ([pi-durable README](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md)); Mastra's `suspend()`/`resume()` snapshots and the OpenAI Agents SDK's serializable `RunState` are workable alternatives ([Mastra suspend and resume](https://mastra.ai/docs/workflows/suspend-and-resume); [OpenAI Agents human-in-the-loop](https://openai.github.io/openai-agents-js/guides/human-in-the-loop/)).

Plan-following long-running work should follow the pattern every coding harness converged on. A read-only planning phase produces a human-approved plan: Claude Code's plan mode "can read, search, and run exploration commands, then presents a plan for approval before touching anything" and lets the user edit the plan with Ctrl+G before proceeding ([Permission modes](https://code.claude.com/docs/en/permission-modes)), and Codex's Plan Mode template demands a "decision complete" plan while insisting that "`update_plan` is a checklist/progress/TODOs tool; it does not enter or exit Plan Mode" ([Codex plan.md](https://github.com/openai/codex/blob/main/codex-rs/collaboration-mode-templates/templates/plan.md)). Keep the checklist harness-managed and lightweight: Manus rewrote a `todo.md` at the end of context because "A typical task takes about 50 tool calls on average" ([Manus blog](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)), but Cline deprecated its Focus Chain todo list because it "was no longer providing enough additional benefit on top of the current harness" ([Cline deprecations](https://github.com/cline/cline/blob/main/docs/resources/deprecations.mdx)). Verify with a model other than the worker: Claude Code's `/goal` runs an evaluator after each turn with verdicts "Not yet met / Met / Impossible" ([/goal](https://code.claude.com/docs/en/goal)), and Anthropic's harness research found "agents reliably skew positive when grading their own work" ([Harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Resume from artifacts, not memory: Anthropic's long-running harness starts every session by reading `git log`, a progress file and a JSON feature list in which agents may only flip `passes` ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). For a personal agent the evaluator checks receipts (did the mail send, does the calendar event exist) rather than tests, and unattended runs obey OpenClaw's rule that the final reply is the deliverable or `NO_REPLY`.

## Sandboxes, Mac control and the agent browser demand Apple-specific engineering

A UTM-style "Mac inside the app" is buildable entirely with public API, but Apple caps what it can be. The Virtualization framework (entitlement `com.apple.security.virtualization`) installs macOS from an IPSW via `VZMacOSRestoreImage` and `VZMacOSInstaller` into a bundle of `Disk.img`, `AuxiliaryStorage`, `MachineIdentifier` and `HardwareModel`, and `VZVirtualMachineView` resizes the guest display with the window ([Apple sample](https://developer.apple.com/documentation/virtualization/running-macos-in-a-virtual-machine-on-apple-silicon)). The framework enforces Apple's licence: a third concurrent macOS guest fails with `VZErrorDomain Code 6: "The maximum supported number of active virtual machines has been reached"`, and the SLA permits two instances for development, testing or "personal, non-commercial use" ([Eclectic Light](https://eclecticlight.co/2022/08/04/virtualisation-on-apple-silicon-macs-8-how-apple-limits-vms/)) — so Psyche should budget exactly one sandbox Mac and never fan out per task. Unattended first boot is new: `VZMacGuestProvisioningOptions` sets `fullName`, `username`, `password`, `logsInAutomatically` and `enablesRemoteLogin`, is evaluated only on the first boot after restore, and "requires guest macOS 27 or later" ([Apple VZMacGuestProvisioningOptions](https://developer.apple.com/documentation/virtualization/vzmacguestprovisioningoptions)); for older guests the proven no-GUI technique is Lume's — boot once, mount the guest's Data volume on the host and write the user, SSH and autologin settings as plain files ([Lume: how it works](https://cua.ai/docs/lume/concepts/how-lume-works.md)). Per-task isolation inside the one guest should come from macOS 27's DiskImageKit, whose "stacked disk images" put a read-only base under copy-on-write overlay layers passed to `VZDiskImageStorageDeviceAttachment` ([Apple DiskImageKit](https://developer.apple.com/documentation/diskimagekit)). iCloud works only when the VM is created on a macOS 15+ host from a macOS 15+ IPSW, and App Store apps "that check the current user is entitled to run them will fail to open" ([Apple: iCloud with macOS VMs](https://developer.apple.com/documentation/virtualization/using-icloud-with-macos-virtual-machines); [Eclectic Light](https://eclecticlight.co/2024/07/12/sequoia-virtualisation-and-apple-id/)), so plan on direct-download apps. Shared directories need macOS 13+ on both sides, clipboard sharing macOS 15+, and USB passthrough and snapshots are macOS 27 features ([UTM macOS guest docs](https://docs.getutm.app/guest-support/macos/)); bridged networking is off the table because `com.apple.vm.networking` "is restricted to developers of virtualization software" ([Apple entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.vm.networking)), and a background VM needs "an unlocked login.keychain" ([Tart FAQ](https://tart.run/faq/)). Inside the guest, follow c/ua: on Tahoe images "cua-spacesd starts at login and handles exec, screenshots, and the viewer" as a gRPC daemon on port 3211, and the published image "comes with screen and accessibility permissions already granted" ([cua: local macOS sandbox](https://cua.ai/docs/start-here/create-a-local-macos-sandbox.md); [trycua/cua](https://github.com/trycua/cua)); a 23 GB image pulls in about eight minutes and clones in about 25 seconds ([cua](https://cua.ai/docs/start-here/create-a-local-macos-sandbox.md)). Shipping the VM pre-built as an OCI image (Lume/Tart) is faster but licensing-sensitive; building from Apple's IPSW on first run is slower but clean. Either way the VM is an optional power feature: most of Psyche's "computer" work belongs in Linux sandboxes and the embedded browser.

For Linux sandboxes on macOS 26 and later, Apple's `container` is the best isolation fit: "Each container runs in its own lightweight VM," `vminitd` exposes a gRPC API over vsock, starts are "sub-second," images are OCI, and the tool is "Supported only on macOS 26" ([apple/containerization](https://github.com/apple/containerization); [apple/container README](https://github.com/apple/container/blob/main/README.md)). For macOS 15 hosts fall back to Colima or Lima with the `vz` driver and Rosetta, Podman's rootless machine, or Docker Desktop (free only below 250 employees and $10M revenue) ([Colima](https://github.com/abiosoft/colima); [Lima VM types](https://lima-vm.io/docs/config/vmtype/); [Docker Desktop install](https://docs.docker.com/desktop/setup/install/mac-install/)). None of these ships a domain-level egress allowlist, so Psyche must add one: Cowork's design is gVisor blocking `socket()` plus a host MITM proxy that re-signs only `api.anthropic.com` and CONNECT-tunnels an SNI allowlist ([Pluto Security](https://pluto.security/blog/inside-claude-cowork-how-anthropics-autonomous-agent-actually-works/)), and Anthropic's open-source `srt` implements the same idea without a VM — Seatbelt profiles on macOS, bubblewrap plus seccomp on Linux, all traffic through local HTTP and SOCKS5 proxies with `allowedDomains`/`deniedDomains`, no network and no writes outside default paths unless configured — and can wrap MCP servers by prefixing their command ([anthropic-experimental/sandbox-runtime](https://github.com/anthropic-experimental/sandbox-runtime); [Claude Code sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing)). Use OpenMuse's container contract as the baseline for the Linux "computer" (nonroot, read-only root, dropped capabilities, `network none`, 512 MB, 128 processes, no host mounts or model keys) ([OpenMuse SECURITY.md](https://github.com/CopilotKit/openmuse/blob/main/SECURITY.md)), and give it a real PTY, which OpenMuse lacks ("not an interactive PTY") ([docs/COMPUTER.md](https://github.com/CopilotKit/openmuse/blob/main/docs/COMPUTER.md)). SharedRoot's lesson is to prefer read-only host shares with an explicit write-back channel, disable unprivileged user namespaces and keep the guest daemon's mounts strict ([The Hacker News](https://thehackernews.com/2026/07/claude-cowork-flaw-could-let-ai-agent.html)); Codex's framing — approvals decide when to pause, the sandbox decides what is reachable — keeps the two layers from being confused ([Codex: Agent approvals & security](https://developers.openai.com/codex/agent-approvals-security)).

Controlling real macOS apps is the Swift helper's job and the TCC rules decide its shape. The proven stack is an Accessibility-tree walk from the app's PID reading `AXRole`, `AXTitle`, `AXValue`, `AXPosition`, `AXSize` and `AXUIElementCopyActionNames` (`AXPress`, `AXConfirm`, `AXShowMenu`), emitting one line per interactive element with a stable `@n1`-style ref, a depth cap of 5–8 and screenshots only when the tree is sparse ([agent-native](https://mintlify.wiki/ericclemmons/agent-native/concepts/accessibility-tree)); Electron apps hide their tree until `AXManualAccessibility` is set on the app element ([Electron accessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility)). Prefer `AXUIElementPerformAction` and `AXUIElementSetAttributeValue` over synthetic events, with `CGEventPost` as the universal fallback; posting needs Accessibility while listen-only taps need Input Monitoring ([Apple Developer Forums](https://developer.apple.com/forums/thread/735204)). Screenshots via ScreenCaptureKit need Screen Recording and on macOS 15 trigger a monthly "Allow For One Month" re-consent ([9to5Mac](https://9to5mac.com/2024/08/14/macos-sequoia-screen-recording-prompt-monthly/)); the Persistent Content Capture entitlement that avoids it is for VNC apps and must be requested from Apple ([Apple entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.persistent-content-capture)), so an AX-first design reduces both risk and prompts. Sending Apple Events to Mail, Notes or Messages requires the hardened-runtime `com.apple.security.automation.apple-events` entitlement plus `NSAppleEventsUsageDescription` ([Apple Events entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.automation.apple-events)), and `shortcuts run "Name" -i input` gives a sanctioned bridge to any Shortcut ([Apple Shortcuts CLI guide](https://support.apple.com/guide/shortcuts-mac/run-shortcuts-from-the-command-line-apd455c82f02/mac)). The pitfalls are identity: "TCC ties a grant to the app's code signature, bundle identifier, and on-disk path," ad-hoc signatures make macOS forget grants on every build, and grants should go to a signed helper with its own bundle ID, "never to a shared `node` binary" ([OpenClaw mac permissions](https://cdn.jsdelivr.net/npm/openclaw@2026.7.1-2/docs/platforms/mac/permissions.md)); macOS 27 additionally removes direct access to the TCC database and denies reads of other teams' app containers by default ([Apple macOS 27 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes)). The behavioural model should combine Muse's per-app Off / Read only / Read and interact switch with Claude's fixed tiers (browsers view-only, terminals click-only), per-app session grants, hiding other apps, excluding Psyche's own window from screenshots, and a consumed global Esc ([AI Agents Library](https://www.aiagentslibrary.com/blog/how-to-use-meta-muse/); [Computer use from the CLI](https://code.claude.com/docs/en/computer-use.md)); Codex's background per-thread cursor is attractive but c/ua's driver shows what it costs — windows addressed by exact `CGWindowID`, Chrome accepting background input while Safari refuses ([Cua Driver](https://cua.ai/docs/cua-driver/concepts/platform-support.md)). Claude's `disclaimer` helper (a TCC responsibility-disclaimer wrapper) is the pattern for keeping MCP child processes from inheriting the app's Screen Recording and Accessibility grants ([Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app)). For Apple's data apps, read iMessage from `~/Library/Messages/chat.db` in read-only mode with a real typedstream decoder — imessage-exporter's `imessage-database` crate handles `attributedBody`, edits, unsent messages and audio transcripts "as of macOS Golden Gate 27.0.1" ([imessage-exporter](https://github.com/ReagentX/imessage-exporter); [features](https://github.com/ReagentX/imessage-exporter/blob/develop/docs/features.md)) — and send through Messages.app's AppleScript surface or the `imsg` CLI, which needs Full Disk Access (manual) and Automation; its richer features require SIP disabled and "may be blocked by library validation" ([steipete/imsg](https://github.com/steipete/imsg)). macOS 26 changed chat GUIDs from `iMessage;-;` to `any;-;` and broke BlueBubbles' AppleScript path ([bluebubbles-server #777](https://github.com/BlueBubblesApp/bluebubbles-server/issues/777)), and the Private API route (SIP and Library Validation off, dylib injection) is not shippable to normal users ([BlueBubbles Private API](https://docs.bluebubbles.app/private-api/installation)). Calendars and Reminders must request full access because "Your app can't request read-only access to either events or reminders" ([Apple EventKit](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)), and Contacts offers a `.limited` grant ([Apple Contacts](https://developer.apple.com/documentation/contacts/accessing-the-contact-store)).

The embedded browser the agent owns is one `BaseWindow` hosting a `WebContentsView` per tab, all created with `webPreferences.partition = 'persist:psyche'` so cookies and storage survive restarts at `ses.storagePath`, with `webContents.debugger.attach('1.3')` per tab for raw CDP (`Accessibility.getFullAXTree`, `Input.dispatch*`, `Page.startScreencast`, `Network.*`), `setWindowOpenHandler` routing OAuth popups into new agent tabs, `session.on('will-download')` quarantining downloads, and the `EnableCookieEncryption` fuse so the cookie jar is OS-key encrypted ([Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view); [Electron session](https://www.electronjs.org/docs/latest/api/session); [Electron Debugger](https://www.electronjs.org/docs/latest/api/debugger); [Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents); [Electron Fuses](https://www.electronjs.org/docs/latest/tutorial/fuses)). Claude Desktop ships `playwright-core` 1.57 for exactly this and its `read_page` YAML tree with `ref_N` handles is Playwright's aria-snapshot style ([app package.json](file:///Applications/Claude.app/Contents/Resources/app.asar); [Playwright aria snapshots](https://playwright.dev/docs/aria-snapshots)); attaching an external Playwright through `connectOverCDP` works but is "significantly lower fidelity" and Chromium-only ([Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)), and `--remote-debugging-port` has no authentication, so never expose it in production. The structural limitation is extensions: Electron "does not support arbitrary Chrome Store extensions," only unpacked ones in persistent sessions, and lists no `chrome.action`, `chrome.identity` or `chrome.windows` support ([Electron Chrome Extension Support](https://www.electronjs.org/docs/latest/api/extensions)), so 1Password's and Bitwarden's extensions will not run inside the pane; that is why the credential broker below exists. "Take control" is natural in-process because the user and the agent touch the same renderer; the engineering is arbitration — pause the agent's input while the user is active, exactly as Muse "pauses when the user takes over or when credentials are being filled" ([Meta research post](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)) — and the three takeover triggers every shipped product converged on should be explicit pane states: verification challenges (Manus prompts "Take Over" on SMS codes, CAPTCHA or MFA and sends a notification) ([Manus Cloud Browser](https://manus.im/docs/features/cloud-browser)), sensitive sites (Operator's Watch Mode pauses "when the user becomes inactive or navigates away from the page") ([Operator System Card](https://cdn.openai.com/operator_system_card.pdf)), and classifier blocks (Claude's Auto mode "reverts to per-step approval after repeated blocks") ([Claude in Chrome permissions](https://support.claude.com/en/articles/12902446-manage-claude-in-chrome-permissions)). Keep the profile clean and separate from the user's browser, with an optional site-by-site login import that excludes banking, email and SSO unless opted in, as Cowork does ([Claude Cowork built-in browser](https://claude.com/blog/cowork-built-in-browser)); make logged-in versus logged-out an explicit per-task choice with a persistent indicator rather than Atlas's sticky default ([Zenity Labs](https://labs.zenity.io/post/exploring-the-risks-of-chatgpt-s-atlas-browser)); run a per-site Allow once / Always allow / Deny card plus a write-action classifier in every mode and a domain check before new origins ([Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md)). Identify honestly instead of evading: sign requests with Cloudflare's Web Bot Auth (RFC 9421 Ed25519 signatures, JWKS at `/.well-known/http-message-signatures-directory`, ~1-minute `expires`) ([Cloudflare Web Bot Auth](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/web-bot-auth/)), because from September 15, 2026 new Cloudflare zones block "Agent" traffic on ad-displaying pages by default ([Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-07-01-ai-traffic-options/)), and never solve CAPTCHAs — Anthropic prohibits it outright ([Using Claude in Chrome safely](https://support.claude.com/en/articles/12902428)). The prompt-injection numbers justify the layering: Anthropic's autonomous-mode attack success fell from 23.6% to 11.2% in 2025 and, with probes plus an action classifier, to 0% for Sonnet 5/Opus 5 and 0.3% for Fable 5 on a harder 2026 eval ([Piloting Claude for Chrome](https://claude.com/blog/claude-for-chrome); [Claude in Chrome GA](https://claude.com/resources/articles/claude-in-chrome-generally-available)); Operator went 62% → 23% with a 99%-recall monitor ([Operator System Card](https://cdn.openai.com/operator_system_card.pdf)); Google's Chrome agent adds a page-isolated "User Alignment Critic" and read-only versus read-writable origin sets ([Google](https://blog.google/security/architecting-security-for-agentic/)). Because "99% is a failing grade" and the lethal trifecta (private data, untrusted content, an exfiltration channel) cannot be filtered away ([Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)), Psyche's planner should see only the user's request and action metadata while quarantined readers process page and email text into references, the CaMeL/dual-LLM pattern ([Simon Willison on CaMeL](https://simonwillison.net/2025/Apr/11/camel/); [arXiv 2503.18813](https://arxiv.org/abs/2503.18813)); Brave's Comet exploit — hidden Reddit text read the user's Gmail OTP — is the canonical failure ([Brave](https://brave.com/blog/comet-prompt-injection/)). Model choice is itself a control: pre-safeguard rates were 17.6% for Opus 4.5 versus 3.8% for Opus 5 on the same eval ([Claude in Chrome GA](https://claude.com/resources/articles/claude-in-chrome-generally-available)).

The credentials manager should be a broker process the model loop cannot read. The 2026 pattern is "the model never sees the secret": 1Password for Claude shows which item is requested and why, the user approves with Touch ID, the extension fills it, access is scoped to the current task and cleared on failure, and "Claude never sees the vault item, password, or one-time code" ([1Password for Claude](https://1password.com/blog/1password-for-claude)); 1Password rejected MCP for credential transfer because it exposes secrets to the model ([1Password](https://1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-agents)); Bitwarden's Agent Access SDK pairs an agent once, requires a separate CLI approval per credential and injects values as child-process environment variables ([Bitwarden](https://bitwarden.com/blog/introducing-agent-access-sdk/)); Dashlane "does not let AI agents autonomously access or operate on a vault" ([Dashlane](https://www.dashlane.com/blog/ai-browsers)). Psyche's own vault should wrap its key in the data-protection keychain (`kSecUseDataProtectionKeychain = true`, which Apple recommends "for all keychain operations") ([Apple](https://developer.apple.com/documentation/security/ksecusedataprotectionkeychain)), gate high-value items with `SecAccessControlCreateWithFlags(.userPresence | .biometryCurrentSet)` so `SecItemCopyMatching` triggers the Touch ID prompt ([Apple: Keychain with Face ID or Touch ID](https://developer.apple.com/documentation/localauthentication/accessing-keychain-items-with-face-id-or-touch-id)) — which on macOS requires a team-signed app with a keychain access group or fails with `-34018` ([Apple Developer Forums](https://developer.apple.com/forums/thread/684453)) — and store ciphertext in SQLCipher (AES-256-CBC per page, PBKDF2-HMAC-SHA512 at 256,000 iterations) or age files ([SQLCipher design](https://www.zetetic.net/sqlcipher/design/); [age](https://github.com/FiloSottile/age)). Electron's `safeStorage` is Chromium's OSCrypt — a random key in a login-keychain item named "<App> Safe Storage" — so it is adequate for low-friction encryption at rest but only as stable as the app's signature ([Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)). The model sees only placeholders (`{{cred:github}}`); the broker types values through CDP only when the current origin matches the credential's bound origin; every fill is a discrete approval card (item, site, agent, task) offering approve / switch / deny; typed values are scrubbed from the screenshots and text the model sees (Skyvern's Mask Secrets, browser-use's `use_vision=False`) ([Skyvern](https://www.skyvern.com/docs/credentials/introduction); [browser-use](https://docs.browser-use.com/open-source/examples/templates/sensitive-data.md)); and OAuth tokens or reused session cookies are always preferred to typing passwords. Cards and government IDs are never stored — Anthropic's agents refuse to enter them and 1Password has not shipped them ([Claude in Chrome permissions](https://support.claude.com/en/articles/12902446-manage-claude-in-chrome-permissions)). Nothing in Apple's APIs lets a third-party app read Safari or Passwords.app items: credential providers hand the system metadata "but not its password" until the user picks an item ([Apple Platform Security](https://support.apple.com/guide/security/sec6319ac7b9/web)), and the only sanctioned bulk path is macOS 26's user-initiated Credential Exchange via `ASCredentialExportManager`/`ASCredentialImportManager` ([Apple](https://developer.apple.com/documentation/authenticationservices/ascredentialexportmanager)), so Psyche can register as an importer but must never scrape `keychain-2.db`. Finally, refuse secure text fields at the dispatcher level as Claude's `secureField` code does, and copy the narrow carve-out observed in Anthropic's agent rules — test credentials may be typed only on `localhost`, `127.0.0.1`, `*.localhost` or `*.test` for the user's own app, from the project's own fixtures.

## Memory, connectors and persona should be files, hashes and trust tiers

Memory should copy OpenClaw's layering rather than adopt a framework, because it is the most fully worked-out design and it matches Muse's own exported layout. Always-injected `AGENTS.md` (operating rules), `SOUL.md` (voice: "Short beats long. Sharp beats vague."), `USER.md` (a user model written "as directives with observed-date and active/superseded metadata" under a 4,000-character cap) and `IDENTITY.md` load every session under the 20,000-per-file / 60,000-total budgets; `MEMORY.md` is a "compact, curated layer of durable non-profile facts and standing decisions" loaded only in the main private session; `memory/YYYY-MM-DD.md` daily notes are "indexed for search but not injected into every turn" ([Agent workspace](https://docs.openclaw.ai/concepts/agent-workspace); [SOUL.md](https://docs.openclaw.ai/concepts/soul); [User model](https://docs.openclaw.ai/concepts/user-model); [OpenClaw memory](https://docs.openclaw.ai/concepts/memory)). Supersede in place rather than append, because "append-only contradictory history can cause systems to follow an original preference the user has since changed" ([User model](https://docs.openclaw.ai/concepts/user-model)). The index is one per-agent SQLite file with FTS5/BM25 plus float vectors, sqlite-vec as "optional acceleration" with an automatic in-process cosine fallback, 400-token chunks with 80 overlap, and a final score of hybrid relevance × a 30-day recency half-life × a write-time importance, with trigger recall injecting at most three entries per turn and only from `MEMORY.md`/`USER.md` ([Builtin memory](https://docs.openclaw.ai/concepts/memory-builtin); [Memory search](https://docs.openclaw.ai/concepts/memory-search)). Every entry carries an origin class — `owner`, `agent`, `untrusted`, `system` — and "Taint from network-sourced tool results marks the rest of the turn as `untrusted`" ([Memory architecture](https://docs.openclaw.ai/concepts/memory-architecture)); a pre-compaction "memory flush" turn appends to the daily note and can run on a local model ([OpenClaw memory](https://docs.openclaw.ai/concepts/memory)); and a nightly `0 3 * * *` dreaming sweep (light, REM, deep) is "the only phase that writes long-term memory, and it writes only to `MEMORY.md`," excluding `untrusted` and `system` candidates and reporting to a human-readable `DREAMS.md` ([Dreaming](https://docs.openclaw.ai/concepts/dreaming)). That is the same architecture as Muse's hourly memory job and nightly dream ([mouse.dev](https://mouse.dev/blog/muse-runtime-export/)), Letta's git-backed MemFS where root files load every turn and indexed directories stay out of context ([Letta MemFS](https://docs.letta.com/concepts/memfs/index.md)), and Devin's daily "Dreaming" consolidation ([Devin memory](https://docs.devin.ai/product-guides/memory.md)). Use sqlite-vec (revived March 2026, v0.1.9 stable, MIT/Apache-2.0) ([sqlite-vec releases](https://github.com/asg017/sqlite-vec/releases)) with Ollama's `/api/embed` serving nomic-embed-text v1.5 (768-d, Matryoshka-truncatable, Apache-2.0, task prefixes required) or Qwen3-Embedding-0.6B (1024-d, 32K context, Apache-2.0) ([nomic](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5); [Qwen3-Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B); [Ollama embed API](https://docs.ollama.com/api/embed)); Apple's `NLContextualEmbedding` is documented for classification rather than similarity and the Foundation Models framework exposes no embeddings ([Apple NLContextualEmbedding](https://developer.apple.com/tutorials/data/documentation/naturallanguage/nlcontextualembedding.json)). Adopt Claude's `memory_20250818` command set — `view`, `create`, `str_replace`, `insert`, `delete`, `rename` under `/memories`, "available on all Claude 4 and later models" with no beta header — as the internal memory-tool protocol so Claude uses it natively and other models go through the same handler ([Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). The user-facing controls to copy are Claude's: topic-level items to edit or delete, pause, an irreversible reset, per-chat memory off, incognito chats and citations back to source conversations ([How Claude's memory works](https://support.claude.com/en/articles/11817273-how-does-claude-s-memory-work)), plus Muse's "Import memory" with content treated as data. Write-gating is the critical safety control: Microsoft's red team raised memory-poisoning success from 4/10 to "over 80%" merely by telling the agent to check memory before acting ([Microsoft AI Red Team](https://cdn-dynmedia-1.microsoft.com/is/content/microsoftcorp/microsoft/final/en-us/microsoft-brand/documents/Taxonomy-of-Failure-Mode-in-Agentic-AI-Systems-Whitepaper.pdf)), and Gemini persisted attacker-chosen memories after a user said "yes" to a delayed tool call ([Embrace The Red](https://embracethered.com/blog/posts/2025/gemini-memory-persistence-prompt-injection/)), so nothing derived from tool, web or email input should reach the injected layer without user confirmation. Benchmark on LongMemEval's knowledge-update and abstention tasks (a 30% accuracy drop for commercial assistants) rather than LoCoMo, whose scores are vendor-run and disputed ([LongMemEval](https://arxiv.org/abs/2410.10813); [Zep rebuttal](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)).

Connectors should be an MCP host built for the **2026-07-28** specification with a 2025-11-25 fallback. The new revision removed protocol-level sessions and the `initialize` handshake in favour of per-request `_meta` and a required `server/discover` RPC, replaced sampling, elicitation and roots with Multi Round-Trip Requests, moved Tasks into an extension, and deprecated Roots, Sampling, Logging, HTTP+SSE and Dynamic Client Registration on a twelve-month clock ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog); [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)); host a Client ID Metadata Document (`https://psyche.example/client.json`) for the host's OAuth identity since CIMD is now preferred over DCR ([Client registration](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration.md)), and use the TypeScript SDK v2 split packages (`@modelcontextprotocol/client|server|core` 2.3.1) ([TS SDK v2](https://ts.sdk.modelcontextprotocol.io/v2/)). MCP Apps (`io.modelcontextprotocol/ui`), production-ready since January 26, 2026 with Claude, Goose, VS Code and ChatGPT as launch hosts, render a tool's `ui://` resource in a sandboxed iframe over postMessage and are the right way to show connector UIs inline ([MCP Apps](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/); [ext-apps](https://github.com/modelcontextprotocol/ext-apps)); the Tasks extension's `input_required` status maps onto Psyche's input requests ([Tasks extension](https://modelcontextprotocol.io/extensions/tasks/overview.md)). Trust must be local because the official registry "is currently in preview," is metadata-only and tells consumers to "assume minimal-to-no moderation" ([MCP registry](https://modelcontextprotocol.io/registry/about.md)), and because the spec itself says clients "MUST consider tool annotations to be untrusted unless they come from trusted servers" ([MCP tools spec](https://modelcontextprotocol.io/specification/2026-07-28/server/tools); [annotations post](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/)). Hence three tiers (bundled, namespace-verified, unknown) where only tier one may auto-approve on `readOnlyHint`; per-tool allow/ask/deny keyed `mcp__<server>__<tool>` exactly as Claude Code does ([Claude Code permissions](https://code.claude.com/docs/en/permissions)); approvals bound to a hash of `tools/list` so a changed description revokes them — the defence against Invariant's tool poisoning, rug pulls and cross-server shadowing, in which a confirmation dialog showed only "Hi" while the payload sat off-screen ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks); [WhatsApp exploit](https://invariantlabs.ai/blog/whatsapp-mcp-exploited)); full, untruncated arguments in every confirmation; stdio servers under `srt` or a container with `--network=none` by default ([Local server security](https://modelcontextprotocol.io/docs/draft/tutorials/security/local-server-security.md)); per-server secrets injected from the keychain at spawn, never a shared environment; and honouring `anthropic/requiresUserInteraction` ([Claude Code MCP](https://code.claude.com/docs/en/mcp)). Package local integrations as `.mcpb` bundles whose `sensitive` `user_config` goes to the OS keychain ([MCPB manifest](https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md); [Desktop Extensions](https://www.anthropic.com/engineering/desktop-extensions)), and prefer first-party remote servers for SaaS — Slack (`mcp.slack.com/mcp`, no DCR, confidential client) ([Slack](https://docs.slack.dev/ai/mcp-server/)), Notion ([Notion](https://developers.notion.com/docs/get-started-with-mcp)), Linear ([Linear](https://linear.app/docs/mcp)), GitHub ([GitHub MCP server](https://github.com/github/github-mcp-server)). Docker's MCP Gateway (`--verify-signatures`, `--block-secrets`, `--log-calls`) and the OWASP MCP Top 10 round out the checklist ([Docker MCP Gateway](https://github.com/docker/mcp-gateway); [OWASP MCP Top 10](https://owasp.org/www-project-mcp-top-10/)), and designing to Anthropic's Software Directory Policy (annotations, OAuth with CA certificates, 64-character tool names, no runtime-fetched instructions) keeps a future Claude-connector listing open ([Software Directory Policy](https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy)).

Google Workspace is a special case because Google ships no MCP server for Gmail or Calendar; its agent-facing tool is the `gws` CLI (Rust, Apache-2.0, "not an officially supported Google product," AES-256-GCM token storage keyed in the OS keyring) ([googleworkspace/cli](https://github.com/googleworkspace/cli)). `gmail.readonly`, `gmail.modify` and `gmail.compose` are restricted scopes while `gmail.send` is merely sensitive ([Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)); verification is unnecessary "if the app is for your personal use (fewer than 100 users)" but unverified apps carry a lifetime 100-user cap ([Google](https://support.google.com/cloud/answer/13464323)), and a project left in Testing issues refresh tokens that expire after seven days ([Google OAuth](https://developers.google.com/identity/protocols/oauth2)). The cheapest compliant setup for a self-hosted single user is therefore a Desktop OAuth client with loopback redirect and PKCE ([Google native apps](https://developers.google.com/identity/protocols/oauth2/native-app)), `gmail.readonly` + `gmail.send` + `drive.file`, polling `history.list` with the saved `historyId` since Google recommends polling for installed apps and `watch` needs renewal every seven days ([Gmail push](https://developers.google.com/workspace/gmail/api/guides/push)), and Calendar `events.list` with `syncToken` since push channels carry no payload and "aren't fully reliable" ([Calendar push](https://developers.google.com/workspace/calendar/api/guides/push)); Fastmail users get JMAP with a personal API token and Outlook users Microsoft Graph subscriptions capped under seven days ([Fastmail](https://www.fastmail.com/dev/); [Microsoft Graph](https://learn.microsoft.com/en-us/graph/change-notifications-overview)). Build the seven-day re-auth into the UI rather than pursue CASA, which is only needed to distribute to others ([Google security assessment](https://support.google.com/cloud/answer/13465431)).

Skills should be `SKILL.md` directories because that format is now shared by Claude Code, OpenClaw, Codex, pi and Hermes, but installation must assume hostility: ClawHub's only barrier was "a GitHub account registered for at least one week" when 1,184 malicious skills appeared ([Antiy CERT](https://www.antiy.net/p/clawhavoc-analysis-of-large-scale-poisoning-campaign-targeting-the-openclaw-skill-market-for-ai-agents/)), so Psyche should show the full skill text and any "prerequisite" install commands, run `openclaw skills verify`-style trust checks and scanning before enabling, and treat third-party skills "as untrusted code" ([OpenClaw skills](https://docs.openclaw.ai/tools/skills)). Self-authored skills are already a shipped feature — OpenClaw's Skill Workshop keeps prior versions for undo and scopes learned skills to the creating agent, Hermes "auto-generates skills" after complex tasks ([OpenClaw skills](https://docs.openclaw.ai/tools/skills); [Hermes Agent](https://hermes-agent.nousresearch.com/)) — and the research says mining repeated tool sequences into reusable workflows pays: Agent Workflow Memory gained +24.6% on Mind2Web and +51.1% relative on WebArena, Agent Skill Induction +23.5% ([arXiv 2409.07429](https://arxiv.org/abs/2409.07429); [arXiv 2504.06821](https://arxiv.org/abs/2504.06821)). Psyche should draft skills from repetition, verify them by replay and propose them in the Ideas tab rather than install them silently.

Clarifying questions deserve a dedicated tool with selectable answers, which is where Psyche can beat Muse's free-text interviews. Claude Code's `AskUserQuestion` carries 1–4 questions each with a 12-character header and 2–4 options (`label`, `description`, optional markdown or HTML `preview`), an optional `multiSelect`, an "Other" row for free text, answers returned as `{ "<question>": "<label>" | [labels] }`, and a rule that questions "stay open until you answer them," with an idle timeout that never runs in background sessions and never auto-resolves permissions ([Agent SDK: user input](https://code.claude.com/docs/en/agent-sdk/user-input.md); [Tools reference](https://code.claude.com/docs/en/tools-reference.md)); the tool is withheld from subagents ([Subagents](https://code.claude.com/docs/en/sub-agents)). OpenMuse's Documents pipeline is the form-shaped variant — a "typed input request" for the PDF's requested field values ([OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md)) — and on chat channels the same question should degrade to native single-select controls, as OpenClaw's `ask_user` does on Telegram ([OpenClaw Telegram](https://docs.openclaw.ai/channels/telegram)). Unattended runs get no questions at all: "the final reply must be the deliverable rather than a plan, acknowledgement, or request for input" ([Payloads](https://docs.openclaw.ai/automation/cron-jobs/payloads)).

Chat forking and a tasks sidebar follow from treating conversations and tasks as different objects. Keep Muse's one main thread and side chats, but make forking explicit: Claude Desktop forks a conversation into a nested session that "appears under the original in the sidebar and reports back," opens a `/btw` side chat that "reads the main thread but adds nothing back," and offers `hand_off_to_session` with a remaining plan ([Claude Desktop changelog](https://claude.com/docs/cowork/changelog.md); [Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md)); OpenMuse's Rich Threads keep an owner-bound main thread, create side chats on first run, and support rename, archive, restore and replay, while deliberately keeping the follow-up queue client-side ([docs/RICH-THREADS.md](https://github.com/CopilotKit/openmuse/blob/main/docs/RICH-THREADS.md)); pi reconstructs state from `ctx.sessionManager.getBranch()` for true branching ([pi extensions](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)); Claude Code checkpoints restore "code, conversation, or both" ([Claude Code glossary](https://code.claude.com/docs/en/glossary)). The tasks sidebar should list task objects — not threads — with Dispatch's state vocabulary (Running, Awaiting input, Awaiting answer, Completed, Error, Archived) ([Dispatch guide](https://claude.com/docs/cowork/guide/dispatch.md)), badges for the originating surface, and the same per-task action log Muse shows under the avatar. In-app search then sits on the same SQLite index: Muse's rail item "finds things within Muse" ([The Rundown](https://app.therundown.ai/guides/how-and-why-to-set-up-meta-muse-desktop)), Claude Desktop ships a `transcript-search` worker and a `search_session_transcripts` tool and registers `com.apple.corespotlightitem` activities for Spotlight ([Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app); [Claude.app Info.plist](file:///Applications/Claude.app/Contents/Info.plist)), and OpenClaw exposes `sessions_search` to the agent ([OpenClaw memory](https://docs.openclaw.ai/concepts/memory)); Psyche's FTS5 plus sqlite-vec index over transcripts, memory files, Library documents and feed posts should serve the command palette, the Search tab and the agent's own recall tool alike.

## Feed, Ideas, Goals and approvals must be bounded, evidence-linked and confirmable

The market has already run the experiment on autonomous feeds and retreated. ChatGPT Pulse launched September 25, 2025 as 5–10 overnight cards built from chats, memory, Gmail and Calendar, ending with "Great, that's it for today" ([TechCrunch](https://techcrunch.com/2025/09/25/openai-launches-chatgpt-pulse-to-proactively-write-you-morning-briefs/)); on June 18, 2026 OpenAI said Pulse would shut within 14 days and pointed users to a relaunched Scheduled tasks feature for daily briefings ([Gigazine](https://gigazine.net/gsc_news/en/20260619-chatgpt-scheduled-tasks/)), while Gemini moved the same idea into a "Daily Brief" and an Ultra-only "Spark" agent on May 19, 2026 ([Gemini release notes](https://gemini.google/release-notes/)). Kagi News builds one non-personalised briefing a day from thousands of RSS feeds with per-story citations and open-sources its front end and feed lists under MIT ([Kagi blog](https://blog.kagi.com/kagi-news); [kagisearch/kite-public](https://github.com/kagisearch/kite-public)); Particle clusters coverage into per-story cards with an "Opposite Sides" view ([TechCrunch](https://techcrunch.com/2024/11/12/particle-launches-an-ai-news-app-to-help-publishers-instead-of-just-stealing-their-work)); Google Discover's feedback vocabulary is follow topic, "Not interested in [Topic]", "Don't show content from [Source]" and like ([Google Help](https://support.google.com/websearch/answer/2819496)); Readwise resurfaces items on 7/14/28-day half-lives once recall probability falls to 50% ([Readwise](https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights)). Psyche's Feed should therefore be Muse's scheduled agent-authored posts — briefings, reminders, price-watch results, goal check-ins, with hearts and comments — delivered as a bounded daily batch rather than an infinite stream. The pipeline is a human-readable **interest ledger** (topics, entities, goals, explicit blocks and recent accept/reject events in a markdown file the LLM reranker reads and the user can edit) with derived embedding centroids; sourcing from RSS through Miniflux (Apache-2.0) or Karakeep's saved items ([Miniflux](https://github.com/miniflux/v2); [Karakeep](https://github.com/karakeep-app/karakeep)), the rate-limit-free Hacker News API ([HackerNews/API](https://github.com/HackerNews/API)), arXiv at one request per three seconds ([arXiv API ToU](https://info.arxiv.org/help/api/tou.html)) and Bluesky's Jetstream filtered to followed DIDs ([Jetstream](https://bsky.network/docs/jetstream)), with paid search only for gaps now that Bing's APIs retired on August 11, 2025 ([Microsoft Learn](https://learn.microsoft.com/en-us/bing/search-apis/)) — Brave at $5 per 1,000 with $5 free monthly credit, Exa at $4–15, Tavily with 1,000 free credits a month ([Brave](https://brave.com/search/api/); [Exa](https://exa.ai/pricing); [Tavily](https://docs.tavily.com/documentation/api-credits)); embedding recall × recency decay, then an LLM reranker over a shuffled shortlist because zero-shot LLM rankers show position and popularity bias ([arXiv 2305.08845](https://arxiv.org/abs/2305.08845)); one or two exploration slots in the LinUCB style that lifted Yahoo! Front Page clicks 12.5% ([arXiv 1003.0146](https://arxiv.org/abs/1003.0146)); mandatory citations and multi-perspective clusters; and a "serendipity" section in Kagi's deliberately unpersonalised spirit. Overnight generation is justified by sleep-time compute, which cuts test-time compute about 5× when queries are predictable ([arXiv 2504.13171](https://arxiv.org/abs/2504.13171)).

Ideas and Goals are the proactive layer and should be gated, not pushed. Muse generates ideas "from goals, patterns, and past conversation" and renders them as cards with a "Let's do it" action and a recurring toggle ([Meta: How We Designed Muse](https://introducing.muse.ai/); [creator walkthrough](https://openclawdatabase.com/news/videos/2026-10-09-meta-muse-setup-walkthrough-gmail-calendar-browser-soul-memory/index.md)); OpenMuse keeps ideas rules-based "with source evidence; edit, accept, or dismiss," excluding anything already done ([OpenMuse README](https://github.com/CopilotKit/openmuse/blob/main/README.md)). The research is unusually consistent: PRISM intervenes only when "a calibrated probability of user acceptance exceeds a threshold" derived from asymmetric costs and cut false alarms 22.78% ([arXiv 2602.01532](https://arxiv.org/abs/2602.01532)); ProAgentBench's 28,000 real events show long-term memory improves timing prediction ([arXiv 2602.04482](https://arxiv.org/abs/2602.04482)); a unified silent/ask/assist/act framework warns that "offline classification performance does not predict real deployment benefit" ([arXiv 2609.03727](https://arxiv.org/abs/2609.03727)); and trained annotators agreed on where to intervene only at Krippendorff's α = +0.047 ([arXiv 2606.04296](https://arxiv.org/abs/2606.04296)). Psyche should therefore run idea and goal generation as nightly jobs that emit candidates with source links, deliver them in scheduled windows, gate them on an acceptance model learned from accept/dismiss logs, and reserve real-time interrupts for user-declared triggers. Goals follow the same rule: Muse's structured goals with plans, categories and check-ins are worth copying, but TIME's criticism of goals inferred from things users have "not said out loud" ([TIME](https://time.com/article/2026/10/06/meta-muse-ai-agent-privacy/)) and OpenClaw's decision that "The inferred commitments experiment was removed in v2026.8.1, so heartbeat no longer extracts follow-ups from conversations. Explicit automations are the replacement" ([OpenClaw automation](https://docs.openclaw.ai/automation)) are the strongest field evidence that silent goal mining produces stale or unwanted tasks. Represent a goal as category, plan steps, check-in cadence and linked tasks and artifacts; surface inferred goals as one-tap "ask" candidates; and store confirmed goals as explicit automations with OpenMuse-style milestones and recurring watches with retry backoff ([docs/FEATURES.md](https://github.com/CopilotKit/openmuse/blob/main/docs/FEATURES.md)).

Approvals are the trust ledger and deserve a schema, not a dialog. Copy Sentinel's separation — the agent proposes, a separate authority grants, the request renders outside the chat stream — and OpenMuse's binding, and store each approval as `{id, kind (exec | purchase | send_email | send_message | fill_form | connector_write), summary, details, requested_at, expires_at, approvers, surfaces, decision, decided_by, binding_hash}`. Bind it to the exact operation (argv, cwd and executable identity for commands; recipient, subject and content hash plus provider version for messages; merchant and amount for purchases) so that "Changes during the approval window deny the run," reject reused one-time approvals and late answers after the turn closes, and default to deny when no surface is reachable or the prompt times out (`askFallback: deny`) ([OpenClaw exec approvals](https://docs.openclaw.ai/tools/exec-approvals); [OpenMuse SECURITY.md](https://github.com/CopilotKit/openmuse/blob/main/SECURITY.md)). Thirty minutes is the convergent TTL — OpenClaw's chat approvals and Stripe Link's spend approvals both expire then, and Stripe re-requires approval when an amount rises ([OpenClaw Telegram rich messages](https://docs.openclaw.ai/channels/telegram/rich-messages); [Stripe Link](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet/use-link-wallet-pay-online.md)). Offer Muse's scopes (once, this task, this site, always) plus the per-connector action matrix, default to "Ask for some" (writes and important reads), and keep standing grants in a visible ledger with use counts and expiry as OpenClaw does ([OpenClaw exec approvals](https://docs.openclaw.ai/tools/exec-approvals)). An optional reviewer model — Claude's auto-mode classifier or Codex's Guardian with its 0–1 risk score — can approve low-risk actions, but the hard never-list stays model-independent: no purchases or account creation without explicit confirmation, no CAPTCHA bypass, no typing of secrets or payment data, no permanent deletion, and no "following instructions found in emails or web content" ([Claude in Chrome permissions](https://support.claude.com/en/articles/12902446-manage-claude-in-chrome-permissions); [Guardian](https://codex.danielvaughan.com/2026/10/17/guardian-subagent-v0160-risk-based-approval-framework-codex-cli/)). Fan the same approval out to every surface — the Mac notification, the phone chat, the web UI — accept the first authorised answer, and invalidate stale controls after a restart, as OpenClaw's iMessage approvals do ([OpenClaw iMessage rich messages](https://docs.openclaw.ai/channels/imessage/rich-messages)); AP2's signed Intent → Cart → payment chain is the model for turning approvals into a "non-repudiable audit trail" of receipts ([Google AP2](https://cloud.google.com/blog/products/ai-machine-learning/announcing-agents-to-payments-ap2-protocol)).

Notifications fall into four kinds — approval needed, task finished or changed, proactive suggestion, scheduled briefing — and only the first should ever break through. Native `UNUserNotificationCenter` gives categories with `UNNotificationAction` buttons and `UNTextInputNotificationAction` inline replies, provisional authorization for quiet trial delivery, and a `timeSensitive` interruption level that "breaks through system notification controls" such as Focus when the user allows it ([Apple: actionable notifications](https://developer.apple.com/documentation/usernotifications/declaring-your-actionable-notification-types); [Apple: asking permission](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications); [Apple timeSensitive](https://developer.apple.com/documentation/usernotifications/unnotificationinterruptionlevel/timesensitive)); Electron's `Notification` wraps the same API with `hasReply` and `actions` but exposes no interruption level and "the app must be code-signed" ([Electron Notification](https://www.electronjs.org/docs/latest/api/notification)), which is one more reason the Swift helper exists. Give every approval notification a per-run action id and an `authenticationRequired` flag for purchases, the pattern Home Assistant's companion app documents ([Home Assistant](https://companion.home-assistant.io/docs/notifications/actionable-notifications/)), and mirror it on the phone as Telegram inline buttons whose callbacks pass through normal authorization ([OpenClaw Telegram rich messages](https://docs.openclaw.ai/channels/telegram/rich-messages)). Claude Desktop's behaviour — an OS notification only when a session finishes and is not in view, plus a phone push when a remote device started the work ([Claude Code Desktop docs](https://code.claude.com/docs/en/desktop.md)) — is the right default quietness.

Inline artifacts need two origins and a sandbox, and viewers need licence discipline. Muse's artifacts are "Interactive outputs that appear in chat and can also exist outside it" — itineraries, PDFs, live dashboards, habit trackers that "open in the browser and can be updated by name" — built on a "Spaces" mini-app framework (React client, Drizzle SQLite, Bun) with separate builders for documents, PDFs, presentations, spreadsheets and Markdown ([Meta: How We Designed Muse](https://introducing.muse.ai/); [Learn AI with Mariah](https://learnaiwithmariah.com/guides/meta-muse-6-things-to-try/); [mouse.dev](https://mouse.dev/blog/muse-runtime-export/)). Claude's artifacts run on a separate `claudeusercontent.com` origin under a CSP that blocks external `connect-src` ([Simon Willison](https://simonwillison.net/2024/Oct/21/claude-artifacts/)), and Psyche should do the same: an `<iframe sandbox="allow-scripts" srcdoc>` served from a second origin with a `<meta>` CSP, never adding `allow-same-origin` because MDN warns the combination "lets the embedded document remove the sandbox attribute" ([MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)), resized through a ResizeObserver/postMessage handshake rather than iframe-resizer, which is GPL-3.0 with paid commercial tiers ([npm iframe-resizer](https://registry.npmjs.org/iframe-resizer/latest); [pricing](https://iframe-resizer.com/pricing/)). React artifacts go through Sandpack with a self-hosted bundler on that second subdomain ([Sandpack](https://sandpack.codesandbox.io/docs/guides/hosting-the-bundler)); WebContainers "require licensing for production usage in a commercial, for-profit setting" ([WebContainers](https://webcontainers.io/enterprise)). For files in the Library: PDF.js is on the 6.x line (`pdfjs-dist` 6.4.299, Apache-2.0) with react-pdf 11 requiring React 19 ([npm pdfjs-dist](https://registry.npmjs.org/pdfjs-dist/latest); [react-pdf release](https://api.github.com/repos/wojtekmaj/react-pdf/releases/latest)), EmbedPDF's PDFium-based core is Apache-2.0 for annotation and redaction ([EmbedPDF LICENSE](https://raw.githubusercontent.com/embedpdf/embed-pdf-viewer/main/LICENSE)), and the Swift shell gets `PDFView` and widget filling from PDFKit for free ([Apple PDFView](https://developer.apple.com/documentation/pdfkit/pdfview); [Apple PDFAnnotation](https://developer.apple.com/documentation/pdfkit/pdfannotation)). Spreadsheets must avoid npm's `xlsx`, frozen at 0.18.5 with a High-severity advisory for which "A non-vulnerable version cannot be found via npm" — install SheetJS CE 0.20.3 from cdn.sheetjs.com and render with TanStack Table ([GitHub advisory](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6); [SheetJS docs](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)); for editing, Univer 1.1.0 keeps formulas, conditional formatting and data validation in its Apache-2.0 core while xlsx import/export, charts and pivots are Pro ([Univer README](https://raw.githubusercontent.com/dream-num/univer/dev/README.md)); Handsontable needs a licence key even for non-commercial use and HyperFormula is GPL-3.0-only ([Handsontable licence](https://handsontable.com/docs/javascript-data-grid/software-license/); [npm hyperformula](https://registry.npmjs.org/hyperformula/latest)). DOCX previews come from docx-preview (Apache-2.0) with mammoth (BSD-2) for semantic HTML ([npm docx-preview](https://registry.npmjs.org/docx-preview/latest); [npm mammoth](https://registry.npmjs.org/mammoth/latest)); no maintained permissive PPTX renderer exists, so convert through LibreOffice headless or Gotenberg (MIT, Docker) or, on the Mac, `qlmanage -t -s 1600 -o <dir>` ([Gotenberg](https://raw.githubusercontent.com/gotenberg/gotenberg/main/README.md); [qlmanage](https://keith.github.io/xcode-man-pages/qlmanage.1.html)); Collabora Online is MPL-2.0 while ONLYOFFICE is AGPL-3.0 ([Collabora COPYING](https://github.com/CollaboraOnline/online/blob/master/COPYING); [ONLYOFFICE](https://api.github.com/repos/ONLYOFFICE/DocumentServer)). Code and data views use CodeMirror 6 and Shiki 4's JavaScript regex engine (no WASM download) rather than Monaco, whose workers "fail on `file://` pages" and whose package is 101 MB unpacked ([Shiki engines](https://shiki.style/guide/regex-engines); [Monaco README](https://raw.githubusercontent.com/microsoft/monaco-editor/main/README.md)); render Mermaid with `securityLevel: 'sandbox'` ([Mermaid](https://mermaid.js.org/config/usage.html)). OpenMuse's document pipeline — AcroForm fill, preview, reviewed reply, receipt — maps onto pdf-lib on the server (`getForm()`, `flatten()`) or PyMuPDF (`is_form_pdf`, `Document.bake()`), PDFKit's `burnInAnnotationsOption` natively, and Apple Vision's `RecognizeDocumentsRequest` for scanned forms on macOS 26 ([pdf-lib](https://pdf-lib.js.org/); [PyMuPDF](https://pymupdf.readthedocs.io/en/latest/document.html); [Apple PDFDocumentWriteOption](https://developer.apple.com/documentation/pdfkit/pdfdocumentwriteoption); [Apple RecognizeDocumentsRequest](https://developer.apple.com/documentation/vision/recognizedocumentsrequest)); XFA forms are the exception no permissive library fills ([pdftk man page](https://www.pdflabs.com/docs/pdftk-man-page/)). Sharing goes through `NSSharingServicePicker` and previews through `QLPreviewPanel` ([Apple NSSharingServicePicker](https://developer.apple.com/documentation/appkit/nssharingservicepicker); [Apple QLPreviewPanel](https://developer.apple.com/documentation/quicklookui/qlpreviewpanel)).

The built-in markdown editor matters more than usual because SOUL, IDENTITY, MEMORY and the daily notes are markdown the user is invited to edit, as Muse already allows ([Hacker News](https://news.ycombinator.com/item?id=49802871)). Only MDXEditor (`@mdxeditor/editor` 4.3.3, MIT) ships a first-party rich-text / source / diff toggle via `diffSourcePlugin` ([npm](https://registry.npmjs.org/@mdxeditor/editor/latest); [MDXEditor diff-source](https://mdxeditor.dev/editor/docs/diff-source)); the safest pattern for arbitrary user files is CodeMirror 6 as the canonical source with Obsidian-style live-preview decorations — Obsidian "uses CodeMirror 6 to power the Markdown editor" ([Obsidian docs](https://docs.obsidian.md/Plugins/Editor/Editor+extensions); [lang-markdown](https://raw.githubusercontent.com/codemirror/lang-markdown/main/README.md)) — so that the agent's files are never silently rewritten by a lossy AST round trip. Avoid BlockNote, whose export is literally `blocksToMarkdownLossy` and whose XL packages are "GPL-3.0 OR PROPRIETARY" ([BlockNote docs](https://www.blocknotejs.org/docs/features/export/markdown); [BlockNote README](https://raw.githubusercontent.com/TypeCellOS/BlockNote/main/README.md)), and treat TipTap's official markdown extension as the "early release" it says it is ([TipTap markdown](https://tiptap.dev/docs/editor/markdown)).

Persona customisation is a file plus an avatar. `IDENTITY.md` holds name, creature, vibe and tagline (OpenClaw creates it in a one-time bootstrap ritual and ships per-agent themes and avatars in its Control UI) ([Agent workspace](https://docs.openclaw.ai/concepts/agent-workspace); [OpenClaw README](https://github.com/openclaw/openclaw/blob/main/README.md)), `SOUL.md` holds tone and boundaries, and OpenMuse shows the minimum viable version — editable name, tone, avatar and memories, with an original capybara mascot bundled locally ([docs/EXPERIENCE.md](https://github.com/CopilotKit/openmuse/blob/main/docs/EXPERIENCE.md)). Muse concentrates motion in the avatar (it "types on a tiny keyboard" while working) and in small card animations rather than page transitions ([Engadget via Yahoo](https://finance.yahoo.com/technology/article/metas-muse-is-an-impressively-capable-ai-agent-despite-some-hiccups-173310662.html)), so Psyche needs idle, working and attention states for the avatar and little else. Muse's pencil-icon natural-language avatar edits imply image generation, but no source confirms the mechanism; a safe v1 is a curated creature set with colour and accessory layers, with optional generation through whichever image model the user has connected. Keep the relationship-building prompt language modest: The Conversation's critique that "the design invites attachment" is aimed squarely at Muse's "strengthen your relationship" instructions ([The Conversation](https://theconversation.com/meta-wants-people-to-use-ai-agents-to-do-daily-tasks-for-them-heres-why-thats-a-problem-292962)).

Theming with a user-chosen accent is a solved problem in the shadcn ecosystem. shadcn's tokens are semantic OKLCH CSS variables (`--primary: oklch(0.205 0 0)`, `--radius` with derived steps) mapped into Tailwind through `@theme inline` ([shadcn theming](https://ui.shadcn.com/docs/theming); [Tailwind theme](https://tailwindcss.com/docs/theme)); Radix's 12-step scale semantics (1–2 backgrounds, 3–5 components, 6–8 borders, 9–10 solids, 11–12 text, with steps 11 and 12 guaranteed to reach APCA Lc 60 and Lc 90 on step 2) are the target ([Radix scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)), and the generator that produces them from a seed — `generateRadixColors({ appearance, accent, gray, background })` using colorjs.io, bezier easing and an APCA check for text colour — is MIT in Radix's website repo and can be vendored and run twice per accent (light and dark), writing `--accent-1..12`, alpha and P3 variants and mapping onto `--primary`, `--ring`, `--border` and friends ([generate-radix-colors.tsx](https://github.com/radix-ui/website/blob/main/components/generate-radix-colors.tsx); [Radix Themes color](https://www.radix-ui.com/themes/docs/theme/color)). `light-dark()`, `color-mix()` and `@property` are all Baseline ([MDN light-dark](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark)); gate accessibility on WCAG 2 contrast and show APCA only as advisory, because WCAG 3's algorithm "is yet to be determined" and the `apca-w3` package carries a restrictive non-commercial licence ([W3C WCAG 3.0](https://www.w3.org/TR/wcag-3.0/); [APCA LICENSE](https://github.com/Myndex/SAPC-APCA/blob/master/LICENSE.md)). Density and font tokens follow Radix Themes' `--scaling`, `--radius` and font-family variables.

Dictation and voice memos are Swift-helper work with a security lesson attached. On macOS 26 and later use `SpeechAnalyzer` with `SpeechTranscriber`: fully on-device, system-managed models that "run outside the app's memory space," volatile then final results on an async sequence, no one-minute limit, and `DictationTranscriber` for custom vocabulary ([Apple SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber); [Apple DictationTranscriber](https://developer.apple.com/documentation/speech/dictationtranscriber); [WWDC25 session 277](https://developer.apple.com/videos/play/wwdc2025/277/)); on macOS 14–15 use FluidAudio's Core ML Parakeet (about 0.19 s on a short clip, 2.1% LibriSpeech WER on the Neural Engine) or WhisperKit for broader language coverage ([FluidAudio benchmarks](https://docs.fluidinference.com/reference/benchmarks); [mac-whisper-speedtest](https://github.com/anvanvan/mac-whisper-speedtest); [WhisperKit](https://github.com/argmaxinc/WhisperKit)); keep `SFSpeechRecognizer` as a last resort given its one-minute and daily-quota limits ([Apple SFSpeechRecognizer](https://developer.apple.com/documentation/speech/sfspeechrecognizer)). Claude Desktop implements its dictation overlay and hotkey listener in the Swift addon ([Telkins teardown](https://www.telkins.com/blog/a-teardown-of-the-claude-desktop-app)), and Muse's hold-the-function-key dictation into any app is the UX to match — but Muse's zero-day was precisely a locally overridable dictation endpoint preference ([Unite.AI](https://unite.ai/meta-hot-fixes-muse-zero-day-that-let-attackers-hijack-the-ai-agent)), so Psyche's audio path must have no user-space-writable endpoint override. For outbound voice memos synthesise PCM with `AVSpeechSynthesizer.write` (Personal Voice is licensed for "personal, non-commercial purposes" only) or Kokoro-82M (Apache-2.0, 24 kHz, about 23× real time via Core ML) ([Apple AVSpeechSynthesizer](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer); [Kokoro](https://github.com/hexgrad/kokoro); [FluidAudio benchmarks](https://docs.fluidinference.com/reference/benchmarks)), then transcode per channel: Telegram's `sendVoice` wants OGG/Opus, MP3 or M4A ([Telegram Bot API](https://core.telegram.org/bots/api#sendvoice)), WhatsApp voice notes require OGG with Opus ([WhatsApp audio](https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/audio-messages)), and iMessage renders inline voice bubbles only from CAF ([Sendblue](https://docs.sendblue.co/docs/voice-note)); OpenClaw's output rules — 48 kHz mono Ogg/Opus for Telegram and WhatsApp, MP3 elsewhere — are a ready default ([OpenClaw TTS output](https://docs.openclaw.ai/tools/tts/output)).

Reply and export round out the surfaces. Muse lets users "Download your Muse data" (chats, files and agent information), ask the agent to export its files, and expose generated podcasts as RSS ([saascrmreview](https://saascrmreview.com/how-to-use-meta-muse/); [TIME](https://time.com/article/2026/10/06/meta-muse-ai-agent-privacy/); [nocode.mba](https://www.nocode.mba/articles/meta-muse-ai-review)); Claude Desktop exposes `export_transcript` to the agent and lets individual artifacts be shared while sessions cannot ([tool manifest](file:///Applications/Claude.app/Contents/Resources/app.asar); [Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)); OpenClaw recommends backing up the workspace files to a private git repository ([Agent workspace](https://docs.openclaw.ai/concepts/agent-workspace)). Psyche should export any thread as markdown or JSON, the memory directory as a zip, and the Library as files; import memory additively and as data; and make "delete" delete — retracting claims and rebuilding the index the way Muse's forget skill does, but without leaving the originals behind.

## Channels, payments and server mode should reuse OpenClaw's pairing and Stripe's Link

Designated-person messaging is OpenClaw's model almost verbatim. For a single-owner agent set `dmPolicy: allowlist` with the owner's numeric Telegram ID, E.164 number or Apple ID (or keep the default `pairing`, where unknown senders get an 8-character code expiring after one hour with at most three pending), set `commands.ownerAllowFrom` because "Manually allowlisted senders are not automatically owners" and "Ownership does not grant chat access," gate groups with `groupPolicy: allowlist` plus `requireMention`, isolate strangers with `session.dmScope: per-channel-peer`, merge the owner's identities across channels with `session.identityLinks`, and filter quoted context from non-allowlisted senders with `contextVisibility` ([OpenClaw access control](https://docs.openclaw.ai/gateway/security/access-control); [OpenClaw pairing](https://docs.openclaw.ai/channels/pairing); [OpenClaw session](https://docs.openclaw.ai/concepts/session)). Approvals must come only from owner identities — OpenClaw's `allowFrom` lists "do not grant approval rights" ([OpenClaw Telegram rich messages](https://docs.openclaw.ai/channels/telegram/rich-messages)). Telegram is the easiest fully supported channel (grammY, long polling by default, inline buttons for approvals, a webhook `secret_token` if exposed) ([OpenClaw Telegram](https://docs.openclaw.ai/channels/telegram); [Telegram Bot API](https://core.telegram.org/bots/api)); iMessage is viable only as a Mac-node capability through `imsg rpc` over JSON-RPC on the signed-in Messages Mac, with the Gateway elsewhere reaching it through an SSH wrapper ([OpenClaw iMessage](https://docs.openclaw.ai/channels/imessage); [OpenClaw iMessage setup](https://docs.openclaw.ai/channels/imessage/setup)); Signal needs signal-cli and a separate number ([signal-cli](https://github.com/AsamK/signal-cli); [OpenClaw Signal](https://docs.openclaw.ai/channels/signal)); Slack works over Socket Mode without a public URL ([Slack Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode)); Discord's `MESSAGE_CONTENT` intent is self-enabled below 10,000 users ([Discord Gateway](https://docs.discord.com/developers/events/gateway)); SMS through Twilio requires US 10DLC registration ([OpenClaw SMS](https://docs.openclaw.ai/channels/sms)). WhatsApp is the hard case: OpenClaw's Baileys path is unofficial and the Baileys maintainers themselves discourage automated use ([WhiskeySockets/Baileys](https://github.com/WhiskeySockets/Baileys)), while Meta's Cloud API is compliant but charges per template message and lets you reply freely only inside a 24-hour window the user opens ([Meta WhatsApp pricing](https://developers.facebook.com/docs/whatsapp/pricing)) — it is an "assistant you text" channel, not a "read my WhatsApp" tool. Claude Code's channels research preview (Telegram, Discord, iMessage via `chat.db` and AppleScript, with pairing codes and a permission-relay capability) confirms the same shape from Anthropic's side ([Claude Code channels](https://code.claude.com/docs/en/channels.md)), and Muse's roadmap of "its own email address" ([TechCrunch](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/)) is cheap to copy as a dedicated mailbox read through the Gmail API or JMAP.

Shopping and payments split into an identity problem and a credential problem, and Muse shows both. Muse detects checkouts, shows exact purchase details for approval every time, and pays with a single-use card bound to one merchant, one amount and a time window ([Meta research post](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)), yet Amazon blocked it as "an unauthorized AI agent" ([Fortune](https://fortune.com/2026/09/22/metas-muse-ai-is-exploding-in-popularity-and-drawing-heated-backlash/); [Payments Dive](https://www.paymentsdive.com/news/amazon-meta-muse-ai-agentic-shopping-experience/831052/)). For a self-hosted agent the usable stack is Stripe's **Link Agent Wallet**: the agent creates a spend request with a ≥100-character context and merchant details, "The customer approves it on the Link website or in the mobile app" within 30 minutes, and the agent receives a one-time virtual card or a `link_pay_token`; agent payments need no Stripe account, spend limits are queryable, and Stripe tells hosted agents to write card details to a 0600 file "rather than returning them to stdout, where they can persist in model transcripts" ([Stripe Link Agent Wallet](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet.md); [Stripe: enable agents to spend](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet/use-link-wallet-pay-online.md)). Stripe's own outcome tags — `captcha`, `anti_bot_script`, `waf_block`, `login_required`, `3ds_challenge` — enumerate what the browser agent will hit ([Stripe](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet/use-link-wallet-pay-online.md)). Where the merchant runs Stripe, WebMCP exposes checkout as structured in-page tools and marks payment submission with a `consequentialHint` the agent must confirm with the user first ([Stripe WebMCP](https://docs.stripe.com/agentic-commerce/agents/webmcp.md)); Shared Payment Tokens cover agent-as-seller flows ([Stripe SPT](https://docs.stripe.com/agentic-commerce/concepts/shared-payment-tokens.md?agent-seller=agent)). The merchant-side protocols are not for individuals: ACP's checkout endpoints are implemented by businesses and OpenAI "deprioritized" Instant Checkout in March 2026 ([ACP spec](https://developers.openai.com/commerce/specs/checkout); [TechCrunch](https://techcrunch.com/2026/03/24/openais-plans-to-make-chatgpt-more-like-amazon-arent-going-so-well)), and Shopify's UCP tiers "unlock broader access, including direct checkout completion" only at higher trust ([Shopify agents](https://shopify.dev/docs/agents)). Sign browser traffic with Web Bot Auth, which Visa's Trusted Agent Protocol also builds on ([visa/trusted-agent-protocol](https://github.com/visa/trusted-agent-protocol)), run the browser on the user's own device with the user's own session — the architecture under which the Ninth Circuit held that "the user, not Perplexity, 'accesses'" Amazon's systems ([Jones Day](https://www.jonesday.com/en/insights/2026/09/ninth-circuit-vacates-cfaa-injunction-against-perplexitys-comet-ai-agent)) — and copy Amazon Buy for Me's confirmation screen of address, taxes, shipping and payment method before any purchase ([About Amazon](https://www.aboutamazon.com/md/news/retail/amazon-shopping-app-buy-for-me-brands)). Order tracking has no protocol; parse order emails or use Shopify's Order MCP where available ([Shopify agents](https://shopify.dev/docs/agents)).

Server mode is the same gateway in Docker Compose, with remote access by identity rather than by exposure. OpenClaw's deployment is the template: image on a state volume, Control UI on the same loopback port, `/healthz` and `/readyz` probes, secrets in Compose `.env` or env-ref indirection so credentials stay out of the main config, state snapshots before schema migrations, and "For mutually untrusted users, run a separate Gateway for each trust boundary" ([OpenClaw Docker](https://docs.openclaw.ai/install/docker); [OpenClaw security](https://docs.openclaw.ai/gateway/security)). Reach it over Tailscale Serve, which proxies a local port at a tailnet HTTPS name and injects `Tailscale-User-Login` headers while stripping client copies, so the app can run trusted-header auth with the core still bound to 127.0.0.1 ([Tailscale Serve](https://tailscale.com/kb/1312/serve); [Open WebUI Tailscale](https://docs.openwebui.com/tutorials/auth-sso/tailscale)); off-tailnet phones get Cloudflare Tunnel plus Access, with the warning that OpenClaw's trusted-proxy mode "does not verify the JWT signature" — Psyche should ([OpenClaw Cloudflare Access](https://docs.openclaw.ai/gateway/cloudflare-access); [OpenClaw trusted-proxy auth](https://docs.openclaw.ai/gateway/trusted-proxy-auth)). Funnel is public and should be avoided for browser control ([OpenClaw Tailscale](https://docs.openclaw.ai/gateway/tailscale)). For more than one app, Pocket ID is a passkey-only OIDC provider in a single container ([Pocket ID](https://pocket-id.org/)); native passkeys require a secure context, which plain-HTTP LAN addresses are not ([LibreChat passkeys](https://www.librechat.ai/docs/configuration/authentication/passkeys); [MDN secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts)); Compose secrets mounted at `/run/secrets/<name>` beat environment variables that "can end up in logs" ([Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/)). The Mac-versus-server split is OpenClaw's: the server runs channels, the model loop, the scheduler and the approvals ledger, while the Mac joins as a paired node that executes Mac-only tools — iMessage, actionable notifications, screen and camera, computer use, the local VM — with pairing treated like operator access (a 10-minute single-use bootstrap token, pending requests expiring in 5 minutes, explicit approval for anything non-loopback) ([OpenClaw nodes](https://docs.openclaw.ai/nodes); [OpenClaw pairing](https://docs.openclaw.ai/channels/pairing); [OpenClaw architecture](https://docs.openclaw.ai/concepts/architecture)). Background "aliveness" is a cheap heartbeat turn every 30 minutes with a tiny scratch context, quiet `NO_REPLY` replies and a scheduler that coalesces missed ticks after sleep ([OpenClaw heartbeat](https://docs.openclaw.ai/gateway/heartbeat); [OpenClaw architecture](https://docs.openclaw.ai/concepts/architecture)), plus explicit automations with isolated sessions for exact-time work. And the one-click RCE should be designed out from the first commit: no `gatewayUrl` query parameter that auto-connects, strict WebSocket origin validation, tokens never in URLs, and pairing before any scope grant ([The Hacker News](https://thehackernews.com/2026/02/openclaw-bug-enables-one-click-remote.html)).

## Conclusion

The personal-agent category has settled faster than its marketing suggests, and the settlement is modular: the face comes from Muse (surfaces, avatar sheet, approval scopes, editable identity files), the spine from OpenClaw (gateway, pairing, markdown memory with budgets and provenance, approvals bound to the exact operation), the task engine from OpenMuse (durable plans, stored reviews, receipts, uncertain-outcome reconciliation), and the card grammar from Claude Desktop (permission, question, plan and next-step cards rendered from tool traffic). What none of them has shipped together is a trust ledger that is both complete and legible — every grant, fill, send and purchase bound to a hash, time-boxed, fanned out to the owner's devices and recorded as a receipt — and that, rather than any model or feature, is where an open-source Psyche can be better than the $100-a-month incumbents, precisely because Muse was attacked on trust (dossiers, delete-that-forgets-nothing, a hijackable dictation endpoint, human concierges) while being praised on design.

The engineering budget should be allocated accordingly. The LLM loop, the chat UI and the viewers are commodity picks with permissive licences; the expensive, differentiating work is the review-and-receipt engine, the credential broker, the macOS TCC plumbing in a signed Swift helper, and the proactivity layer that generates Feed, Ideas and Goals as confirmable candidates rather than interruptions. Two forces will keep moving the ground: model generation is now a measurable security control (pre-safeguard prompt-injection rates differ by 4–5× between adjacent Claude generations), and the platform substrate is shifting toward Psyche — macOS 27 made unattended Mac VMs and copy-on-write guest snapshots possible, MCP 2026-07-28 made stateless hosts and in-chat MCP Apps standard, and Tauri 3's CEF runtime and Electrobun are the only credible routes to shedding Electron's weight without losing the embedded browser. Build the gateway first, keep every capability behind a grant, and let the avatar do the charming.
