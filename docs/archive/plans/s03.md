# S03 plan: model router

Goal: `@psyche/model-router` is the only code that talks to model providers (architecture §4.4, B1–B6, ADR-003). It implements `ModelProvider` per provider family and a `ModelRouter` (also a `ModelProvider`, id `router`) that adds roles, fallbacks, cooldowns, auth-profile rotation, strict mode, usage accounting and the capability probe.

## Shape

- **Adapters** (`src/adapters/`). One generic `AiSdkAdapter` drives any AI SDK v7 `LanguageModelV4` through `doStream` (no `streamText`: the router owns retries, and we need the raw parts to round-trip provider metadata). A factory builds the model per kind: `anthropic`, `openai` (Responses), `google` (Interactions), `openrouter`, `openai-compatible` (llama.cpp, LM Studio, vLLM, mlx-lm), `anthropic-compatible` (Ollama `/v1/messages`), `ollama` (native `/api/chat`).
- **Request conversion**: `ModelMessage` parts to the V4 prompt. Tool results need a tool name; it is taken from the part or from the matching earlier `tool_call`. Images become `file` parts. `ToolSpec`s become function tools; on Anthropic, specs named `memory` / `computer` become `memory_20250818` / `computer_toolset_20260801` when the profile enables them.
- **Opaque round-tripping**: provider metadata (Anthropic thinking signatures, OpenAI reasoning item ids and encrypted content, Gemini signatures on tool calls) travels as `reasoning` events whose `data` is a versioned envelope tagged with provider and model. Envelopes for another provider or model are dropped on the way back, so a fallback never sends Claude signatures to OpenAI. `TurnAccumulator` builds the assistant `ModelMessage` from the stream in arrival order (for S02).
- **Keys**: profiles hold `{{cred:slug}}` placeholders plus a standing `credential_fill` approval id. The provider package is built with a sentinel key; a fetch wrapper resolves the secret through `CredentialBroker` per HTTP request and swaps it into the header inside `ResolvedSecret.use`. Error text passes through `broker.redact`. No headers are logged.
- **Router**: refs `provider/model`; `router/<role>` picks a role chain (`primary` + `fallbacks[]`, `utility`, `embedding`, `vision`, `speech`). Errors are classified (rate limit, overloaded, server, timeout, auth, billing, not found, context overflow, bad request). Retryable errors put the profile, then the provider, in cooldown (30 s, 1 m, 5 m cap; billing 10 m). Rotation goes through the profiles before the next fallback. Fallback happens only before the first content event of a call; after that the stream ends with `finish{error}`. Strict mode (user-pinned or per-thread `/model`) never changes model and fails visibly. A `prepareStep` hook can swap the model per step.
- **Usage**: AI SDK v7 usage normalized to disjoint classes (`input` = uncached input; `cacheRead`, `cacheWrite`; `output` includes `reasoning`). Cost comes from the vendored price table (`src/data/prices.json`, from LiteLLM via `pnpm prices:update`), or from OpenRouter's reported cost. `UsageLedger` writes rows through `UsageRepository` (in-memory and SQLite against the existing `usage` table), exposes `summary()` for the meter, and fires budget alerts at 80% and 100% once per month.
- **Probe** (B4): six cases (single tool call, typed arguments, parallel calls, no tool when none is needed, uses a tool result, JSON-only answer). It passes at 5/6 with both tool-call cases required. The result is persisted through `ProbeStore`. `setRole("primary", chatOnlyModel)` throws unless `override: true`. RAM-fit guidance and suggested local models are a static table.
- **Embeddings**: `embed(texts, {model, task})` through any adapter with an embedding model. nomic task prefixes are applied; `embeddingInfo()` reports the dimension.

## Tests

Recorded wire fixtures (SSE / NDJSON bodies) are replayed through an injected `fetch`, so the real provider packages parse them. No network. Each adapter covers streaming text, parallel tool calls, tool results in, images in, reasoning round-trip, usage, error mapping and cancellation. Router tests run on `FakeModelProvider` plus `FakeClock`. Live tests are behind `PSYCHE_LIVE_TESTS=1`.

## Risks

- Fixtures are hand-written from the provider docs, not recorded against live APIs (no keys in CI). Live tests re-check them.
- Provider keys need a standing `site` grant from S06 (B6); until then tests use the fake broker.
- The contract has no tool-call delta event and no structured error code on `finish`; the code is a prefix of `finish.error` (`rate_limited: …`).
