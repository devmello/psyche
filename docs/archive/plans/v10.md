# V10 coding helper: plan

Owner: the M3 coding-helper session (S02 scope, `packages/agent-core`). Spec: docs/03 V10 (P1), C1–C3, C10; security docs/05 §3.5 (bindings), §3.6 (taint), §5.1 (container contract, mount validation), §5.4 (no host fallback).

## Goal

A task opens a repository folder the owner granted and works in it: search, read, patch, run the tests in the sandbox, and use git, with every write behind the broker and a receipt, and a push only after a card that names the remote and the branch.

## Shape

- **Workspace** (`packages/agent-core/src/coding/`): `code.open {path}` binds a repository root (a real path inside a folder the owner granted; the broker's folder policy decides) to the call's task, or its thread when there is no task. Every other `code.*` tool names the root and refuses one that is not open in its scope.
- **Tools.**
  - `code.search` (read): regex or literal search with path globs over the root, ripgrep-style `path:line:text` hits; skips `.git`, `node_modules`, symlinks and binaries.
  - `code.read` (read): delegates to the P9 `read_file` executor (same provenance index and limits) with a root-relative path and optional line range.
  - `code.edit` (write, `file_write`): a unified diff over one or more files under the root; the card and the receipt carry the diff; files are written through the P9 `write_file` executor (atomic, provenance recorded) after a hash check. Never `.git/`.
  - `code.run` (write, `exec`): argv in the sandbox scope `project:<workspace>` with the repository bind-mounted at `/workspace/repo` (`.git` read-only), network `none`; `network: "proxy"` goes through the K4 egress proxy and its per-origin cards. A cwd outside the root is refused.
  - `code.git` (read for `status` / `diff` / `log`; `git_write` for `commit` / `branch`; `git_push` for `push`): a fixed git argv on the host (hooks off, no external diff or textconv, no prompts), never a shell. Push binds root + remote + remote URL + branch + commit, `once` only, and is never forced.
- **Protocol** (`protocol:` PR first): approval kinds `git_write`, `git_push`; `SandboxMount` and `ensureSandbox(scope, {mounts})`; the fake runner keeps mounts.
- **Permissions**: card titles and key fields, `git_push` offers `once` only, the folder check covers `code.*` path targets, `inferApprovalKind` maps `code.*`.
- **Sandbox**: the container runner bind-mounts validated sources (real path, not `/`, the home root, `~/Library` or `$PSYCHE_HOME`).
- **Gateway**: `apps/gateway/src/compose/coding.ts` (host git runner, registration with the sandbox runner and the P9 file tools), wired after the sandbox part.
- **UI**: approval cards and tool blocks with a `diff` detail render through the existing diff viewer (check `packages/viewers` first).
- **Acceptance**: `tests/acceptance/scenarios-m3/v10-coding-helper` in S18's format: fix a failing test in a fixture repo, run the tests in the fake runner, commit, push only after a card; refusal when the model runs a command outside the workspace. Scorecard row V10.

## Risks

- A read-write repository mount is a bridge out of the container (SharedRoot). Mitigations: `.git` is mounted read-only so a command cannot plant hooks or config the owner's own git would run; host git runs with hooks off; only folders the owner granted read-write are mounted.
- Host git is not `exec_host`: it is a fixed set of subcommands with fixed flags, like the file tools writing host files. Push uses the owner's credentials, so it is `once` only and bound to the exact commit.
- No container runs on this Mac (heat rule): the runner's mount flags are unit-tested with the fake driver only.
