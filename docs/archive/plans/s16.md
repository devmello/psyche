# S16 plan: search and skills

Owner: S16. Paths: `packages/search/**`, `packages/skills/**`, plus own migrations in `packages/db/migrations/` (`search_*`, `skills`). Features: S1 (S2 later), T1, T2, T5 (loading side).

## Goal

1. **`@psyche/search`**: one SQLite FTS5 index over everything the owner and the agent produced (architecture §4.12, UI §3.13), queried with a small filter language, ranked with a recency boost, grouped by kind with highlights, permission-aware, kept current from Gateway events. Memory is not copied: memory hits come from `MemoryStore.search` and are fused in at query time.
2. **`@psyche/skills`**: discovery, parsing, gating, the prompt index and the `skills_search` / `skills_read` tools (T1), and the install / trust pipeline (T2): sources, static scan, optional VirusTotal hash lookup, `skill_install` approval through `PermissionBroker`, a lock file with whole-tree hashes, update with diff review, disable / remove.

## Steps

1. Tests: parser, ranking, filters, scoping, events, conformance suite, 100k-document timing.

Install and trust: sources (local path, git at a ref resolved to a commit, zip with size and path limits), whole-tree hash, scanner rules, VirusTotal client behind a key, proposals with a `skill_install` binding hash, install that verifies the binding and records a receipt, lock file, update proposals with a unified diff, enable / disable / remove, `skills.*` handlers.
4. Protocol PR (`protocol: …`): optional `SearchIndexDoc` fields (`scopeKey`, `parentId`, `flags`), richer `SearchHit`, `skills.*` method schemas, optional `SkillLoader` methods. Until it merges, the packages export local types with the same shape.
5. README per package, `docs/status/s16.md`, independent review subagent, PR.

## Decisions (see READMEs for detail)

- **Incognito content is never stored** (stronger than "never returned"): indexing an incognito doc deletes any existing row with that id.
- **Designated-person scoping**: every doc has a `scopeKey` (`owner` by default; channel threads with a persona overlay carry their session key). The owner sees all non-incognito docs; a delegated viewer sees only its own scope and never memory.
- **Workspace skills need the owner's approval** (review design-02, Critical): the agent can write `workspace/skills/**` through the memory tool, so a workspace `SKILL.md` is indexed only when its tree hash matches an owner-approved lock entry. Unapproved or changed workspace skills are listed as drafts and never reach the prompt.
- **Whole-tree hash re-verified on every load** (review design-24): installed skills whose files changed are disabled with `hash_mismatch` and reported through `onChange`.
- **Third-party skill text is untrusted** (design-24): `skills_read` returns `provenanceOut: "untrusted"` for `verified | unknown` trust, so reading it taints the turn. Bundled and owner-approved local skills are trusted.
- **High-severity scan findings block enabling.** The skill can still be installed (so the owner can read it in place) but stays disabled; enabling it is refused with `policy_denied` while any `high` finding stands.
- `skill_install` binding hash: `sha256("psyche.binding.v1|skill_install|" + canonicalJSON({name, source, treeHash}))`; grant key `skill_install|<name>`; side effect `destructive` so it is `once`-only and device-only.

## Interfaces

Implements `SearchIndex`, `SkillLoader`. Consumes `MemoryStore`, `PermissionBroker`; tests use `FakeMemoryStore`, `FakePermissionBroker`, `FakeClock`. Events consumed: `chat.message`, `thread.updated`, `task.updated`, `task.action`, `approval.created`, `receipt.created`.

## Risks

- FTS5 `bm25()` with a JS recency UDF over very common terms: measured by the 100k-document test.
- `fs.watch` recursive behaviour differs on Linux; the watcher rescans the whole root on any event, so missing details are tolerated.
- Git sources shell out to the `git` binary (argv only, no shell, protocol allowlist, hooks off); a pure-JS fallback is not planned.
- Tool names used by `requires.tools` are provisional until S02 / S09 publish the registry.
