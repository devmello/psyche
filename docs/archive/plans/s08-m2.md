# S08 plan, Milestone 2 slice: I15, I10, I12 (2026-10-19)

Branch `ws/s08-m2` from `main` (after INT-2 #81). M1 plan: [s08.md](s08.md). Three small PRs, in this order.

## PR 1: I15 logged-out profile

**Goal.** A task browses without the owner's sign-ins unless it has a reason to use them, the choice is explicit and visible, and it is never remembered (security §6 "Logged-out default").

- `choosePartition(url, policy)` in `src/origin/partition.ts`: the task's mode is `profile`, `clean` or `auto`. `auto` opens a tab in the persistent profile only when its origin is one the owner has signed into (`signedInOrigins` patterns); every other tab, and every blank tab, is `clean`. Popups inherit the opener's partition.
- Both drivers open tabs per partition: the bridge driver passes `profile: clean | logged-in` on `bridge.tab.open` (the pane's indicator); the Playwright driver keeps one ephemeral context per session beside the persistent one.
- `listTabs` reports `partition` per tab; `browser.tabs` (client) shows it instead of a constant.
- Fixtures gain a cookie jar per partition and a `a/account` page that says who is signed in, so the conformance suite proves the isolation on the mock and on real Chromium.

## PR 2: I10 recording (two PRs: `protocol:` first)

- `protocol:` additive `browser.recordings.list`, `browser.recordings.get`, `browser.recordings.frame` and the schemas, for the Activity sheet (S12 builds the UI).
- `FileRecordingSink` grows an event log beside the frames: navigations, snapshot text (what the model saw, already masked), actions with the element's role and name, downloads, blocks, control changes. Credential fills record the placeholder and the ref, never a value; typed text goes through `redact`.
- Gateway handlers read `library/recordings/<task>/index.json`; frames are served by sequence number.

## PR 3: I12 dev preview

- `browser.dev_preview {url}` opens a loopback dev server in its own dev-preview session (clean partition, `devPreview` policy restricted to allowed ports) after a `new_origin` approval; `browser.console` and `browser.network` work on its tabs.
- The gate is a `DevPreviewGate` the composition builds from the owner's allowlist (`PSYCHE_DEV_PREVIEW_PORTS`); nothing on loopback opens without it. `OriginPolicy` gains `loopbackPorts` so a dev-preview session cannot wander to other local services.

## Risks

- `DriverTab` / `DriverSession` are protocol types: the partition per tab is a local extension (`DriverTabEx`) until a `protocol:` PR adds it.
- The desktop (S11) decides what `profile: clean` maps to; the request is one ephemeral partition per task (`taskId` is on `bridge.tab.open`).
