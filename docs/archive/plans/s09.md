# S09 plan: MCP host and connectors

Owner: S09. Paths: `packages/mcp-host/**`, `packages/connectors/**`. Features M1, M2, M4 (data), M5, M8, M11; later M3, M7, M10, M6.

## Goal

Psyche talks to MCP servers safely (trust tiers, `tools/list` hashing, annotation downgrade, sandboxed stdio, vault-injected secrets) and ships first-party connectors (Google, web search, fetch) behind one `Connector` interface with action matrices and a catalogue for the directory UI.

## Steps (each a small PR into `main`)

1. **mcp-host core** (`McpHost` contract). TypeScript SDK v2 `@modelcontextprotocol/client` 2.3.1 with `versionNegotiation: { mode: "auto" }`: probe `server/discover` (2026-07-28: per-request `_meta`, MRTR, no sessions), fall back to the 2025-11-25 `initialize` handshake. No Roots / Sampling / Logging / DCR capabilities are declared. Pieces:
   - `toolsListHash`: `sha256:` over canonical JSON of every model- or policy-visible field (name, title, description, input / output schema, annotations, `_meta`), sorted by name, no Unicode normalization (any byte change revokes).
   - Change detection: `refresh(serverId)` re-lists; a different hash emits `tools_changed` with a per-tool diff (added / removed / changed fields) and calls bound to the old hash fail `conflict`.
   - Side-effect class from annotations: only `bundled` servers get `readOnlyHint` → `read`, `destructiveHint` → `destructive`; `verified` / `unknown` get `write` minimum (a hint can raise severity, never lower it).
   - Tool registration into the agent-core `ToolRegistry` as `mcp__<server>__<tool>` (dots, spaces → `_`), executor passes the current hash; results `untrusted` unless `bundled`.
   - MRTR: SDK auto-fulfil through an injected `InputRequester` (elicitation form/URL); sampling and roots requests are refused.
   - Streamable HTTP + OAuth 2.1: `OAuthClientProvider` with a Client ID Metadata Document URL (CIMD) as Psyche's identity, loopback redirect `http://127.0.0.1:<port>/callback`, PKCE S256, `state` check, tokens through an injected `McpTokenStore` (vault item in production). Credential placeholders are refused in `url` / headers.
   - stdio: env values may be `{{cred:slug}}` placeholders resolved by the `CredentialBroker` at spawn (approval id from the broker); a `StdioLauncher` wraps the argv with `srt --settings <generated> --` (deny-read `~/.psyche`, per-server domain allowlist). Without a launcher, non-`bundled` stdio servers are refused (`unavailable`), never run bare.
   - MCP Apps: tools with `_meta.ui.resourceUri` → `readAppResource` returns `{ html, mimeType: "text/html;profile=mcp-app", csp, provenance: "untrusted" }` for the UI's sandboxed frame.
   - Tests: `@modelcontextprotocol/server-filesystem` over stdio on a temp dir; an HTTP echo server (SDK v2 server + `@modelcontextprotocol/node`) covering discovery, hashing / revocation, annotation downgrade, OAuth with a mock authorization server (PRM + AS metadata + CIMD + PKCE token exchange), an MRTR round trip, legacy fallback.
2. **connectors framework + search / fetch** (M4 data, M8, M11). `Connector` interface (connect / disconnect, scopes, scope mode, action matrix, tools, sync, health), `ConnectorRegistry` (catalogue, status, matrix, `connector.invalidated` events on account change / disconnect), API handlers `connectors.catalogue|list|get|connect|disconnect|status|setMatrix` as plain functions for the Gateway (S01 mounts them; schemas go through a `protocol:` PR). Search providers Brave / Exa / Tavily / SearXNG behind `SearchProvider`; `fetch(url)` → Markdown with size caps, scheme allowlist, private / link-local / loopback blocks checked on the resolved address at connect time (DNS-rebinding guard), redirect limit with re-check per hop, content-type handling, provenance `untrusted`.
3. **Google connector** (M5). Desktop OAuth client with loopback + PKCE, onboarding copy (publish to production, personal-use exemption, 7-day Testing expiry), scopes `gmail.modify` or `gmail.readonly`+`gmail.send`, `calendar`, `drive.file`; Gmail threads / read (sanitized, attachments to Library through a sink) / labels / drafts / send (write, through the broker); `history.list` polling with saved `historyId`, full resync on 404; Calendar list / events (bounded) / free-busy / create / update / delete, `syncToken` with 410 resync; Drive upload / download; tokens as vault items; account change invalidation. All tests on recorded fixtures through an injected `fetch`.

## Interfaces used

`McpHost`, `ToolRegistry` / `ToolRegistration`, `PermissionBroker`, `CredentialBroker`, `SandboxRunner` (M3), `Clock`. Fakes from `@psyche/testing`. No other package's source is imported.

## Risks

- SDK v2 behavior differs from the notes: read its `.d.ts` (done for `Client`, transports, `OAuthClientProvider`) and pin `2.3.1`.
- The `connectors` table is not in `packages/db` yet and adding a migration requires `schema.ts` (S01) to change in the same PR (parity test). M1 keeps a `ConnectorStore` interface with an in-memory implementation; the migration is requested from S01 in `docs/status/s09.md`.
- `connectors.*` write methods are not in `packages/protocol` (read-only `list` / `get` only). Handlers are written against local TypeBox schemas and proposed in a `protocol:` PR.
- `srt` is a research preview; the launcher is optional and its absence blocks non-bundled stdio servers rather than weakening isolation.
