# Plan — S06 Vault (2026-10-19)

## Goal

`packages/vault`: the Credential Broker (architecture §4.7, security §4, data model §6, ADR-006, features G1–G7, G13, G14). Done when the definition of done in `prompts/s06-vault.md` holds: create / unlock / lock, wrapped-key round trips with both wrappers against a fake helper, refused kinds, CSV imports, placeholder parsing and a redaction property test, resolve denials (origin, approval missing, approval expired), one-shot handles, the use log, rotation and the disconnect event. Plus the S23 review cases that touch credentials (design-01, 05, 13, 15, 16, 18).

## Steps

1. **`protocol:` PR** (branch `ws/s06-protocol-vault`, additive): `ResolveOptions.element` (the field descriptor the broker checks, S23 design-01) and `ResolveOptions.selector`; `CredentialUse`; `vault.status / setup / unlock / lock / add / update / delete / import / uses` methods; events `vault.locked`, `vault.unlocked`, `credential.updated`; `ConnectorCredentialStore` (`rotate`, `revoke`, `onRevoked`) for connectors. `FakeCredentialBroker` gains the element check and the store. Conformance cases for the element check.
2. **Storage.** SQLCipher 4 through `better-sqlite3-multiple-ciphers` (sync API like `@psyche/db`; raw 32-byte DEK via `PRAGMA key = "x'…'"`, so PBKDF2 is skipped). `vault/vault.db` with `items` and `header`; `secure_delete=ON`; values overwritten before delete.
3. **Key slots.** `KeyWrapper` with `KeychainWrapper` (mac helper `keychain.set` / `vault.unlock` / `keychain.delete`, access control `[biometryCurrentSet, or, devicePasscode]`), `SafeStorageWrapper` (adapter over Electron `safeStorage` or libsecret; refuses `basic_text`), `KeyFileWrapper` (server mode, `PSYCHE_VAULT_KEY_FILE`, 0600 only). Recovery slot `vault/recovery.slot`: 32 random bytes shown once as grouped base32, DEK wrapped with AES-256-GCM under an Argon2id-derived key (security §4.2; the prompt's "BIP39-style words" loses to the doc).
4. **Items.** Kinds `login | api_key | oauth_token | ssh_key | note | payment_link`; bindings; refusal of card numbers (Luhn), CVVs, IBANs, SSNs and other government ids, with an explanation pointing to Stripe Link; CSV import (1Password, Bitwarden, Chrome); metadata mirror (`credential_meta`, `credential_uses`) in the main DB through a migration in `packages/db/migrations/`.
5. **Placeholders and redaction.** Resolve-time grammar check; `.totp` resolves to the current RFC 6238 code, never the seed. `redact()` over every registered value (all items while unlocked, every resolved value for the process lifetime): raw, URL / form encodings, base64 / base64url at all three alignments, hex, base32, reversed, ROT13, and a fuzzy pass over NFKC-normalized, case-folded text with whitespace / separators / format characters removed (S23 design-15, 18). Prefix / suffix match for long keys (design-16). Property tests with fast-check.
6. **Resolve.** Grammar → item → origin binding (exact origin, opaque origins refused; design-13) → field class vs element (design-01) → approval through `PermissionBroker.verifyBinding` with the `credential_fill` binding hash recomputed here (item id, origin, field selector, field: security §3.5) → `ResolvedSecret` → `credential_uses` row + audit entry. Denials are audited too.
7. **Fill helpers.** Browser (CDP `Page.getFrameTree` origin check, focused-element descriptor from an isolated world, `Input.insertText`, clear on failure, `secureField`); HTTP header injector (HTTPS only, `redirect: "manual"`, credentials only on same-origin hops, errors rebuilt from an allowlisted shape; design-16); sandbox env injector (`PSYCHE_SECRET_<NAME>`, explicit env only; design-17).
8. **Approvals.** `credentialFillApproval()` builds the `ApprovalRequestInput` (kind `credential_fill`, scopes `once` + opt-in `site`, item / site / task / agent in details, grant key includes the field class).
9. **OAuth.** `rotate()` replaces tokens atomically; `revoke()` deletes, calls the connector's revoke hook and emits `credential.updated {change: "revoked"}`.
10. **API handlers** for the Gateway (`vault.*`) and events; README with the threat-model checklist; `docs/status/s06.md`.

## Interfaces used

`CredentialBroker`, `ResolvedSecret`, `PermissionBroker.verifyBinding`, `NodeClient.invoke` (helper), `AuditLog.append`, `Clock`. Fakes: `FakePermissionBroker`, `FakeNodeClient`, `FakeAuditLog`, `FakeClock`, secret-leak checker.

## Risks

- The helper's `keychain.*` wire shape is not specified anywhere; this package defines it and asks S14 to implement it (status file).
- 04 §4.2 and 05 §3.5 disagree on credential-fill binding fields (S23 design-13). I follow 05 §3.5 and record the objection.
- 04 §6 says `userPresence`/biometry; 05 §4.2 and the prompt say `[.biometryCurrentSet, .or, .devicePasscode]`. I follow 05.
- Key slots cannot live in a `header` table inside the encrypted database (05 §4.1), because the header must be readable before the key is known. Slots live in `vault/slots.json` and `vault/recovery.slot`; the in-database `header` keeps the version and slot ids.
- The PermissionBroker's real `site`-grant verification belongs to S05. A `site` grant is honoured only through what `verifyBinding` returns.
