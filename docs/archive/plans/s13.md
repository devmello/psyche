# S13 plan — viewers, editor, documents

Owner: S13. Package: `packages/viewers` (`@psyche/viewers`). Features: P1, P3, P4, P5, P6, P9 (M2: P2, P8).

## Goal

One package that the shells (S11) and screens (S12) use to show and edit anything in the Files pane, the
Library and inline chat cards, plus the text extraction the agent's file tools (P9) call. Everything
heavy is a pure TypeScript core (testable in Node, usable by the Gateway) with a thin React layer.

## Layout

```
src/core/       framework-free logic, safe to import in the Gateway (no DOM)
  registry      ViewerRegistry impl + default ViewerSpecs (protocol contract)
  detect        MIME / extension / magic-byte sniffing
  pdf           PDF.js 6 open, outline, search, AcroForm fields, XFA detection, text
  sheet         SheetJS CE parse, fast CSV/TSV parser, filters, column stats
  docx          mammoth raw text / HTML fallback
  email         .eml parse, DOMPurify sanitizing, remote-image blocking
  artifact      srcdoc builder (CSP + bridge), message validation, host page, update-by-name
  markdown      frontmatter split, budgets, DocumentSession (autosave + etag conflicts)
  convert       ConversionService interface + Gotenberg / LibreOffice / qlmanage adapters
  extract       extractText(item) bounded, paged, with page / sheet / cell refs
src/react/      viewer components + the props contract and component map
```

## Decisions

- **Markdown editor: CodeMirror 6, not MDXEditor.** docs/06 §3.8 makes raw Markdown canonical and says
  Rich "never rewrites untouched lines". MDXEditor's rich mode re-serialises the whole document through
  mdast (list markers, emphasis, spacing normalised), so it rewrites lines the user never touched. CM6
  live-preview decorations over the raw text cannot, by construction. Diff uses `@codemirror/merge`.
  Memo: `packages/viewers/docs/editor-decision.md`.
- **Artifact frame**: `sandbox="allow-scripts"` (never `allow-same-origin`), CSP `<meta>` first in
  `<head>`, `connect-src 'none'`, home-grown ResizeObserver/postMessage bridge. Two modes: inline srcdoc
  (opaque `null` origin) and hosted (the Gateway serves `artifactHostPage()` on a distinct port; the host
  page owns the inner srcdoc frame).
- **Spreadsheets**: SheetJS CE 0.20.3 from `cdn.sheetjs.com` tarball (never npm `xlsx`); CSV/TSV use our
  own streaming-free parser (faster than SheetJS for the 50k-row budget).
- **PPTX**: no JS renderer (ADR-013); `ConversionService` converts to PDF (Gotenberg / LibreOffice in
  the sandbox) or thumbnails (`qlmanage` on the Mac node); otherwise a placeholder.

## Interfaces

- Implements `ViewerRegistry` / `ViewerSpec` from `@psyche/protocol` (contract tests run against both the
  real registry and `FakeViewerRegistry`).
- Exposes `ViewerProps` (item, source loader, page state, selection events, `onOpenInPane`,
  `onSendToChat`) for S11/S12, and `extractText()` for the Gateway's file tools.
- Consumes nothing from other sessions at runtime; OCR, conversion, saving and fetching are injected.

## Steps

1. Registry, detection, plan/status docs.
2. PDF core + fixtures (100-page, AcroForm, XFA) + viewer.
3. Sheets core (SheetJS, CSV) + grid viewer, perf budget.
4. DOCX/PPTX/convert, image, JSON, code, text viewers.
5. Email sanitizing + viewer; artifact frame + browser sandbox tests.
6. Markdown editor (rich/source/diff, autosave, conflicts, frontmatter) + round-trip tests.
7. extractText for every format.
8. README, status, independent review, PR.

## Risks

- PDF.js / CodeMirror in jsdom: geometry APIs are missing, so component tests stub layout and the real
  browser checks run in Chrome via `playwright-core` (skipped when no Chrome is installed).
- Sandbox guarantees need a real browser; structural tests always run, Chrome tests run where Chrome exists.
- The artifacts origin is served by the Gateway (S01); S13 ships the host page and headers only.

## M2 (branch `ws/s13-viewers-m2`)

1. **P2 building blocks** (`core/forms.ts`): detect fields with pdf.js (reusing `PdfHandle.fields()`
   and XFA detection), fill with `@cantoo/pdf-lib`, bind the reviewed copy by sha256, flatten on
   send, value-free `ReceiptInput`. Scanned forms: `OcrProvider` line boxes → overlay fields drawn
   as page text. Orchestration (`ask_user`, reply draft, approval, send) stays in S04/S09.
2. **P8 generators** (`core/generate/`): one spec model (`DocSpec`, `WorkbookSpec`, `DeckSpec`,
   `ChartSpec`) and `generateFile`. Markdown and HTML are hand-written with escaping; PDF on pdf-lib
   (standard fonts; Chromium print of `docToHtml` for full Unicode); DOCX on `docx` 9.8.1 (pinned
   below 9.12.0, which was 3 days old); XLSX on SheetJS CE; PPTX on pptxgenjs 4.0.1; charts as
   static SVG; itinerary/dashboard templates through the script-free artifact srcdoc.
3. **Univer editing** (branch `ws/s13-viewers-m2b`): Univer 1.0.3 (Apache-2.0, pinned below
   1.1.0, which was 2 days old) as an Edit mode of `SheetViewer`. Univer OSS has no xlsx I/O, so
   `core/sheet-edit.ts` converts SheetJS ⇄ `IWorkbookData` both ways; explicit Save through
   `onSave`. Lazily loaded; tested with a fake runtime in jsdom and the real one in Chrome.
4. **Sandpack React artifacts**: `@codesandbox/sandpack-client` 2.19.8 in the app; our own
   Sandpack-protocol bundler (React 19 CJS + `@babel/standalone` 8.0.6) served by the Gateway from
   `@psyche/viewers/bundler`, because CodeSandbox's bundler fetches dependencies from its CDN.
   The frame keeps `sandbox="allow-scripts"`; the client's target origin becomes `"*"` since an
   opaque frame never matches the bundler URL. Chrome test: a hostile artifact reaches neither the
   parent nor any host.

Risks: Univer is large (≈ 1.8 MB gzip), so it must stay out of the initial bundle; the Sandpack
client's private `iframeProtocol.origin` is patched (pinned version, covered by the Chrome test).
The standard fonts cover WinAnsi only (values outside it are refused when filling and
replaced when generating); DOCX cannot embed SVG charts without a PNG fallback, so charts there
are data tables.
