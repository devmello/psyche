# S22 plan: CLI, deploy, release

Owner: S22. Paths: `apps/cli`, `deploy/`, `.github/workflows/release.yml`, `docs/status/s22.md`. Features: A7 (LaunchAgent), A10 (CLI), A11 (Linux packaging), U2 (export), U4 (backups). Security: 05 §10 (control plane), §14 (data handling).

## Goal

`psyche` is a thin client of the Gateway WS API. It never opens `state/psyche.sqlite`. The files it does touch directly: its own device identity, `config.json` (doctor/audit read it; `config set gateway.*` writes it), log files (`logs`), the supervisor files (plist, unit), and whole directories for `backup` while the Gateway is stopped.

## Steps

1. **CLI core** (`apps/cli/src`): command table → argument parsing (`node:util` `parseArgs`), `--json` on every command, exit codes (0 ok, 1 problems found / command failed, 2 usage). Shell completions are generated from the same table (`psyche completion bash|zsh|fish`).
2. **Gateway client**: global `WebSocket` (Node 24), `connect` → challenge → `connect.verify` with the CLI's own Ed25519 key (`$PSYCHE_HOME/cli/device.json`, 0600, `deviceFamily: "cli"`). The CLI never presents the handshake secret: it pairs like any device and the owner approves it with `psyched devices approve <CODE>` (first admin) or from an admin device. Params are validated against the protocol registry before sending; side-effecting methods get an idempotency key.
3. **Commands**: `onboard`, `start|stop|restart|status`, `doctor`, `security audit`, `pairing list|approve|deny`, `devices list|revoke`, `skills list|install|verify`, `automations list|run|pause`, `vault list|add|import|lock|unlock`, `backup create|restore|verify`, `export`, `logs`, `config get|set`, `version`, `completion`.
4. **Supervisor**: macOS LaunchAgent (`launchctl bootstrap|bootout|kickstart|print gui/<uid>`), Linux systemd user unit (`systemctl --user`), Compose hint otherwise. The plist and unit are rendered from the templates in `deploy/`.
5. **doctor / security audit**: gather a snapshot (HTTP health, `/version`, handshake, `settings.get`, `channels.list`, `grants.list`, `devices.list`, `nodes.list`, `sandbox.status`, `vault.status`, local file modes and disk), then run pure rule functions over it. Tests cover each rule.
6. **Backup**: tar of `state/ workspace/ vault/ library/` (channel sessions live in `state/channels/`) plus `manifest.json` with SHA-256 per file, encrypted with age (`age-encryption`, passphrase or X25519 recipient). Refuses while the Gateway is running unless `--stop` (stop, snapshot, restart), because copying a live WAL database is not a consistent snapshot. `restore` refuses a non-empty target unless `--force`; `verify` decrypts and checks every hash.
7. **Deploy**: Dockerfile (multi-stage, workspace sources with production dependencies run by Node 24 type stripping, Node 24 slim, uid 10001, healthcheck on `/healthz`), Compose (host networking so the Gateway keeps its loopback bind; named volume; profiles `tailscale`, `cloudflare`, `browser`; sandbox socket mount commented out with the risk), launchd plist, systemd unit, Tailscale and Cloudflare READMEs, `deploy/backup/*.sh`.
8. **Release workflow**: on tag `v*`: multi-arch image (buildx, QEMU) pushed to GHCR and signed keyless with cosign; CLI binaries for darwin arm64/x64 and linux x64/arm64 with `bun build --compile`; the desktop package (unsigned) when `apps/desktop` has a `make` script; release notes from changesets. Signing and notarization steps documented with secret names, skipped when the secrets are absent.
9. **CI**: a `deploy` job (compose smoke test: build, `docker compose up --wait`, `psyche status --json` in the container and from the host, plist/unit validation). It lives in `release.yml`'s sibling `deploy-smoke` job triggered on PRs touching `deploy/**` or `apps/cli/**`.

## Interfaces used

Protocol methods only (`packages/protocol/src/methods`). Methods the Gateway does not have yet (`skills.*`) are called by name; `unknown_method` / `not_implemented` is reported as "not available on this Gateway" with exit code 1 and `{"available": false}` in JSON.

## Risks

- The Gateway core (S01, PR #31) merged into its stacked base branch, not into `main`; `main` runs the bootstrap Gateway. The CLI is built and tested against a mock Gateway (`@psyche/web/testing`), and `doctor` treats `not_implemented` as "unknown", not a failure.
- Security §10 "Docker defaults" asks for `PSYCHE_BIND=container` + `PSYCHE_GATEWAY_TOKEN_FILE`; the Gateway does not implement either. Compose uses host networking instead so the loopback bind holds. Objection recorded in `docs/status/s22.md`.
- `skills.*` has no protocol methods (S16). Requested in the status file.
