# S19 plan: psyche-node

**Goal.** `apps/node` ships `psyche-node`: a headless process that pairs with a Gateway as a `node` device, advertises the capabilities this machine really has, and serves `node.invoke` with streamed `node.event`s and a final `node.result` carrying a receipt (architecture §7, §10; security §10, §13; features L3, N13, K6/K7).

## Steps

1. **Wire layer.** `FramePeer` over a `FrameChannel` (one JSON frame per WS message or NDJSON line), validated with `parseFrame` / `validateParams` from `@psyche/protocol`. Correlates `res` frames, answers Gateway `req`s.
2. **Transports.** `ws` (loopback, tailnet, SSH tunnel; no `Origin` header), `unix` (the Gateway's `run/node.sock`), `vsock` (VM guest). Node has no `AF_VSOCK`, so vsock goes through a bridge process speaking NDJSON on stdio (`socat VSOCK-CONNECT:…` on Linux, the helper's bridge on macOS). Detection: `/dev/vsock` on Linux, `sysctl kern.hv_vmm_present` on macOS; when a vsock endpoint is configured and the machine is a guest, vsock is preferred.
3. **Identity and pairing.** Ed25519 key and device id in `<home>/identity.json` (0600). `connect {role: node, deviceFamily, capabilities}` → sign `connectSigningPayload` → `paired` (keep going), `pending` (log the code, wait for the Gateway to close the connection on approval, reconnect), `denied` (stop on `device revoked` / key or role mismatch, otherwise back off). Scopes come from the owner, never from the node.
4. **Reconnection.** Exponential backoff with full jitter (0.5 s → 30 s), reset after a stable connection. In-flight invocations are cancelled when the connection drops (the Gateway already failed them).
5. **Clock.** `serverTime` from `paired` gives the skew; receipts and deadlines use the skew-corrected clock, so approvals minted on the Gateway are not judged with a wrong local clock.
6. **Capabilities.** Each provider `detect()`s availability and returns its manifest entries plus handlers:
   - `health` (always).
   - `exec` through `@psyche/sandbox` when a backend is present; `exec.host` only when this node's config enables it *and* the invocation carries an `approvalId` (K7: always asks, Gateway binds approval to argv + cwd).
   - `fs.list|stat|read|write|mkdir|remove` over configured roots, confined by `realpath` (no `..`, no symlink escape), read-only roots respected.
   - `browser.*` via `@psyche/browser`'s Playwright driver, persistent profile under `<home>/browser/profiles`.
   - `computer.*`, `apps.*`, `notify.*`, `speech.*`, `keychain.*` proxied to a co-located Mac helper when its socket answers; the node re-advertises exactly what the helper declares, never `vault.*` / `permissions.*`.
7. **Install.** `scripts/install-macos.sh` (LaunchAgent), `scripts/install-linux.sh` (systemd user unit), `scripts/guest-bootstrap.sh` (what the VM manager runs inside the guest over vsock/VirtioFS).
8. **Tests** with a fake Gateway (real `connect` handshake, signature check): pairing (paired / pending / denied), capability negotiation, invoke streaming, approval-id passthrough, exec receipts, fs root confinement, reconnection. Manual vsock test plan in `apps/node/docs/manual-test-plan.md`.

## Interfaces used

`@psyche/protocol` (frames, `connect*`, `node.*`, `NodeCapability`, `Receipt`, `SandboxRunner`, `BrowserDriver`), `@psyche/sandbox`, `@psyche/browser`. No protocol change planned; additive requests go to `docs/status/s19.md`.

## Risks

- vsock needs a bridge process (no native support in Node); the host side forwarder belongs to S14.
- The Gateway's pending connection is closed on approval, so the node must reconnect promptly; covered by the reconnection loop.
- Helper protocol drift: proxy only what the helper itself advertises.
