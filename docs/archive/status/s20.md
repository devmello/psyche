## Open questions for S07 (memory)

1. **Bootstrap writes.** `BOOTSTRAP.md` asks the agent to write `IDENTITY.md`, `USER.md` and possibly `SOUL.md` in the first conversation. Each is a `memory_protected_write`. Can S07 (with S05) treat the onboarding answers as owner-provenance and let one approval cover the first-run batch, or should onboarding (S11) write `IDENTITY.md` directly so the ritual only needs one card for `USER.md`? The template supports both ("one approval covers this first-run batch if Psyche offers it").
2. **Placeholder substitution.** `IDENTITY.md` uses `{{name}}`, `{{creature}}`, `{{vibe}}`, `{{tagline}}`, `{{emoji}}`, `{{avatar}}`, `{{voice}}`, `{{owner}}`. Please substitute at copy time with the defaults in `templates/README.md` so no raw token reaches the prompt. They are not `{{cred:…}}` placeholders; make sure the credential placeholder scanner doesn't flag them (it matches only `{{cred:`).
3. **`AGENTS.md` protection.** `PROTECTED_MEMORY_FILES` on `main` (`packages/protocol/src/contracts/MemoryStore.ts`) lists SOUL, IDENTITY, USER, MEMORY, but `docs/05` §8 also names `AGENTS.md` as a protected path. The templates tell the agent `AGENTS.md` changes need approval. Please add it (or tell S20 to change the wording).
4. **Tone presets.** `templates/personas/*.md` replace `SOUL.md` wholesale. Should "apply preset" be a whole-file write (simplest, current assumption) or a section replace of `## Personality` / `## How I write` so owner edits to Core truths survive? `BOOTSTRAP.md` currently says "replace the Personality section".
5. **HTML comments.** Templates use short `<!-- -->` guidance for the owner. They count against budgets. Strip them at injection time, or keep them? Either works for S20; stripping saves ~1,500 characters across the set.
6. **Daily-note tag format.** Templates and the `memory-hygiene` skill use `- HH:MM [owner|agent|untrusted:<kind>:<source>] text` per `docs/04` §7.1. Please confirm `appendDailyNote` renders exactly that.
7. **Persona preset choice from onboarding.** If S11 adds the "Starting personality" picker from `docs/copy/onboarding.md`, the chosen preset should reach the bootstrap block so the agent doesn't ask again.

## Open questions for S16 (skills loader)

1. **Gating keys.** Bundled skills use `requires.tools` (all must be registered and enabled) and `requires.anyTools` (at least one), with `*` globs for a family. The Agent Skills / OpenClaw convention only has bins/env/os. Adopt these keys, or map them to something you prefer? Without tool gating, `shopping-compare` would show on a Gateway with no browser.
2. **Sibling files.** Each skill folder has `acceptance.md`. Please make sure the loader never injects or indexes non-`SKILL.md` files (and that `skills_read` returns only `SKILL.md`).
3. **`metadata.psyche.*`** (priority, features, approvals) is informational. Ignore it in the loader, or surface `approvals` in Settings → Skills?
4. **Description budget.** Descriptions are 190–270 characters (about 3,000 for twelve). If your index budget is tighter, tell S20 the target and the descriptions will be cut.
5. **Name collisions.** If a workspace skill shadows a bundled one (same `name`), it wins per precedence. Should Settings show "overrides bundled"?
6. **Slash commands.** Eleven skills are `user-invocable: true`; `browsing` is model-only. Confirm the composer lists them as `/name`.
