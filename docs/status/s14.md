# S14 status: Mac helper (`apps/mac-helper`)

Updated 2026-10-19. Plan: [docs/plans/s14.md](../plans/s14.md). Package docs: [apps/mac-helper/README.md](../../apps/mac-helper/README.md). Manual test plan: [apps/mac-helper/docs/manual-test-plan.md](../../apps/mac-helper/docs/manual-test-plan.md).

## What works (M1)

- **Node runtime (A9).** Persistent device identity (data-protection keychain, 0600 file fallback for builds without a provisioning profile, one-way migration file → keychain). Long-running connection with reconnect backoff; `connect` declares the capability manifest; `node.invoke` → `res {accepted}` → `node.event`* → `node.result` with receipts (including `failed` receipts for refused side effects); errors carry protocol codes plus `details.reason`. `psyche-helper --manifest` prints it.
- **Permissions (A9).** `permissions.status/request/open_settings` from preflight APIs only, explanations, `x-apple.systempreferences:` links, security §12 order; Screen Recording only with `purpose: vision_fallback`; Full Disk Access opens Settings.
- **Computer use (J1, J2, J5).** Spike 04's walker as a generic, unit-tested builder (visit/emit budgets, clipping, pruning, collapsed labels, detached focus, Electron wake-up); helper-held identity refs; `expect` checks; exact-match selectors; AX-first actions with read-back and HID CGEvent fallback; secure fields refused at dispatch; risky labels and chords need approval; tiers with fixed caps, `ask` + 30-minute session allowances, one session lock, Esc stop through an active event tap that also ends the session.
- **Screenshots (J3).** ScreenCaptureKit with Psyche, terminals/IDEs, password managers, finance apps and Off-tier apps excluded, 1372×887 downscale, suppressed while a secure field is focused; `SCContentSharingPicker` capture.
- **Apple Events / Shortcuts (J4).** In-process AppleScript/JXA with per-target Automation preflight; Shortcuts via `/usr/bin/shortcuts` spawned with responsibility disclaimed.
- **Keychain (G1).** S06's contract: `keychain.set`, `vault.unlock`, `keychain.delete`, plus `keychain.status`; `[.biometryCurrentSet, .or, .devicePasscode]`, `WhenPasscodeSetThisDeviceOnly`, `LAContext` prompts, OSStatus mapping.
- **Notifications (O10).** `notify.show` accepts S15's `NotifyShowParams`; categories per kind, text replies, interruption levels, quiet hours, provisional authorization, Touch ID before forwarding approvals that need it; responses on `notify.subscribe`.
- **Speech (Q1).** SpeechAnalyzer / SpeechTranscriber / DictationTranscriber on 26+, on-device SFSpeechRecognizer otherwise; microphone or pushed PCM; `AVSpeechSynthesizer.write` PCM; Personal Voice opt-in flagged non-commercial.
- **Bundle.** `scripts/build-app.sh` (hardened runtime, entitlements, optional profile → keychain group and time-sensitive), `install-agent.sh` (LaunchAgent, quarantine cleared), `tcc-reset.sh`.
- Tests: 198 Swift Testing cases (160 in `PsycheHelperCoreTests`, 38 in `PsycheHelperSystemTests`); none need TCC grants.
- An independent review of the diff found 16 issues, all fixed: input only goes to a verified frontmost app that owns keyboard focus (checked per chunk), synthetic clicks are hit-tested for occlusion/secure fields/risky labels, menus and non-press actions need Read and interact (so no Terminal Edit>Paste in the click tier), `apps.open` stays inside Applications folders and refuses executable documents, scripts may not drive System Events or capped apps, Esc uses per-invocation tokens, `session` is required, numeric params are clamped, writes after close cannot hit a reused fd, the picker callbacks hop to main, the Esc tap setup is locked.

## Packaging (bundled helper in Psyche.app): layout and launch contract

This is the contract the desktop bundle codes against. Route chosen: **`Contents/Resources`, launched through LaunchServices**. There is no `SMAppService` login item: it needs both apps signed by one team, so ad-hoc builds cannot use it, and Electron would need a native module.

**Build.** `deploy/macos/build-helper.sh` builds `apps/mac-helper/dist/PsycheHelper.app`:

```
PsycheHelper.app/Contents/
  Info.plist                 CFBundleIdentifier com.psyche.helper, CFBundleExecutable psyche-helper,
                             LSUIElement true, CFBundleShortVersionString = package version,
                             CFBundleVersion = numeric part of it (monotonic across releases)
  MacOS/psyche-helper
  embedded.provisionprofile  only when PSYCHE_HELPER_PROFILE is set
  _CodeSignature/
```

- With `PSYCHE_SIGN_IDENTITY` (Developer ID), the script signs with the hardened runtime, a secure timestamp and `apps/mac-helper/Support/PsycheHelper.entitlements`.
- Without it, the script signs ad-hoc with the identifier `com.psyche.helper`.
- Version: `PSYCHE_VERSION`, else `apps/desktop/package.json`.

**Desktop packaging (S11/S22).**
- forge `packagerConfig.extraResource: ["../mac-helper/dist/PsycheHelper.app"]`, which puts it at `Psyche.app/Contents/Resources/PsycheHelper.app`.
- Run `build-helper.sh` before `electron-forge package`, with the same `PSYCHE_SIGN_IDENTITY`.
- osx-sign must not re-sign the helper with Electron's entitlements, which would drop Apple Events, audio input, Virtualization and the rest. Use `osxSign.ignore: (p) => p.includes("/PsycheHelper.app/")`. The outer signature then seals the already-signed helper.
- Notarization accepts this because the helper is Developer ID + hardened runtime + timestamp.

**Launch.**
- The packaged desktop on macOS runs this once the Gateway is listening (after `run/handshake.secret` is written):

  ```
  /usr/bin/open -g -j [--env PSYCHE_HOME=<home>] "<process.resourcesPath>/PsycheHelper.app"
  ```

  Pass `--env` only when the home is not `~/.psyche`.
- Never `spawn` the binary. A child of Electron is attributed to Psyche.app by TCC, so grants and prompts would name the wrong app.
- `open` is idempotent. Running it again, for example when `node.updated` shows the helper offline, is safe.
- Unpackaged dev builds do not launch it. Developers use `apps/mac-helper/scripts/build-app.sh --install` or the LaunchAgent.

**Lifetime.**
- One helper per `$PSYCHE_HOME`. It holds `$PSYCHE_HOME/run/helper.lock` (flock), and a second copy exits 0 at once.
- It keeps running when the desktop quits and reconnects to the socket with backoff (≤ 30 s).
- At login it comes back with the desktop (the desktop's own login item launches it). The LaunchAgent template stays for server-node mode.

**Pairing.** No terminal or card is needed. The helper reads `$PSYCHE_HOME/run/handshake.secret` on every connect attempt. The Gateway auto-pairs `role: node, deviceFamily: mac-helper` over the local socket with the secret (`autoPairScopes`, scope `node`).

**First run requests nothing.** At start the helper only installs its notification delegate and categories. Every macOS prompt comes from `permissions.request`, `notify.request_authorization`, or a capability the owner invoked.

**Onboarding / doctor.** Call `node.invoke permissions.status` (read, no prompts). It returns:
- `permissions[]`: `{permission, status, title, explanation, whenRequested, settingsURL, requestStyle}` for accessibility, screen recording, automation (per target), full disk access, calendars, reminders, contacts, microphone, speech recognition, notifications and input monitoring;
- `next` and `bundled`;
- a `bundle` object `{path, version, build, signing: developer_id|development|adhoc|unsigned, teamId?, insideApp}`, so doctor can warn when an ad-hoc helper will lose its grants on upgrade.

**Upgrade.**
- When the `psyche-helper` executable inside its bundle is replaced or removed (Psyche.app updated or trashed), the running helper exits within 30 s. The desktop's next `open` starts the new one.
- TCC grants survive only if the designated requirement is unchanged. Developer ID: identifier + team, so grants are kept. Ad-hoc: the cdhash, so every build is new to TCC. The old toggles stay visible in System Settings but no longer apply; reset with `tccutil reset All com.psyche.helper` and grant again.

**Requests for packaging.**
- **S11 / desktop bundle:**
  - Copy `apps/mac-helper/dist/PsycheHelper.app` with `extraResource`.
  - Set `osxSign.ignore` for `/PsycheHelper.app/`.
  - Launch with `open -g -j` after the Gateway is listening. Running `open` again is safe.
- **S22 / doctor and release:**
  - Doctor's permissions line: show `permissions.status.permissions[]` and `next`. Warn when `bundle.signing` is `adhoc` (grants are lost on upgrade) or `unsigned`, or when `bundle.insideApp` is false for a DMG install.
  - Release CI: run `deploy/macos/build-helper.sh --arch <arch>` with the release `PSYCHE_SIGN_IDENTITY` before `electron-forge package`.

## VM snapshots and resets (L6, helper side)

- **Capabilities:** `vm.snapshot` (write, streaming `vm.snapshot` events), and `vm.restore`, `vm.reset`, `vm.snapshot_delete` (destructive; restore and reset stream `vm.reset` events). Shapes are in protocol #452.
- **What a snapshot holds:** APFS clones (`clonefile`, instant and copy-on-write) of the disk, `AuxiliaryStorage`, `state.json` and any saved machine state, in `$PSYCHE_HOME/vm/<name>/snapshots/<id>/`. The guest's identity (HardwareModel, MachineIdentifier, MAC) is never copied, so a restore is the same Mac.
- **Guest state required:** stopped, saved or installed. Running guests answer `vm_running`.
- **Restore:** clones beside the current files, then swaps them in. A failed clone changes nothing. The guest comes back `stopped`, `saved` when the snapshot had a machine state, or `installed` if it was never provisioned. `durationMs` is in the result; on APFS it is milliseconds, well under the 30 s target.
- **Base and retention:** at most one `base`, and a new base demotes the old one to manual. At most 10 manual snapshots (`snapshot_limit`); `task` snapshots are pruned to the newest 3.
- **Errors:** `vm.reset` without a base answers `no_base_snapshot`. A non-APFS home answers `clone_unsupported`.
- **Not done:** DiskImageKit overlays (`method: overlay`) are reserved and unimplemented. Clones already meet the target.

### Requests to S01 for L6 (Gateway half)

- **Tools:** expose `vm.snapshot`, `vm.restore`, `vm.reset` and `vm.snapshot_delete` through `nodes.invoke` / compose like the other `vm.*` capabilities. Restore, reset and delete are `destructive` and ask when the agent invokes them; owner actions from Settings → Devices go through as usual.
- **`vm.resetPerTask` (default false):** before a Task that runs in the sandbox, run `vm.stop` if the guest is running, then `vm.reset`, then `vm.start`. Optionally take a `task` snapshot with `taskId` after the Task. If there is no base (`no_base_snapshot`), the Task stays in `awaiting_input` with a "Take a base snapshot" prompt rather than running on a dirty Mac.
- **Broadcasts:** re-broadcast `vm.updated`. The guest now carries `snapshots` and `baseSnapshot`.
- **S11:** a snapshots list on the Devices pane (label, kind, date, size), "Make this the fresh Mac", Reset, Delete. One guest per user is already enforced by `vm.create` (`guest_exists`).

## Prebuilt guest images (L7, helper side)

- **Format:** `<id>/` holds `manifest.json` (the protocol's `VmImageManifest`, with the SHA-256 of every file), `Disk.*`, `AuxiliaryStorage`, `HardwareModel` and `bootstrap.json` (guest admin user and password). It never contains the MachineIdentifier, MAC, SSH keys, shares or saved state. A `.aar` (Apple Archive) is accepted too.
- **Build:** `deploy/macos/build-guest-image.sh` runs `psyche-helper guest-image build` in a throwaway `PSYCHE_HOME`: create from IPSW → provisioning boot → `install_psyche` (retried until SSH answers) → stop → offline TCC grant → `vm.export_image`. The build refuses hosts with less than 24 GB unless forced, and was not run here (16 GB host, no guest boots). `guest-image verify` checks an image.
- **Import:** `vm.create {image, imageSha256}` verifies before copying. It requires exactly the expected regular files, no symlinks, and every size and SHA-256 matching; with `imageSha256`, the manifest itself must also match.
- **New identity:** the imported guest gets a new MachineIdentifier (`VMBackend.prepareImported`, which also refuses unsupported hardware models) and a new MAC. Its state is `stopped`, provisioned, with the Psyche and permission flags from the manifest, plus `image` and `passwordRotationPending`.
- **First start:** rotates the bootstrap password over SSH (password auth with the old one): `dscl -passwd`, the login keychain, `sysadminctl -autologin`, and replaces `authorized_keys` with this helper's key. Passwords are alphanumeric only (checked) before they reach a shell. A failure leaves the guest running and the rotation pending.
- **Tests:** the build pipeline, export and import against the fake backend and shell. Tamper cases: a flipped byte, extra or missing files, a symlink, a wrong published checksum, a newer format, a hostile password.
- **Not done:** OCI / registry pull. Images are files.

## Doc objections (proceeding with the docs unless noted)

1. **Depth ≤ 8** (S14 prompt, research default) is too shallow: Electron web content and Reminders rows sit deeper (spike 04). The helper bounds walks by visit/emit budgets (6000/400) with depth 40 only as a safety cap. The prompt should say so.
2. **Security §4.2 / research KQ7: "constraint flags combined without `.or` return `errSecParam`"** is not what macOS 27 does: `[.biometryCurrentSet, .devicePasscode]` creates fine and means AND (both required). Only `.or` together with `.and` fails with `-50`. The helper always passes `.or`; the doc sentence should be corrected.
3. **Data-protection keychain probing:** without the entitlement, `SecItemCopyMatching` for a missing item returns `-25300`, not `-34018`; only add/delete reveal `-34018`. `keychain.status` probes with a delete.
4. **Architecture §6 table** names `apps.shortcut`; the helper uses `apps.shortcut_run` (the S14 prompt's name) plus `apps.shortcuts_list`.

## M3 threat-model fixes (helper side)

- #269 (closed here): Notification Center, the user-notification and security agents, LocalAuthentication's UI agent, loginwindow and System Settings are fixed-cap Off in the helper and in the broker's `LOCKED_OFF_APPS`. The two lists are kept in parity by tests.
- #266 (helper side): a click or press on a menu-like role (`AXMenuItem`, `AXMenuBarItem`, `AXMenuButton`, `AXPopUpButton`, …) runs as intent `menu`, which needs interact. This applies to refs and to x/y points (the role is hit-tested).
- #267 (helper side): approvals are bound. The helper honours `approvalId` only together with `params.approval {app, tier}`, and only when `app` is the app the action reaches. The 30-minute allowance grants exactly the approved tier. x/y calls must name `app`, and the point must land in it (`app_mismatch`).

- #270 (helper side): in messaging and mail apps (`SendKeys.apps`: Messages, Mail, Slack, WhatsApp, Telegram, Discord, Signal, Teams, Outlook, …), `computer.key` with Return, Enter or cmd+shift+D (`send_key`), and `computer.type` with a line break (`send_text`), need their own approval. They answer `approval_required` with `details.sideEffect: "destructive"`.
- #271 (helper side): AX labels, values, window titles and app names escape every line terminator (\n, \r, \r\n, U+2028, U+2029, NEL, VT, FF) as `⏎`. Other control and format characters become spaces. Identifiers containing them are dropped. A rendered snapshot is always one line per element.

- #268 (closed here): `apps.applescript` / `apps.jxa` run out of process (`/usr/bin/osascript`, responsibility disclaimed, minimal environment, source on stdin, `timeoutSeconds` 1–300, default 60), so a script never holds the helper's Accessibility or Full Disk Access. `ScriptGuard` (now in Core) matches tokens on source with whitespace, line continuations and invisible characters removed, and bans shell, `run script`, ASObjC (`use framework`, `current application`), raw `«event»` codes, JXA's ObjC bridge and `$`, `eval`, `Library`, computed members, arrow functions, template strings, Standard Additions file I/O and the clipboard. `target` is required. Finder, System Events, Terminal, iTerm2, Script Editor, Automator, Shortcuts and apps whose fixed cap is below interact are refused. Every app the script addresses (`application "…"`, `app id "…"`, `Application('…')`) must resolve to the target, and any non-literal app reference is refused (`script_dynamic_target`). In the broker `apple_script` is device-only and needs authentication.

- #272 (helper side): pause-when-unwatched for computer use. Sensitive apps are terminals and IDEs, messaging and mail apps (`SendKeys.apps`), and the owner's `sensitive` list in `computer-use.json`. In those apps, every intent except read and scroll needs owner input on this Mac within 5 minutes. A listen-only session tap (`AttentionMonitor`) records keyboard, mouse and trackpad events that lack the helper's `Input.marker`. With no input on record (tap not running yet) the action waits, so the check fails closed. The refusal is `presence_required` with reason `awaiting_attention` (`retryable: true`, `details {app, idleSeconds?, windowSeconds: 300}`). It comes after fixed-cap and tier refusals and before `tier_ask`, so no card is shown for an action that cannot run. An approval does not count as attention.
