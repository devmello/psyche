# S14 status: Mac helper (`apps/mac-helper`)

Updated 2026-10-19. Plan: [docs/plans/s14.md](../plans/s14.md). Package docs: [apps/mac-helper/README.md](../../apps/mac-helper/README.md). Manual test plan: [apps/mac-helper/docs/manual-test-plan.md](../../apps/mac-helper/docs/manual-test-plan.md).

## What works (M1)

- **Node runtime (A9).** Persistent device identity (data-protection keychain, 0600 file fallback for builds without a provisioning profile, one-way migration file → keychain). Long-running connection with reconnect backoff; `connect` declares the capability manifest; `node.invoke` → `res {accepted}` → `node.event`* → `node.result` with receipts (including `failed` receipts for refused side effects); errors carry protocol codes plus `details.reason`. `psyche-helper --manifest` prints it.
- **Permissions (A9).** `permissions.status/request/open_settings` from preflight APIs only, explanations, `x-apple.systempreferences:` links, security §12 order; Screen Recording only with `purpose: vision_fallback`; Full Disk Access opens Settings.
- **Computer use (J1, J2, J5).** Spike 04's walker as a generic, unit-tested builder (visit/emit budgets, clipping, pruning, collapsed labels, detached focus, Electron wake-up); helper-held identity refs; `expect` checks; exact-match selectors; AX-first actions with read-back and HID CGEvent fallback; secure fields refused at dispatch; risky labels and chords need approval; tiers with fixed caps, `ask` + 30-minute session allowances, one session lock, Esc stop through an active event tap that also ends the session.
- **Screenshots (J3).** ScreenCaptureKit with Psyche, terminals/IDEs, password managers, finance apps and Off-tier apps excluded, 1372×887 downscale, suppressed while a secure field is focused; `SCContentSharingPicker` capture.
- **Apple Events / Shortcuts (J4).** In-process AppleScript/JXA with per-target Automation preflight; Shortcuts via `/usr/bin/shortcuts` spawned with responsibility disclaimed.
- **Keychain (G1).** S06's contract: `keychain.set`, `vault.unlock`, `keychain.delete`, plus `keychain.status`; `[.biometryCurrentSet, .or, .devicePasscode]`, `WhenPasscodeSetThisDeviceOnly`, `LAContext` prompts, OSStatus mapping.
- **Notifications (O10).** `notify.show` accepts S15's `NotifyShowParams`; categories per kind, text replies, interruption levels, quiet hours, provisional authorization, Touch ID before forwarding approvals that need it; responses on `notify.subscribe`.
- **Speech (Q1).** SpeechAnalyzer / SpeechTranscriber / DictationTranscriber on 26+, on-device SFSpeechRecognizer otherwise; microphone or pushed PCM; `AVSpeechSynthesizer.write` PCM; Personal Voice opt-in flagged non-commercial.
- **Bundle.** `scripts/build-app.sh` (hardened runtime, entitlements, optional profile → keychain group and time-sensitive), `install-agent.sh` (LaunchAgent, quarantine cleared), `tcc-reset.sh`.
- Tests: 198 Swift Testing cases (160 in `PsycheHelperCoreTests`, 38 in `PsycheHelperSystemTests`); none need TCC grants.
- An independent review of the diff found 16 issues, all fixed: input only goes to a verified frontmost app that owns keyboard focus (checked per chunk), synthetic clicks are hit-tested for occlusion/secure fields/risky labels, menus and non-press actions need Read and interact (so no Terminal Edit>Paste in the click tier), `apps.open` stays inside Applications folders and refuses executable documents, scripts may not drive System Events or capped apps, Esc uses per-invocation tokens, `session` is required, numeric params are clamped, writes after close cannot hit a reused fd, the picker callbacks hop to main, the Esc tap setup is locked.

## Doc objections (proceeding with the docs unless noted)

1. **Depth ≤ 8** (S14 prompt, research default) is too shallow: Electron web content and Reminders rows sit deeper (spike 04). The helper bounds walks by visit/emit budgets (6000/400) with depth 40 only as a safety cap. The prompt should say so.
2. **Security §4.2 / research KQ7: "constraint flags combined without `.or` return `errSecParam`"** is not what macOS 27 does: `[.biometryCurrentSet, .devicePasscode]` creates fine and means AND (both required). Only `.or` together with `.and` fails with `-50`. The helper always passes `.or`; the doc sentence should be corrected.
3. **Data-protection keychain probing:** without the entitlement, `SecItemCopyMatching` for a missing item returns `-25300`, not `-34018`; only add/delete reveal `-34018`. `keychain.status` probes with a delete.
4. **Architecture §6 table** names `apps.shortcut`; the helper uses `apps.shortcut_run` (the S14 prompt's name) plus `apps.shortcuts_list`.

## M3 threat-model fixes (helper side)

- #269 (closed here): Notification Center, the user-notification and security agents, LocalAuthentication's UI agent, loginwindow and System Settings are fixed-cap Off in the helper and in the broker's `LOCKED_OFF_APPS`. The two lists are kept in parity by tests.
- #266 (helper side): a click or press on a menu-like role (`AXMenuItem`, `AXMenuBarItem`, `AXMenuButton`, `AXPopUpButton`, …) runs as intent `menu`, which needs interact. This applies to refs and to x/y points (the role is hit-tested).
- #267 (helper side): approvals are bound. The helper honours `approvalId` only together with `params.approval {app, tier}`, and only when `app` is the app the action reaches. The 30-minute allowance grants exactly the approved tier. x/y calls must name `app`, and the point must land in it (`app_mismatch`).

- #270 (helper side): in messaging and mail apps (`SendKeys.apps`: Messages, Mail, Slack, WhatsApp, Telegram, Discord, Signal, Teams, Outlook, …), `computer.key` with Return, Enter or cmd+shift+D (`send_key`), and `computer.type` with a line break (`send_text`), need their own approval. They answer `approval_required` with `details.sideEffect: "destructive"`.
- #271 (helper side): AX labels, values, window titles and app names escape every line terminator (\n, \r, \r\n, U+2028, U+2029, NEL, VT, FF) as `⏎`. Other control and format characters become spaces. Identifiers containing them are dropped. A rendered snapshot is always one line per element.

- #268 (closed here): `apps.applescript` / `apps.jxa` run out of process (`/usr/bin/osascript`, responsibility disclaimed, minimal environment, source on stdin, `timeoutSeconds` 1–300, default 60), so a script never holds the helper's Accessibility or Full Disk Access. `ScriptGuard` (now in Core) matches tokens on source with whitespace, line continuations and invisible characters removed, and bans shell, `run script`, ASObjC (`use framework`, `current application`), raw `«event»` codes, JXA's ObjC bridge and `$`, `eval`, `Library`, computed members, arrow functions, template strings, Standard Additions file I/O and the clipboard. `target` is required. Finder, System Events, Terminal, iTerm2, Script Editor, Automator, Shortcuts and apps whose fixed cap is below interact are refused. Every app the script addresses (`application "…"`, `app id "…"`, `Application('…')`) must resolve to the target, and any non-literal app reference is refused (`script_dynamic_target`). In the broker `apple_script` is device-only and needs authentication.

### Requests to S01 / S05 for #268

- Check the target's fixed cap (`appCap(p.target)`) before the card is shown, not in `run()`, so a script aimed at Terminal is refused without a card (`app-script-terminal-target-026`).
- The helper answers `policy_denied` with reasons `shell_escape`, `script_target_mismatch`, `script_dynamic_target`, `script_target_capped`, `system_events`, and `not_found/script_target_unknown`; surface them to the model as is.

### Requests to S01 for #270 / #271

- `describeAct`: `key` with return / enter / cmd+shift+d, or `type` text with a line break, in the same app list is `sideEffect: "destructive"` (`message_send` card), and must not be covered by an `${app}|interact` grant.
- `elementsIn`: split on `\n` only (not a `/gm` regex). The helper no longer emits other terminators, but the parser should not rely on that.

### Requests to S01 for #266 / #267

- Send `approval: {app: <bundle id the card named>, tier: <tierRequired>}` with every `computer.*` / `apps.focus` invocation that carries an `approvalId`. Without it the helper treats the call as unapproved (`approval_required/tier_ask`).
- Send `app` with every x/y target (`endpoint()`), and expect `policy_denied/app_mismatch` when the point is elsewhere.
- In `describeAct`, a click on a ref the snapshot shows as `menuitem`, `menubaritem`, `menubutton` or `popupbutton` needs `tierRequired: "interact"`.

## Requests to other sessions

- **S00 / protocol (additive `protocol:` PR wanted):**
  - `node.cancel {invocationId}` (Gateway → node). The helper already honours it; the Gateway needs it to stop dictation, pickers and Touch ID sheets when a run is cancelled.
  - An unsolicited node → Gateway event (e.g. `node.emit {event, payload}`), so notification responses and Esc stops need not ride a long-lived `notify.subscribe` invocation.
  - Optionally lift capability params into TypeBox (the helper's `inputSchema`s are the source today).
- **S01 (Gateway):**
  - Pass a stable `session` (the run id) in every `computer.*` call and call `computer.end_session` when the run ends.
  - Write user tiers to `$PSYCHE_HOME/config/computer-use.json` (format in the helper README) from Settings → Computer use; never expose a tier-changing capability through `node.invoke`.
  - Keep `keychain.*`, `vault.unlock` and `permissions.request` unreachable from agent tools (Gateway-internal / UI-initiated only); treat `vault.unlock` results as secrets.
  - Strip any `approvalId` the agent supplies; only the Permission Broker may set it.
  - Open `notify.subscribe` once per helper connection and route `notify.response` events to approvals (`authenticated: false` must not approve when Touch ID was required).
- **S05 (permissions):** classify `computer.*` with the helper's `targetKind: app`; `apps.applescript`, `apps.jxa`, `apps.shortcut_run` are `destructive` and should bind the approval to the exact `source`/`name`+`input`. The helper additionally refuses risky labels/chords without an `approvalId`.
- **S06 (vault):** the helper implements your README table. Without a provisioning profile, `keychain.set` fails with `unavailable/missing_entitlement`; fall back to passphrase mode.
- **S11 (desktop):** launch the helper through LaunchServices (`open -b com.psyche.helper` / `NSWorkspace`), never as a child process, or TCC grants attach to Electron. Show "Psyche is using your computer · press Esc to stop" while a computer-use session runs. Call `vault.lock` on sleep/screen lock (S06 asked S11/S14; the helper can add a sleep observer in M2 if S11 prefers).
- **S15 (notifications):** `notify.show` accepts your params as-is; action callbacks arrive as `notify.response` events with `text` for replies and `authenticated` for Touch ID.
- **S17 (speech):** the helper's `speech.*` shapes follow `SpeechEngine` (`TranscriptSegment`, `AudioFormat`); push audio with `speech.audio_push`.
