- **Backups**: age (passphrase or X25519 recipients), SHA-256 manifest, verify, restore with move-aside; Compose scripts in `deploy/backup/`.
- **Release workflow** (`.github/workflows/release.yml`): tags and manual runs only (CI diet, #165). Deploy smoke gating the image, multi-arch image + SBOM/provenance + keyless cosign signature, CLI binaries for 4 targets with version and migrations baked in, DMGs, GitHub release with notes and SHA256SUMS, Homebrew tap; the changesets Version Packages PR on a manual `version_pr` run.

## Backups and logs in the Gateway (branch ws/s22-backup-gateway)

- `@psyche/backup` (new package, S22) holds the archive code the CLI and the Gateway share; `apps/cli` imports it.
- The composed Gateway serves `backup.list` (read), `backup.create`, `backup.verify` and `backup.delete` (admin; protocol #110 makes verify admin too) and `logs.tail` (read). `backup.create` keeps the Gateway running: SQLite's online backup API on the Gateway's own connection for `state/psyche.sqlite`, a hard-link snapshot for the rest. Restore stays CLI-only.
- `psyche backup create` asks a running Gateway for the archive (no downtime); `--out` or `--stop` keep the offline path.
- `logs.tail` runs every line through the audit redactor (`redactForAudit`, `redactSensitive`). It reads `$PSYCHE_HOME/logs/gateway*.log`, which only the LaunchAgent writes: under systemd and Docker the Gateway logs to the journal / stdout, so the viewer is empty there (request to S01 below).
- Tests: the composed Gateway (`apps/gateway/test/backup.test.ts`) and a real `psyched` → `psyche backup restore` round trip that boots a second Gateway from the restored home (`apps/cli/test/backup-roundtrip.test.ts`).
- Not covered: `vault/vault.db` is copied from a hard link, not an online backup (the vault is not composed into `psyched` yet); when it is, pass its connection's backup as a second snapshot writer. Backup and verify are not audited yet.

## M3 release hardening

- **Sandbox image publishing, reviewed on paper** (`deploy/sandbox-image/publish.sh`, `release.yml` jobs `sandbox-image` and `sandbox-image-pr`; nothing built locally). `publish.sh --dry-run --version 1.2.3 core base full` prints, per variant, a multi-platform `buildx build --push` with provenance and SBOM, then `cosign sign` by digest, and leaves `versions.json` untouched; bad versions and unknown variants exit 2. `apps/cli/test/deploy.test.ts` now runs that dry run. Walking the job: it publishes only when `PUBLISH` and the ref is a `v*` tag (dispatch runs and branches dry-run); before building it checks that `versions.json .repository` is under `ghcr.io/<owner>` and that this run's signer identity (`https://github.com/<repo>/.github/workflows/release.yml@refs/tags/v…`) matches `.signing.certificateIdentityRegexp`; after pushing it `cosign verify`s every variant against that regexp and issuer; `sandbox-image-pr` copies only `version` and `variants` onto the default branch and opens a PR. No defects found. Notes: a full tag run takes up to ~3 h (the `full` variant under QEMU); the digests PR is opened with `GITHUB_TOKEN`, so it starts no workflows (irrelevant under the local merge gate).

## Independent review (fixed in this PR)

A read-only review of the diff found: crafted backup manifests could rename files outside `$PSYCHE_HOME` on restore (entries and file paths are now validated against the known top-level names, with rollback on a failed restore); tar failures were unhandled rejections; the Compose backup scripts `cd`'d into a directory owned by uid 10001 and copied identities next to the backup (now absolute paths and the identity on stdin); signed Bun binaries lacked JIT entitlements; Compose env vars silently overrode `config.json`; `launchctl bootstrap` raced `bootout`; node-shim `psyched` paths would crash-loop under launchd's PATH; `config set gateway.host 0.0.0.0` was accepted; `backup verify` extracted plaintext next to the archive (now under `$PSYCHE_HOME`); Ctrl-C at a secret prompt hung. Left as is: `security import -P` takes the P12 password in argv on the ephemeral macOS runner (no alternative in `security`); the Playwright sidecar fetches its pinned npm package on start (documented in the Compose file).

## Objections to the docs (proceeding with the doc's intent)

- **Security §10 "Docker defaults"** says the image binds the container interface with `PSYCHE_BIND=container` and requires `PSYCHE_GATEWAY_TOKEN_FILE`. The Gateway implements neither and refuses non-loopback binds. Compose therefore uses host networking: the Gateway listens on the host's loopback, nothing is published, and the proxies (Tailscale, cloudflared) run on the host network. This meets the goal (no exposed bind) but needs Linux or Docker Desktop host networking. When S01 adds a container bind with token auth, switch Compose to a bridge network with the proxy on an internal network.
- **Architecture §14 / security §14** say backups are age-encrypted; the doc does not say how the snapshot stays consistent. The CLI never opens the database, so backups stop the Gateway (`--stop`). An online snapshot needs a Gateway method (request below).
