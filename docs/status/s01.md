## What works (M1)

- **Server**: WS + HTTP on `127.0.0.1:7979`, `req/res/event` frames, `seq` + persisted `stateVersion` on every event, async dispatch, graceful shutdown, metadata-only JSON logs, `config.json` (validated, fail fast) with env overrides.
- **Auth and pairing**: signed Ed25519 challenge; loopback auto-pairing for the desktop (read/write/approvals, never admin) and the helper (`node`); node socket accepts only nodes; pairing requests with key fingerprint, transport and address; `devices.list|pairing.list|approve|deny|revoke` (approve checks the fingerprint and optional code; revoke closes connections and takes node authority); first-admin bootstrap with `psyched devices approve <code>`; rate limits (failed challenges 10/min/IP, pairing 5/hour/IP, 20 pending); pending connections close at expiry; Origin allowlist; proxy identity headers ignored; `trustedProxy` is a config flag only.
- **Idempotency**: results of side-effecting methods persisted in `gateway_idempotency` in the mutation's transaction; concurrent duplicates share one in-flight call.
- **Session controller**: per-thread serialization on the writer guard, `followUp` (durable, visible, removable queue) / `steer` / `interrupt`, cancellation revokes authority via `AgentLoop.cancel` and `PermissionBroker.revokeRunAuthority`.
- **Threads and chat**: every `threads.*` method (one main thread, side, incognito with 24 h expiry, title search, activity counts, cursor paging, fork with lineage copying blocks and provider-native turns verbatim), `chat.send` (Library attachments as `file` blocks), `chat.steer`, `chat.followUp`, `chat.cancel`, `chat.history`, `chat.queue.list|remove`, `chat.export` (Markdown, JSON), `events.subscribe` filters.
- **Agent wiring**: `AgentEvent` → `chat.delta`, `chat.block`, `chat.message`, `run.updated`, `tool_call.updated` (persisted rows), `approval.created`, `question.created`.
- **Nodes**: registry over the node protocol, `nodes.list|capabilities|invoke` through `PermissionBroker.decide` with approval requests, `approvalId` passthrough re-verified with `verifyBinding`, receipts via `recordReceipt` + `receipt.created`; `vault.*`, `keychain.*` and security namespaces unreachable.
- **Restart recovery** and **retention** as described in the README.

## Independent review of this diff

A read-only reviewer reported 10 findings (3 reproduced); all are fixed with regression tests in `test/review-regressions.test.ts`: an interrupt now detaches the superseded turn before the new one starts and finished runs cannot be reopened; `threads.delete` stops the thread's queue before cancelling; a reconnecting node stays online; recovery leaves tool calls of suspended runs alone; retention keeps expired incognito threads that still have suspended runs; the capability denylist matches whole names (`vault`, `vault_fill`, `keychain/read`); every persisted run and tool-call update bumps `stateVersion`; scopes are re-read from the device row on each request (a downgrade or revocation applies to live connections); an unverified `approvalId` is not passed to the node on `allow`; agent errors are logged by code only.

## Objections to the docs (proceeding with the docs)

- The S01 prompt names `chat.fork`; architecture §11 and the protocol use `threads.fork`. Implemented `threads.fork`.
- "Scoped device tokens": the protocol returns no token in `ConnectPaired`, and security §10 says a token alone never authenticates, so the device key plus stored scopes is the credential; `devices.token_hash` stays unused.
- Feature E3 needs a visible, removable queue; the protocol had none. Added `chat.queue.list|remove` and `chat.queue.updated` additively.
- `threads.delete` had no event for other clients (N14). Added `thread.deleted`.
