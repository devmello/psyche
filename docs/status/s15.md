# S15 status: proactive surfaces and notifications

Updated 2026-10-19 (M2 PR 2). Plan: [docs/plans/s15.md](../plans/s15.md).

## Works (M1, notifications: `packages/notifications`)

- `PsycheNotifier` implements `Notifier` and passes the `@psyche/testing` conformance suite on both stores (memory, SQLite).
- Durable inbox: `SqliteNotificationStore` on better-sqlite3 (survives restart, tested on a file DB); `MemoryNotificationStore`.
- Routing per kind to in-app (desktop, web), OS (`notify.show` on the mac helper node, Electron fallback hook) and the owner's chat surfaces, with interruption levels per kind. A routing-matrix test covers every kind.
- De-duplication per `<kind>:<taskId>` or an explicit key. Terminal task notifications supersede the task's open question or failure.
- Quiet hours: IANA zone, windows that cross midnight, day filters, DST-safe end computation, approvals break through. Deferred deliveries re-plan when settings change.
- Retries with exponential backoff; non-retryable failures and policy suppressions are recorded per surface.
- Restart reconciliation: open approvals become stale; task-bound rows are checked against `TaskEngine`; custom rules can be added; deliveries cut off mid-flight are re-queued.
- `notifications.list` / `markRead` / `resolve` handlers, typed from the protocol registry; `toGatewayEvent`.
- Security: `deviceOnly` approvals never reach chat (not even as text); approvals cannot be answered through the inbox; `authenticationRequired` reaches the helper.
