## What works (M1)

- **SQLCipher vault and key slots:**
  - the vault runs on `better-sqlite3-multiple-ciphers` in SQLCipher 4 page format with a raw 32-byte DEK;
  - key slots: keychain (through the mac helper), `safeStorage` (refused on `basic_text`), and a key file for server mode;
  - recovery key: grouped base32, Argon2id, AES-256-GCM, shown once, then confirmed;
  - the vault locks after idle time; concurrent unlocks share one Touch ID prompt; items flagged for it prompt on every use.
- **Items:**
  - kinds `login`, `api_key`, `ssh_key` and `note`; OAuth tokens are owned by connectors;
  - a login can be bound to several origins, and bindings are normalized;
  - card numbers, CVVs, bank accounts and government ids are refused with an explanation that points to Stripe Link;
  - CSV import from 1Password, Bitwarden and Chrome;
  - metadata is mirrored to `credential_meta` / `credential_uses`;
  - the last 50 uses per item are kept.
- **Placeholders and resolve:**
  - the full resolve order is documented in the package README;
  - the binding hash is recomputed at resolve time and verified through `PermissionBroker.verifyBinding`;
  - every denial is logged and audited;
  - `.totp` resolves to the current code;
  - `.header` resolves to the prefix plus the token.
- **Redaction:** exact and fuzzy forms. Values that left the vault are kept for the life of the process. Covered by property tests.
- **Fill helpers:** browser (CDP), HTTP with manual redirects and rebuilt errors, sandbox env.
- **`credential_fill` approval builder:** offers `once` plus opt-in `site`; the grant key includes the field class.
- **OAuth:** store, owner-only access token, atomic rotate, and revoke with an invalidation event.
- **`vault.*` handlers and events:** checked against the protocol schemas.
- **Tests:** 90 pass and 3 are todo (`pnpm --filter @psyche/vault test`). The `CredentialBroker` conformance suite runs against the real vault.

## Adversarial review (before the PR)

An independent reviewer found 12 defects; all are fixed, with regressions in `test/review-fixes.test.ts` and `test/fill.test.ts`:
- **Browser fill TOCTOU:** origin and focus are now re-checked after resolve, which can wait on Touch ID.
- **Text-type password fields:** no longer accepted (protocol devmello/psyche#34); every fill reports `secureField`.
- **Mirror trust:** the encrypted store now decides owner and bindings.
- **Wildcard bindings:** refused over shared and public suffixes and in imports.
- **Redactor:** now masks form encoding.
- **Import skip reasons:** they no longer echo cells.
- **Refusal scanner:** bypasses closed (separators, full-width digits, IBAN followed by text, spaced SSN, "security code is"), and the quadratic regex is gone.
- **Grant key:** now includes the executor.
- **Approval consumption:** lock, unlock and missing-field failures no longer consume the approval; each writes a `failed` use row.
- **Unlock paths:** serialized, with no leaked DEK or store handle.
- **Form action:** `formaction` on submitters is now checked.

## Objections to the docs (proceeding as noted)

1. **05 §4.1** puts key slots in a `header` table inside `vault.db`. That cannot work: the slots must be readable before the key is known. Slots live in `vault/slots.json` and `vault/recovery.slot`, both 0600. The in-database `header` keeps the version, the vault id and the slot names.
2. **05 §4.1 and §4.2 disagree** on the recovery KDF (PBKDF2 vs Argon2id). I used Argon2id, following §4.2. The S06 prompt's "BIP39-style words" also loses to §4.2's grouped base32.
3. **04 §6** says the keychain access control is `userPresence`/biometry. 05 §4.2 and the prompt say `[.biometryCurrentSet, .or, .devicePasscode]`. I followed 05; 04 §6 should be updated.
4. **04 §4.2 and 05 §3.5 disagree** on the credential-fill binding fields (S23 design-13). I followed 05 §3.5: item id, target, field, field selector with element tag / type / autocomplete, plus executor. There is no tab id.
5. **The `CredentialBroker` contract lists only `approval_required`** for approval failures. The vault uses that code for all of them, with `details.reason` (`approval_expired`, `approval_consumed`, `approval_binding_mismatch`, …).
6. **Undefined `executor` in `ResolveOptions`** is treated as a non-browser executor, because the conformance suite resolves without one. Browser executors must pass `executor: "browser"`; `fillBrowserField` always does.
