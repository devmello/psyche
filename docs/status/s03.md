# S03 model router: status

Branch `ws/s03-model-router`. Package `packages/model-router`. Plan: `docs/plans/s03.md`.

## What works (M1)

- **Adapters (B1).** One `AiSdkAdapter` on AI SDK v7 (`ai` 7.0.143, `@ai-sdk/provider` 4.0.29) drives `LanguageModelV4.doStream` for each kind: `anthropic`, `openai` (Responses), `google` (Interactions), `openrouter`, `openai-compatible`, `anthropic-compatible`, `ollama` (native).
  - Each adapter handles streaming text, parallel tool calls, tool results in, and images in.
  - Opaque reasoning round-trips: Anthropic signatures, OpenAI encrypted reasoning, and Gemini signatures on tool calls.
  - Usage is reported by class. Errors map to router kinds. Cancellation and first-event / idle timeouts work.
  - Anthropic: adaptive thinking is on by default, prompt caching marks the system prompt and last message, and `memory_20250818` / `computer_toolset_20260801` pass through when enabled.
- **Router (B2).** `router/<role>` refs; the `primary` role with fallbacks, plus `utility`, `embedding`, `vision` and `speech`.
  - Per-provider and per-profile cooldowns (30 s → 1 min → 5 min, billing 10 min, `retry-after` honoured).
  - Auth profiles rotate before fallback. Fallback happens within one request, before any content.
  - Strict mode for user-pinned models, per-thread `/model`, and a `prepareStep` hook.
  - An `auto`-mode allowlist and `health()`.
- **Usage (B3).** Usage is normalized into disjoint classes and costed from the vendored LiteLLM price table (`pnpm --filter @psyche/model-router prices:update`), or from OpenRouter's reported cost.
  - `UsageLedger` has in-memory and SQLite repositories (the existing `usage` table).
  - `summary()` feeds the meter, and the monthly budget alert fires once per threshold.
- **Probe (B4).** Six-case suite. Verdicts are saved through `KeyValueProbeStore` (settings rows `models.probe.<ref>`).
  - `setRole("primary")` and `setThreadModel` refuse `chat-only` models unless `override` is set.
  - RAM-fit tiers and suggested models are included, with names checked against ollama.com/library on 2026-10-19.
- **Embeddings (B5).** `embed(texts, {model, task})` with nomic task prefixes, and `embeddingInfo()` reports the dimension.
- **Keys (B6).** Keys are resolved per HTTP request through `CredentialBroker.resolve` for the request origin and injected inside `ResolvedSecret.use`. Packages only ever hold a sentinel. Errors are redacted.
- **Tests.** 245 tests pass, with no network.
  - Fixture-replay tests for all seven kinds, router tests, ledger and probe tests, and the shared conformance suite on the router and every adapter.
  - Live tests sit behind `PSYCHE_LIVE_TESTS=1`.

## Subscription CLIs as providers (2026-10-20)

`claude-code` and `codex` kinds use the owner's Claude and ChatGPT plans through the installed CLIs, with no API key. The design and the limits are in the README section "Subscription CLIs".

- **Model router (`src/cli/`).**
  - `CliAdapter` drives one CLI process per turn.
  - `ToolBridge` and `mcp-stdio-bridge.mjs` bridge Psyche's tools as the `psyche` MCP server. A model call ends at the tool calls, and the next call resumes the same process with the results.
  - The `claudeCodeDialect` and `codexDialect` parsers turn CLI output into model events.
  - `probeCli` probes version and sign-in, and never reports account details.
- **Gateway.** Both providers are listed by default ("Claude Code (subscription)", "ChatGPT via Codex (subscription)").
  - `PSYCHE_SUBSCRIPTION_CLIS=off` leaves them out. `PSYCHE_CLAUDE_PATH` / `PSYCHE_CODEX_PATH` point at a CLI that is not on PATH.
  - Each CLI gets a working directory under `$PSYCHE_HOME/cli/<id>`.
  - Suspended runs are stopped with the Gateway.
- **Settings.** Both show as "Subscription" with no key line, and a probe chip ("Not signed in" when signed out). Their models can be picked as primary or utility.
- **Protocol.** No change was needed: `ModelProviderSummary.kind` is a free string and the probe shape fits.
- **Tests.** They run against a fake CLI (`test/fake-cli/fake-cli.mjs`). It replays recorded stream-json / exec JSONL and acts as a real MCP client against the real relay. The real CLIs never run in CI.
  - model-router: Claude Code 19, Codex 15, probe 6.

  - UI: 1.

### #504: Anthropic key from Settings refused with HTTP 401 (2026-10-20)

- **Findings.**
  - On the packaged path (vault-backed keys, no environment), the key reaches Anthropic byte-exact in `x-api-key` with `anthropic-version: 2023-06-01`. This holds for the probe and for a chat turn, after a replace, and through the real Gateway composition (`apps/gateway/test/model-key-wire.test.ts`).
  - One local check with the real key, through the real composition, gave `reachable` with 13 models.
  - On the owner's install (read-only look: plist, env names, settings rows and credential metadata, never the vault), the env holds no API-key variables. There is one `model-anthropic` item, written once and filled on every request. So Anthropic rejected exactly the stored bytes: what was pasted was not that key (a subscription token, a stray character, or a wrong first paste).
  - Settings then offered no way to replace a stored key.
- **Fixes.**
  - `models.setKey` normalizes the paste: surrounding spaces, quotes and invisible characters, plus a pasted `Bearer ` or `x-api-key:` prefix, are dropped. It refuses, with a reason and without quoting the key, a key that holds whitespace or non-ASCII, a Claude subscription token (`sk-ant-oat…`, which points to the Claude Code provider), an Admin key, or anything not shaped `sk-ant-…`.
  - The probe reports the provider's own reason. A 401 / 403 says the key was refused or that no key reached the endpoint; 400 / 404 / 405 / 415 / 422 say the request was malformed.
  - Onboarding probes right after saving and keeps the field open on a refusal; the recovery key is still shown.
  - Settings → Model & providers has an inline Add / Replace key field that saves through `models.setKey` and probes at once.

### #500: V1 s10 on `claude-code/haiku` (2026-10-20)

This was not a provider bug.
- **What happened.** After the tampered send is refused (`binding_mismatch`), Claude Code Haiku retries `gmail.send` with the body it drafted. The harness injected the edited body ("I'll bring the deck") after the approval, so the model never saw it. API Haiku does not retry, so its s10 is skipped with three assertions unchecked (INT-3).
- **The cause.** The live driver bound the soft `apr_v1_send_lena_2` to that retry card, because it fell back to the latest card when none showed `mustShow`. It then ran s10's hard checks against a send that could not contain the edit.
- **Driver fix.**
  - An assertion that is soft in live mode and has `mustShow` binds, and holds its card for a later approve step, only when a card shows every string.
  - Otherwise the step is skipped and reported, and the retry card gets the scenario's `deny` policy.
- **Provider check.** A fake-CLI test confirms that the refused call goes back to the CLI as an MCP `isError` result and is never re-emitted.
- **Real runs.** I made two `claude` runs of V1, recording only summaries:
  - Run 1 had the driver's binding fix only. The retry card stayed pending, so the run ended `awaiting_approval` (hard fail).
  - Run 2 had both fixes: 36 hard checks passed, 0 failed, 3 unchecked; 7 of 9 soft checks passed. That is the same profile as API Haiku.

## M3 (2026-10-19): remaining B1 adapters and the B4 probe UI

Branches: `ws/m3-models-protocol` (devmello/psyche#249), `ws/m3-model-adapters` (this package), `ws/m3-models-settings` (Gateway + Settings UI).

- **New kinds `llamacpp` and `lmstudio`.** Both run on `@ai-sdk/openai-compatible` with default local base URLs and wire fixes at the HTTP boundary (`src/compat.ts`):
  - a named tool choice becomes `required` with only that tool;
  - tool-call deltas are repaired (a shared `index`, an empty `id`, object `arguments`, `stop` after tool calls);
  - usage is rebuilt from llama.cpp `timings`;
  - LM Studio's plain-string errors are reshaped;
  - `--jinja` errors map to `bad_request`.
- **Google `googleApi: "generate-content"`.** Adds the stable `streamGenerateContent` Gemini API alongside the default Interactions API. Thought signatures round-trip, and `store: false` is sent only to Interactions.
- **OpenRouter.** `attribution: {url, title}` sends `HTTP-Referer` and `X-OpenRouter-Title` through the package's `appUrl` / `appName`. It is off by default (no telemetry). Model ids keep their slashes and `:variant` suffixes (`openrouter/meta-llama/llama-3.1-8b-instruct:free`).
- **Tool names per provider** (`toolNameRuleFor`): Anthropic allows 128 characters; OpenAI-style providers allow 64; Gemini allows 64 and needs a letter or `_` first. Before this, every provider got the 128-character Anthropic rule, which OpenAI and Gemini reject above 64.
- **Endpoint probe** (`probeEndpoint`, `src/endpoint-probe.ts`).
  - It reports reachability, the model list and capability guesses (vision, tool use, reasoning, embeddings, context length) per kind, with a `not_probed` state.
  - Facts merge in this order: name heuristic < catalog < listing < config.
  - Results are stored as `models.endpoint.<id>` settings rows (`KeyValueEndpointProbeStore`), and `AiSdkAdapter.learn()` feeds them into `capabilities()`.
  - `ModelRouter.providers()` lists the registry.
- **Tests:** 352 pass offline (`--maxWorkers=2`), up from 249. They include the conformance suite for `llamacpp` (text and tool streams), `lmstudio` (text and tool streams) and `google` generate-content.

### Gateway and Settings (branch `ws/m3-models-settings`)

- **Gateway `models.*`** (`apps/gateway/src/compose/model-settings.ts`):
  - `models.list` returns configured providers, the models known from role chains, config and the last probe, tool-check verdicts, and the stored endpoint probe (`not_probed` until someone asks).
  - `models.probe` probes one configured provider and stores `models.endpoint.<id>`. The adapter learns the facts.
  - `models.check` runs the six-case suite.
  - `models.setRole` returns `policy_denied` for a chat-only primary unless `override` is set. It persists `models.primary` / `models.utility` and emits `settings.changed`.
  - At boot the Gateway re-applies the picks and the learned facts. Tool-check verdicts now persist through `KeyValueProbeStore`.
  - `PSYCHE_LLAMACPP_URL`, `PSYCHE_LMSTUDIO_URL` and `PSYCHE_OLLAMA_URL` list those local servers.
- **Settings → Model & providers** (`packages/ui` `ModelSection`):
  - Each provider shows its endpoint probe state (`EndpointProbeStatus`) with a "Check endpoint" button, plus model capability chips (Tools, Vision, Reasoning, Embeddings, context).
  - Primary and utility picks go through `models.setRole`. A chat-only primary asks "Use anyway".
  - The tool check goes through `models.check`. Embedding models are not offered as roles.
  - Older Gateways fall back to the `models.providers` setting.
  - The mock gateway answers `models.*` from fixture data (`sampleModelProviders`, `sampleEndpointProbes`).
- **apps/web:** the ⌘⇧I model picker suggests `models.list` refs.
- **Tests:** 7 Gateway tests (`model-settings.test.ts`), 7 UI tests (`screens-settings-models.test.tsx`), 2 web tests, and a `ModelEndpointsProbed` story.

## Stubbed or not verified (M1)

- **Fixtures are hand-written.** They were written from the documented wire formats and the installed parsers, not recorded against live APIs (no keys here). The live tests re-check them.
- **The probe has not been run by hand against Ollama** from this session (no local server). The README documents the procedure.
- **Speech:** the role can be bound, but there is no speech call (S17).
- **M2 is not started:** vision and speech wiring, OpenRouter BYOK, Anthropic server-side compaction (pass-through only), and the health panel.

- **Usage on aborted calls.** Cancelled, timed-out and failed-after-content calls record no usage (AI SDK parts carry usage only on `finish`), so the ledger under-counts billed prompt tokens for them.
- **Probe verdicts.** A probe run where any case could not reach the model (server down, cancelled) is `inconclusive` and is not stored.

## Objections to the docs (proceeding with the docs)

- **Probe result storage.** Data model §10 has `model_profiles.probe_result`, but `model_profiles` and `model_roles` are not in schema v0. Adding them needs `packages/db` schema and test changes, which belong to S00/S01. Probe verdicts are therefore saved as settings rows for now. `probe_result` should also be per model rather than per profile (a JSON object keyed by model id), because one provider serves many models.
- **Contract gaps in `ModelProvider` (no PR opened).**
  - `finish` has no structured error code. The convention here is a `<kind>: ` prefix on `finish.error`.
  - There is no tool-call delta event.
  - Tool calls carry no provider metadata. Gemini signatures travel as `reasoning` envelopes of kind `part-metadata`.
  - An additive `protocol:` PR could add `finish.code` and `tool_call.providerMetadata` if S02 wants them.
