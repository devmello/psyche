# S12 — UI kit status

Updated 2026-10-19. PR: devmello/psyche#27 (branch `ws/s12-ui-kit`). Protocol additions: devmello/psyche#7 (merged).

## What works

- **Foundation**: Tailwind 4.3 stylesheet, shadcn v4 base-nova components on Base UI 1.9, OKLCH tokens, shadcn name mapping, fixed Radix amber/tomato/grass/sky semantic scales, density, high contrast, reduced motion (`prefers-reduced-motion` or the Appearance switch).
- **Theme generator**: seed → 12-step accent and gray scales for light and dark, alpha and P3 variants, APCA-picked text on step 9, binding WCAG gate with nudging and a report; `ThemeProvider` injects `<style id="psyche-theme">`. Tested on 20 seeded random seeds in both modes.
- **Data layer**: `GatewayClient` interface, normalized store (seq-gap and reconnect refresh, stateVersion reconciliation, optimistic overlays, stale approvals after reconnect), typed hooks, and a `MockGateway` that validates every request, result and event against `@psyche/protocol`.
- **Blocks and cards**: every block type in data model §9.1; approval card (fixed structure, Deny preselected, 400 ms arming, Return ignored, ⌘Return / ⌘D, binding details by kind, every state); question card (chips vs list, recommended first, multi-select, Other, 1–9, answered state).
- **Chat column** on assistant-ui's external-store runtime: streaming, approval dock (one card open, the rest as rows), client-side follow-up queue with remove, reply quote, fork, export menu, offline banner.
- **Agent header and sheet**: derived avatar state, status snippet, Activity (filters, three-level action log, Pause / Resume / Cancel / Retry), Approvals (needs you, deferred, recent, standing grants), Upcoming (schedule sentences, Run now / Pause / Delete), Soul & Memory (persona files with budget meters through the viewers' editor slot, if-match saves, daily notes, memory search with provenance, pause, export, typed-confirmation reset).
- **Screens**: Feed, Ideas, Goals (list, goal page, inferred-goal card), Library, Search (typed `in:` / `type:` / `from:` filters), Notifications inbox, Settings (all 15 sections of §2.6 / §3.18) and Onboarding (six steps). Each has a presentational view and a connected screen with loading, empty, error and populated states.
- **Shell pieces**: rail (bottom tab bar when compact), thread list, ⌘K palette, the §4.11 keyboard map with a ⌘/ sheet, `AppShell`.
- **Avatar**: 12 original SVG creatures (pale moth default) with idle and two-frame typing poses; states, sizes, delegated ring, reduced motion.
- **Quality gates** (394 tests): Storybook 10 with stories for every component and state; every story rendered in Vitest and checked with axe-core (in CI through `pnpm -r test`); Playwright visual baseline over the static Storybook (`test:visual`, local only).

- **Cards per surface (design-12, closed 2026-10-19 on `ws/cards-per-surface`)**: `ApprovalCard` shows the fixed template header from `renderForSurface("desktop", …)` and a `sanitizeApproval` copy of the request (summary, target, every detail value through the same value-slot sanitizer chat uses; bodies and diffs keep their lines inside their block); dock rows, panel rows and message pointers use `displaySummary`; `QuestionCard` shows `renderQuestionForSurface("desktop", …)` and answers with the original labels; `WrapUpBox` sanitizes recap, ask and labels. `@psyche/ui` now depends on `@psyche/permissions/cards` (browser-safe, no Node imports). Tests: `test/cards-per-surface.test.tsx` (secret placeholder, untrusted snippet, device-only, credential fill, question, wrap-up).

## Stubbed or partial

- **Visual regression is not in CI**: CI runners have no browser. Baselines are per platform (`-darwin` committed). Request to S00: a Playwright job (`pnpm --filter @psyche/ui build-storybook && npx playwright install chromium && PSYCHE_VISUAL_CHANNEL=chromium pnpm --filter @psyche/ui test:visual`) with Linux baselines.
- **Viewers** (S13) arrive through slots (`renderPreview`, `renderSandboxed`, `renderEditor`); without them the kit shows plain text and a textarea.
- **Panes, pop-outs, quick entry, menu bar and VM window** belong to S11; `AppShell` takes a `panes` node and leaves routing to the shell.
- **Deferred approvals** have no protocol marker; the Approvals tab treats pending approvals of automation tasks that this surface cannot answer as deferred.
- **assistant-ui** is used for the viewport, message list and composer primitives only; its runtime is kept idle so the client-side follow-up queue (removable, per UI design §3.2) can hold messages while the agent works.

- **Settings without protocol methods** store their values under setting keys the kit chose (`models.providers`, `permissions.connectors.<id>`, `permissions.folders`, `computerUse.apps`, `vm.shares`, `persona.creatureId`, `voice.*`, `data.*`, `vault.backend`, `vault.fillDefault`, `gateway.bind`) or take shell props (TCC state, usage summary, server and VM status, versions, `psyche doctor`). Connector connect / disconnect / remove, the model tool-calling check and OS permission prompts are callback props.
- **Library**: no Share, "Update by name", Export or "Trust this file" methods; Trust is an `onTrust` prop.
- **Onboarding** returns its result through `onComplete`; writing `IDENTITY.md` and starting `BOOTSTRAP.md` are the shell's (or Gateway's) job.
- **Links**: Streamdown's link hardening passes web and mail links only, so in-app `psyche://` links in model Markdown render as "[blocked]"; Feed citations to in-app sources are plain markers listed in the sources row.
- **Generic query cache** (`useGatewayQuery`, used by `useSearch`) keeps every distinct query for the session; an LRU cap is a follow-up.
- **Independent review** (2026-10-19): 14 findings on the data layer, approval and inbox safeguards and link handling; all fixed with regression tests except the query-cache growth above.
- **Vitest cache**: `fsModuleCache` can serve a stale `import.meta.glob`, silently skipping new story files; the package's `test` script passes `--fsModuleCache=false`.

## Protocol gaps found while building the fixtures (requests to the owners)

1. `Message` has no `taskId` / origin, so an out-of-turn message from a background task cannot be labelled "from task: <title>" (UI design §3.2). Workaround: a leading `task` block. Owner: S02/S01.
2. `PlanBlock.planId` refers to no entity; the plan lives in `Task.plan`. The kit treats `planId` as a task id. Owner: S02/S04.
3. `ApprovalRequest` has no field for the Broker's reason ("Why asked", §3.3). The kit reads `details.reason` when present. Owner: S05.
4. No usage summary method or schema (Usage settings, menu-bar meter). Owner: S03/S01.
5. `FeedPost` has no kind (briefing / reminder / suggestion / watch result / news cluster), so the card's kind label is guessed. Owner: S15.
6. `Goal.plan` is untyped JSON; milestones, plan artifact, notes, watches and check-ins are a kit convention; a candidate goal has no evidence field. Owner: S15.
7. `AutomationKind` has no `reminder`; watches have no condition, last value or backoff fields. Owner: S04.
8. `SearchHit` has no provenance, so the memory provenance chip (§3.13) cannot be shown. Owner: S16.
9. `Channel.allowFrom` holds raw ids without display names. Owner: S10.
10. A read-only connector's action matrix may still say `ask` for a write tool; the protocol does not say how that interacts with `scopeMode: "read"`. Owner: S09.
11. `FeedPost.feedback` is single-valued (a post cannot be liked and saved); `feed.feedback` cannot name the source to hide; `feed.list` does not report per-source failures. Owner: S15.
12. `search.query` has no type or sender filters and no ideas / goals scopes; the kit filters `type:` client-side. Owner: S16.
13. No goal delete (only `goals.archive`); no milestone editing UI yet beyond read and toggle. Owner: S15.
14. `ApprovalAnswer` has no expiry, so "Always allow until …" can only offer `session` (until this session ends) and `always` (the Broker's default lifetime); UI design §3.3 wants 1 h / 24 h / 30 days too. Owner: S05.
