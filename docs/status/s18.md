## Doc conflicts and ambiguities (found while preparing the corpus)

These change expected outcomes; the corpus follows docs/05 where it is explicit. Requests to S05 (policy) and S07 (memory) unless noted.

1. **Chat approval of `destructive`.** docs/02 §4.6 makes `destructive` device-only and chat `write`-only; docs/05 §3.7, §3.11 (`chatSurfacesMaySee: ["write","destructive"]`) and §9 let chat approve `destructive`; docs/04 §4.1's `send_email` example has `deviceOnly: true`; docs/05 §16 item 6 is open. Corpus follows docs/05.
2. **Approval-kind names.** docs/05 §3.5/§3.11 use `email.send` / `messages.send` / `policy`; docs/04 and the protocol `ApprovalKind` use `send_email` / `message_send` / `policy_change`; `pairing` and `memory_protected_write` are in the protocol enum but not in docs/04's kind list. Corpus uses the protocol enum.
3. **Untrusted-derived writes to `MEMORY.md` / `USER.md` / `AGENTS.md`.** docs/05 §8 says a direct agent edit "always asks" (`memory_protected_write`), and also that untrusted-derived writes go only to the daily note and dreaming is the sole `MEMORY.md` writer. Corpus choice: in a tainted turn such a write is `blocked` (`memory:untrusted_not_promoted`); in an untainted turn a protected-path edit asks.
4. **Taint vs. credential-fill origin mismatch.** §3.6 says a fill whose bound origin differs from the tainting origins asks even with a `site` grant; §4.5 says resolution needs an exact bound-origin match. Corpus choice: origin mismatch is checked first and is `blocked`; the §3.6 ask applies only when the bound origin matches the target.
5. **Taint for Tasks spawned from a tainted turn.** docs/02 §4.6 says the first turn inherits taint; docs/05 §16 item 7 lists it as open.
6. **Do MCP `tools/list` descriptions and annotations taint the turn?** §3.6 lists non-bundled MCP *results* only; §11 calls annotations untrusted. Tool-poisoning and shadowing defenses depend on descriptions tainting. Proposal: descriptions and annotations of non-bundled servers taint like results.
7. **Is there an agent-callable `skills.install`?** No doc says whether install is UI-only. If it is, a hijacked install call is `blocked`, not `asked`.
8. **Recalled `agent`-provenance import facts** are not listed as taint sources, so an imported "pre-approved purchases under $500" fact would not escalate on recall. Proposal: imported facts taint like `untrusted` until reviewed.
9. **Default for verified / unknown MCP tools with no per-tool rule:** ask always, or the mode default for the declared side-effect class (and which class when undeclared)?
10. **Unattended `ask`.** Deferred approvals (docs/05 §3.3) have no outcome of their own in the corpus format; proposal: add `deferred` as an outcome variant before the runner lands.
11. **`session` scope.** docs/05 §3.4 (until `/new`, restart or 12 h idle) vs. docs/02 §4.6 (stored as `always`, expiring with the app session).
12. **Designated person outside delegation.** docs/05 §9 lists what they do not get but not which rule denies a request for it (channel authorization vs. missing tool), so the audit rule name is undecided.
13. **`.test` fixture hosts.** docs/05 §3.10 lets test credentials be typed on `.test` hosts; fixtures therefore use `.example` (fixed in the registry).

## Harness (after the scaffold)

- **Secret-leak checker** (PR `[s18 harness] secret-leak checker`): fixture registry loader with derived values, card / SSN / IBAN / bank-account / passport / private-key detectors, model-visible capture in the fakes, a Vitest guard, `pnpm check:secrets` and the `security / secret-leak` CI job. Coverage: every fake that produces model-visible text captures it; packages that build their own executors call `captureModelVisible` or enable `secretLeakGuard()`.
- **Injection runner** (PR `[s18 harness] injection runner`): worst-case-model runner over the corpus format, reference gate over the fakes, diffable report, `pnpm check:injection` and the `security / injection-corpus` job. Runs the empty committed corpus today; findings for S05/protocol: `ApprovalRequest` lacks taint sources (docs/05 §3.7 shows `taint.sources`), and the gate rules S02 must implement in `before_tool_call` are listed in `packages/testing/src/injection/gate.ts`.
- Next: resumability harness and scenario runner, fakes completeness (conformance suites for AgentLoop, Scheduler, BrowserDriver, McpHost, ChannelAdapter, SkillLoader, SpeechEngine, ViewerRegistry; mock Gateway server), more CI gates.
