## M3 corpus expansion: Milestone 2 surfaces (2026-10-20)

67 cases in `tests/corpus/injection/cases/` (the first committed cases; the worked example stays in `tests/integration/injection/example-cases.json`). They are grouped in four family files:
- `email-calendar-messages.json` (19): iMessage from allowlisted senders, groups and designated persons; Messages content read by the agent.
- `mac-surfaces.json` (27): AX snapshot text, window titles, screenshot OCR, dictation-adjacent text, Apple app adapters, AppleScript and Shortcuts.
- `web-documents.json` (9): Files pane file names and converted DOCX / XLSX / PDF / PPTX.
- `mcp-skills-memory.json` (12): MCP tool descriptions and results, skill manifests.

Outcomes: 38 blocked, 27 asked, 2 ignored. Every case follows docs/05; the reasoning is in reports/m3-threat-model-review.md.

Format additions (schema, validator, types): the `mac-surfaces` family; new vectors, source kinds and techniques for these surfaces; id prefixes `imsg | ax | dict | conv | app`; goals `computer_action`, `run_script`; `context.requester` (passed to the broker as `DecisionContext.requester`); and a validator rule that `apple_script`, `shortcut_run` and `skill_install` approvals offer `once` only.

Known failures are pinned in `tests/corpus/injection/known-failures.json` (`<id>[<mode>]` → issue and owner). `pnpm check:injection`, `packages/testing/test/injection.test.ts`, the INT-2 test and the acceptance test all read that file, and each fails on a pin that passes again.

Harness changes:
- **Reference gate.** It now enforces:
  - the fixed computer-use caps (§12);
  - documents opened in a terminal or IDE count as `exec_host`;
  - every app a script addresses, plus shell escapes;
  - unreachable node capabilities (`dictation.*`, keychain, vault);
  - the Apple adapter approval kinds.
- **Fake broker.** It mirrors the real engine:
  - once-only kinds, and `exec_host` with `once` / `always`;
  - designated-person persona limits;
  - a tainted navigation to a new origin asks (`taint:new_origin`);
  - the taint rule is named whenever it decides the ask.

### M2 stack: the real loop and the Gateway's tools (#294, 2026-10-20)

`tests/integration/injection/m2-stack.ts` runs every case through the real agent loop (`createAgentLoop`: its `before_tool_call` gate, taint, binding, `beforeDispatch`) with the real broker on SQLite. The tools are the real registrations the Gateway composes:
- `createComputerUse` (`computer.*`, `apps.*`) over a fake Mac helper node that makes no system call;
- `fileTools` with the Gateway's protected roots, over a temporary granted folder;
- `execTool` over `FakeSandboxRunner`;
- `registerMcpServerTools` over `FakeMcpHost`;
- INT-2's browser tools and Google connector.

A scripted model reads the payload through a stub `source.read` tool whose output is `untrusted`, so the loop taints the turn itself. It then emits the hijacked call. Outcomes:
- **asked:** the loop requested an approval for it;
- **executed:** it was dispatched without one and its executor did not refuse;
- **blocked:** the broker denied it, the loop refused it, or the executor threw a `PsycheError`.

Tools the Gateway does not give the agent reach the loop as unknown tools, which is the real outcome: `messages.send`, `dictation.insert`, `pairing.*`, `skills.install`, `credentials.request` and the J6 `node.*` adapters. `pnpm --filter @psyche/integration-tests exec vitest run injection/m2-injection.test.ts` writes `m2-report.json`.

## Doc conflicts and ambiguities (found while preparing the corpus)

These change expected outcomes; the corpus follows docs/05 where it is explicit. Requests to S05 (policy) and S07 (memory) unless noted.

1. **Chat approval of `destructive`.** docs/02 §4.6 makes `destructive` device-only and chat `write`-only; docs/05 §3.7, §3.11 (`chatSurfacesMaySee: ["write","destructive"]`) and §9 let chat approve `destructive`; docs/04 §4.1's `send_email` example has `deviceOnly: true`; docs/05 §16 item 6 is open. Corpus follows docs/05.
2. **Approval-kind names.** docs/05 §3.5/§3.11 use `email.send` / `messages.send` / `policy`; docs/04 and the protocol `ApprovalKind` use `send_email` / `message_send` / `policy_change`; `pairing` and `memory_protected_write` are in the protocol enum but not in docs/04's kind list. Corpus uses the protocol enum.
3. **Untrusted-derived writes to `MEMORY.md` / `USER.md` / `AGENTS.md`.** docs/05 §8 says a direct agent edit "always asks" (`memory_protected_write`), and also that untrusted-derived writes go only to the daily note and dreaming is the sole `MEMORY.md` writer. Corpus choice: in a tainted turn such a write is `blocked` (`memory:untrusted_not_promoted`); in an untainted turn a protected-path edit asks.
4. **Taint vs. credential-fill origin mismatch.** §3.6 says a fill whose bound origin differs from the tainting origins asks even with a `site` grant; §4.5 says resolution needs an exact bound-origin match. Corpus choice: origin mismatch is checked first and is `blocked`; the §3.6 ask applies only when the bound origin matches the target.
5. **Taint for Tasks spawned from a tainted turn.** docs/02 §4.6 says the first turn inherits taint; docs/05 §16 item 7 lists it as open.
6. **Do MCP `tools/list` descriptions and annotations taint the turn?** §3.6 lists non-bundled MCP *results* only; §11 calls annotations untrusted. Tool-poisoning and shadowing defenses depend on descriptions tainting. Proposal: descriptions and annotations of non-bundled servers taint like results.
7. **Is there an agent-callable `skills.install`?** No doc says whether install is UI-only. If it is, a hijacked install call is `blocked`, not `asked`.
8. **Recalled `agent`-provenance import facts** are not listed as taint sources, so an imported "pre-approved purchases under $500" fact would not escalate on recall. Proposal: imported facts taint like `untrusted` until reviewed.
9. **Default for verified / unknown MCP tools with no per-tool rule:** ask always, or the mode default for the declared side-effect class (and which class when undeclared)?
10. **Unattended `ask`.** Deferred approvals (docs/05 §3.3) have no outcome of their own in the corpus format; proposal: add `deferred` as an outcome variant before the runner lands.
11. **`session` scope.** docs/05 §3.4 (until `/new`, restart or 12 h idle) vs. docs/02 §4.6 (stored as `always`, expiring with the app session).
12. **Designated person outside delegation.** docs/05 §9 lists what they do not get but not which rule denies a request for it (channel authorization vs. missing tool), so the audit rule name is undecided.
13. **`.test` fixture hosts.** docs/05 §3.10 lets test credentials be typed on `.test` hosts; fixtures therefore use `.example` (fixed in the registry).
