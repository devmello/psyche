## M3 groundwork: I13 real-Chrome mode (branch `ws/s08-i13-real-chrome`, no PR yet)

- **What works.** `launchRealChrome` starts the owner's Google Chrome on a Psyche-owned data dir with DevTools on a random loopback port; `browser.use_real_chrome` asks for consent (device-only `policy_change`, presence, once) per task, then attaches a Playwright `connectOverCDP` driver through the new routing driver and opens the tab under the task's shared origin policy; `browser.stop_real_chrome` releases it. The port is on `ownPorts` while attached, an unresolved notification and the window title show the mode, and Chrome closes on release, after 15 minutes idle, on exit or at Gateway stop. `PSYCHE_REAL_CHROME=1` turns the mode on (off by default).
- **Tests.** Launcher against a fake Chrome script; router and tools over two mock desktops; the composed Gateway's real broker (the consent card's shape, refusal without presence, no launch) and the lifecycle (port, indicator, teardown, crash). The real-Chrome proof (`test/real-chrome-live.test.ts`) is behind `PSYCHE_BROWSER_TESTS=1` and was not run locally (hot machine).
- **Doc reading.** The request said "the owner's own installed Chrome where they are signed in". ADR-007 and security §6 say a separate branded Chrome with its own user data dir, so this uses the owner's Chrome binary with a Psyche profile the owner signs into once, never their everyday profile.

## What works (M1)

- **Two drivers, one engine.**
  - `CdpBridgeDriver` runs over the desktop bridge. `PlaywrightDriver` uses `launchPersistentContext` on `$PSYCHE_HOME/browser/profiles/<name>/`; a clean partition is a fresh context, and `connectOverCDP` attaches to a loopback endpoint only.
  - Both run every page operation through `PageController` on a `CdpTarget`.
  - Both pass the same conformance suite (I2).
- **Snapshots (I3).**
  - AX tree plus DOMSnapshot gives a pruned text tree with stable `ref_N` ids, roles, names, values, states and viewport CSS boxes.
  - Interactive elements come first. The size cap drops static text before paging.
  - Same-origin frames are inlined and cross-origin frames hidden.
  - Sparse trees and CAPTCHAs are flagged.
  - Measured on the 22 fixture pages: under 300 ms on the mock and on real Chromium. A synthetic 5,000-node page builds in well under 300 ms.
- **Actions (I4).**
  - Pointer actions by ref or coordinate: click, double click, right click, hover.
  - type (with clear and submit), press (chords), select (native), scroll and scrollTo, drag, upload (Library paths) and download.
  - Waits: load, text, ref, network idle, timeout.
  - back, forward and reload; tabs list, open, focus and close.
  - Dialogs are surfaced. Input and reads refuse while a dialog is open, because it blocks the renderer.
- **Origin policy (I7).** The hard rules and the per-task sets run on every hop: the initial URL, each redirect, page-initiated document requests and each commit.
  - New origins raise `approval_required {kind: "new_origin"}`.
  - The tools ask the broker, widen the policy, and replay a stopped GET.
  - Loopback is allowed only for dev preview; private networks are blocked; there is a local blocklist and an optional remote reputation check.
- **Popups and OAuth (I8).** The bridge driver adopts popups into the opener's session through `openerTabId`; the Playwright driver uses `page.on("popup")`. The OAuth round-trip fixture passes on both drivers.
- **Downloads (I9).** Files go to the Library quarantine through `LibraryWriter`. The type is sniffed from magic bytes, executables are flagged, a receipt (`browser.download`) is written, and nothing is opened.
- **Take control.**
  - The session `controlState` is the aggregate of the per-tab `bridge.control.changed` events, or `setControlState` for Playwright.
  - Agent input is refused with `conflict {reason: "user_in_control", retryable}`.
  - On release, every ref must be re-read before the next action.
- **Credential fills.**
  - `browser.fill_credential` resolves through the `CredentialBroker` only with a `credential_fill` approval, passing the focused `FillElement` and selector, so the vault's field-class rule (S23 design-01) applies.
  - It checks the top-frame origin, the element (refs are identity-bound) and control, then types inside `ResolvedSecret.use`.
  - The secret never reaches tool output, snapshots or screenshots: screenshots are suppressed and recording frames dropped while a secure field is active.
  - Card numbers and secure fields are refused for plain typing.
- **Tools.** There are 27 `browser.*` executors. Output is `untrusted`. `describeCall` escalates per element: submit is `write`, consent and delete are `destructive`, purchase paths are `financial`.
- **Recording (I10, M1 part).** `FileRecordingSink` writes throttled JPEG frames plus `index.json` under `library/recordings/<task>/`; URLs in the index keep origin and path only.
- **Dev preview (I12, M1 part).** Console and network logs are kept for dev-preview tabs only.

## Stubbed or partial

- **`BrowserDriverEx`.** The extra methods (pointer, press, drag, scrollTo, upload, reload, dialogs, describe and peek, fillSecret, policy, console and network, `onEventEx`) live in this package until the `protocol:` PR below merges.
- **`LibraryWriter`** is local. `FsQuarantineWriter` moves files into `library/quarantine/` and keeps an in-memory index; the macOS quarantine xattr and the `library_items` row belong to the Library owner.
- **`browser_submit` binding.** It covers origin, path and the submit element. The digest of non-credential field values (security §3.5) is not in it yet, because `describeCall` is synchronous. The plan is to capture the values on approval in the executor.
- **Post-fill hygiene.**
  - Snapshot and text redaction go through `CredentialBroker.redact` when it is wired (`deps.redact`).
  - Clearing typed fields after a failed submit (§4.7) is not implemented.
  - Screenshots are refused rather than blacking out the field box.
- **Popups load before adoption.** On both drivers a popup's first request happens before the Gateway attaches, so only the commit check (which withholds content) applies to it. Blocking that first request needs the desktop to hold `window.open` loads until `bridge.attach` (S11 request below). Playwright needs a `context.route` gate for popup pages.
- **Coordinate clicks** are classed as `write` but are not hit-classified, because the hit element may have no ref. Prefer clicks by ref.
- **OOPIFs.** Cross-origin frames stay hidden. Showing related ones needs `Target.setAutoAttach`, which the desktop denies.
- **Pause-when-unwatched (§7.2 item 5)** and CAPTCHA → parking the task are emitted as events (`captcha`, `control_state`) only. Parking the task is S04's job.
- **Later:** the I12 element picker and the I14 Web Bot Auth signer; real-Chrome gaps above.

## Decisions worth knowing

- **Playwright drives pages through a CDP session, not `ariaSnapshot({boxes})`.**
  - Playwright's `[ref=eN]` ids are per snapshot. Its boxes are `getBoundingClientRect` in a different pruning.
  - Sharing `PageController` makes refs, pruning and errors identical across drivers, which I2 needs.
  - `ariaSnapshot({mode: "ai", boxes: true})` remains an option for a future "describe" tool.
- **The driver never decides permissions.** The policy says where the agent may go; the broker decides what it may do there. Redirects and popups to new origins stop with `approval_required`, and the tool layer asks.
- **`<select>` and download-by-URL use two fixed functions in a bridge-created isolated world.** They read nothing back. There is no other page script and never one from the model.
- **The bridge frame cap is 16 MiB** (spike 01, amendment 2). `bridge.snapshot` as a desktop composite remains a later optimisation.
- **`*.localhost` hosts need explicit set entries even in dev preview.** Only bare loopback hosts get automatic `write` access. That keeps fixture origins distinct and stops one dev task from reaching every local app.

## Objections to the docs (proceeding with the docs)

- **Security §6 says "Never in the browser: purchases, account creation…"**, while the S08 prompt says "purchase paths = financial". The code classifies them as `financial` or `destructive`, so they ask with `once`-only approvals rather than being refused outright. If "never" must be absolute, the change is one line in `classifyActivation` callers.
- **`bridge.tab.open` requires an http(s) URL** (protocol v1). That forbids opening a blank tab and lets the desktop load the URL before the Gateway attaches, so the first redirect hops are unseen; only the commit check runs. A protocol request follows below.
