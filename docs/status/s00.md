## Independent review

A read-only reviewer checked the Gateway, frames, fake brokers, leak checker and db transactions and verified most findings with scripts. All 15 findings are fixed with regression tests:

- Pairing: an unpaired row squatting on the desktop's device id no longer blocks it; paired devices keep their stored role; pending requests are capped at 20.
- Settings: admin keys match whole segments case-insensitively and include `grants` and `approvals`.
- Events reach only devices holding the event's scope; malformed requests are answered with their id; static read errors no longer crash the process.
- Fakes: grants never cover a more severe side-effect class, task grants need their task, pairing and policy changes are device-only, grant expiry and session revocation on restart are enforced, credential approvals are bound and consumed.
- Leak checker: Error fields, Map/Set entries and base64 at any alignment.
- Migrations re-check under the write lock.

Still open from the review: per-IP pairing rate limits (5/hour, security §10) instead of the global cap (S01).

## Decisions worth knowing

- TypeScript 5.9.3 (the brief says 5.x; 7.0 is current), `@sinclair/typebox` 0.34 rather than the new `typebox` 1.x line, Vitest 5, Biome 2.5 with the `recommended` preset.
- pnpm 12 settings live in `pnpm-workspace.yaml`: `allowBuilds` (better-sqlite3, electron, esbuild) and `publicHoistPattern: [electron]`, which satisfies Electron Forge without a hoisted node-linker.
- `@psyche/testing` exports conformance suites from a subpath because they import vitest.
- Unix socket paths are limited to 104 bytes on macOS; deep `PSYCHE_HOME` paths need `PSYCHE_NODE_SOCKET`.

## Objections to the docs (proceeding with the docs)

- `CredentialKind` is `payment_link` in data model §6 but `payment` in architecture §4.7 and security §4.4. The schema follows the data model; S06 should pick one.
- Security §3.7 makes pairing and policy-change approvals device-only, but data model §4 lists no such approval kinds. Added `pairing` and `policy_change` to `ApprovalKind` additively.
- Feature A1 says "`pnpm dev` starts Gateway + desktop + web"; the desktop's dev task opens an Electron window, so headless CI cannot run `pnpm dev`.
