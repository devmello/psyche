# S02 status: agent runtime (`packages/agent-core`)

Updated 2026-10-19. Plan: [docs/plans/s02.md](../plans/s02.md). Package README: [packages/agent-core/README.md](../../packages/agent-core/README.md).

## What works (M1)

- **Loop (C1)**: `PsycheAgentLoop` implements `AgentLoop`. Steer skips the rest of the tool batch and injects guidance; follow-ups run in order when the model would stop; `finishTurn → end | continue`; all seven hooks in architecture §13 order; step and token budgets with visible markers; cancellation revokes run authority and closes dangling tool calls.
- **Tool registry (C3)**: `AgentToolRegistry` implements `ToolRegistry`; `defineTool` with TypeBox schemas (validated before the broker); `mcp__<server>__<tool>` helpers; per-tool toggles; active set by permission mode and run mode.
- **Context assembly (C2)**: base prompt → persona files (20k / 4k `USER.md` / 60k total, missing and truncated markers) → skills index → tools → yesterday's and today's daily notes → compaction summary; untrusted sections fenced and labelled. Golden file in `packages/agent-core/test/fixtures/prompt.golden.txt`.
- **Compaction (B7)**: estimate against the model's context window → `MemoryStore.flush` on a private copy (skipped for incognito threads) → `before_compaction` → utility-model summary; summaries of untrusted content stay marked untrusted.
- **Permission path and taint**: hooks → `decide` with taint and `newTarget` → approval with binding verification → receipt for write+ actions. Provenance never goes below the spec's `provenanceOut`; untrusted results, provider-executed tool results and `[untrusted]` daily-note lines taint the turn; tasks created from tainted turns pass their taint on.
- **Questions (C4)**: `ask_user` (1–4 questions, 2–4 options, header ≤12, recommended first, no explicit "Other", safe previews); attended runs park in-turn, task runs park through `TaskEngine.requestInput`.
- **Plan mode and checklist (C5)**: read-only tool set, `exit_plan_mode` → `plan_exit` approval → mode change; `update_plan` and `wrap_up` blocks.
- **Unattended contract (C8)**: `NO_REPLY` silent, empty final fails, approvals queued with a notification, `ask_user` withheld.
- **Composer commands (C9)**: `parseComposerInput` → `ComposerIntent` for all twelve commands.
- **Prompt viewer (C11)**: `explainContext(runId)`.
- Tests: 71 in `packages/agent-core/test` (scripted `FakeModelProvider` for every case in the prompt's definition of done, golden prompt, unit tests, and `security.test.ts` for the fixes from the independent security review).

## Security review (independent subagent, 2026-10-19)

Fixed: `memory view` returned plain workspace files as trusted (now untrusted unless a persona file or a clean daily note); tainted turns could ask to write protected memory (now refused before any card, and protected writes offer `once` only); `newTarget` used substring and `display` matching (now exact canonical tokens from the owner's text, approved targets only); write+ calls without a target were never new (now fail closed); no abort check between `decide` / `verifyBinding` and dispatch; `describeCall` could borrow another tool's `grantKey` or bind a subset of the params (grant keys are namespaced by tool; the binding always includes tool + params hash); taint did not carry to later turns while untrusted content stayed in context; case-variant protected paths; `task.start` in plan mode; fence look-alikes and attribute injection; unattended hook suspends; external executor errors were trusted.

## Decisions and doc notes

- The prompt says "zod → JSON Schema"; the protocol uses TypeBox, whose schemas are JSON Schema, so tools use TypeBox (no zod dependency).
- Attended approvals and questions park inside the turn; a run with a `taskId` hands its question to the task engine and ends `awaiting_input`.
- `ask_user` answers are keyed by question `header`, matching `questions.answer` in S12's protocol PR (#7).
- Hooks run before `decide` (security §3.3 puts hard prohibitions and deny rules first). Hooks can only block or suspend, and the broker still decides afterwards, so the outcome is the same; the audit order differs.
- Taint is turn-scoped in security §3.6, but a turn starts tainted while untrusted tool results or an untrusted compaction summary are still in its context: the model still reads that content. This is stricter than the doc's wording; S05 may want the doc to say so.
- Follow-ups and steers are treated as the owner's words (target matching, `user` role). The Gateway must only route owner messages through them.
- With `kind` set, `bindingHash` = `bindingHash(kind, {tool, paramsHash, fields: bindingFields})`, a superset of data model §4.2, so it always covers every argument.
- `exit_plan_mode` is the model-facing name of the `ExitPlanMode` tool in the docs (snake_case like the other built-ins).

## Requests to other sessions

- **S01 (Gateway)**: store subagent events from `onSubagentEvent` for the Subagents pane (view-only transcripts);  supply a durable `ThreadStateStore`; persist `tool_result_persist` records as `tool_calls` rows; call `answerQuestion` for attended `questions.answer` and route task questions through the task engine; execute `ComposerIntent`s; call `explainContext` for "Show prompt".
- **S03 (model router)**: map tool names with dots (`task.start`) for providers that reject them; emit one `reasoning` event per provider-native block with the data to round-trip; report `contextWindow` in `capabilities`.
- **S05 (permissions)**: `decide` receives `newTarget` computed by the loop (target not in the owner's text and not approved earlier in the run); `plan_exit` approvals are requested with `sideEffect: "write"` and `scopesOffered: ["once"]`.
- **S07 (memory)**: add `provenance` to `MemoryFile` so `memory view` can trust agent-written files from clean turns; make a file-backed store reject case aliases of protected files; implement `MemoryStore.flush`; add `delete` / `rename` so the `memory` tool can offer them; keep the `[untrusted]` tag on daily-note lines (the loop taints turns that inject them).
- **S04 (tasks)**: the evaluator runs inside the loop, so a task run that ends `final` has passed it; an answer of "Mark it done" to a "Not verified" question should close the task without another run, "Try again" re-queues it.  a task question re-queues the task; its next turn should include the answer in the input text.
