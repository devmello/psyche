# S11 status: desktop and web shells

Updated 2026-10-19. Branch `ws/s11-desktop-web-shell`; protocol PR [devmello/psyche#14](https://github.com/devmello/psyche/pull/14) (`ws/s11-protocol-bridge`) is cherry-picked onto it until it merges. Plan: [docs/plans/s11.md](../plans/s11.md).

## Works (tested)

- **Shared client** (`@psyche/web/client`): one `GatewayConnection` for desktop main and web. The duplicated bootstrap helpers are gone (S00's request).
- **Shell** (`@psyche/web/shell`), one React app for both hosts:
  - rail and bottom tabs, thread list, chat with streaming
  - approval dock (Deny first, 400 ms arming, ⌘Return and ⌘D)
  - composer: slash commands, attachments, follow-up queue, mode and model pills, dictation
  - palette, shortcut sheet, offline and pairing banners, quick entry, pop-out routes
- **Pane layout engine**:
  - per-thread tab strips, split at ≥ 1440 px, resize with clamping, pop-out, ⌘\ with focus returning to the opener
  - `view.command` validated against the protocol, `view.report` sent after every change
  - persisted per thread (69 tests)
- **Desktop main**:
  - app:// renderer, typed preload, IPC payload validation, microphone only for app renderers
  - menu-bar item (Quit vs Quit entirely), ⌥Space quick entry, `psyche://` deep links (routes only)
  - notification relay that defers to the mac helper
- **Gateway lifecycle**: dev child, LaunchAgent `com.psyche.gateway` via launchctl, or external; never starts a second Gateway.
- **Embedded browser**:
  - `WebContentsView` per tab in `persist:agent-<profile>` (symlinked under `$PSYCHE_HOME/browser/profiles`) or a clean per-task partition, `backgroundThrottling: false`
  - popups adopted as tabs, downloads and inline PDFs quarantined
  - status pill and Overlay highlight, pop-out and full screen, clear browsing data
- **CDP bridge client**:
  - `bridge.hello`, 16 MiB frames, reconnect, socket ownership check
  - spike 01 allowlist: isolated-world-only script, no cookies, Storage or Target
  - Take control arbiter: keyboard via `before-input-event`, mouse only outside agent input; agent input refused with `user_in_control`
- **Terminal**: node-pty sessions for exactly the argv the Gateway returns from `terminal.open`, with a minimal env and no host fallback; xterm tabs.
- **Packaging**:
  - fuses: RunAsNode, NODE_OPTIONS, inspect and GrantFileProtocolExtraPrivileges off; ASAR integrity and cookie encryption on
  - signing and notarization from env only ([apps/desktop/docs/signing.md](../../apps/desktop/docs/signing.md))
  - entitlements, `psyche://` in Info.plist, update placeholder
- **Tests**: desktop 198 vitest, web 104 vitest (including the production web build served by `startGateway`), and 7 Playwright-for-Electron smoke tests against the mock Gateway.
  - The smoke tests cover: launch and pair, chat.send, view.* panes, keyboard shortcuts, the browser tab lifecycle over the bridge, Take control, and the download toast.
  - They pass locally on macOS 27 / M5.

## M2 chat slice (branch `ws/s11-m2-chat`, PR [devmello/psyche#126](https://github.com/devmello/psyche/pull/126), 2026-10-19)

- **E5 reply-to and edit**: the kit's Reply chip now reaches the Gateway: `chat.send` gains
  `replyToMessageId` (protocol PR [devmello/psyche#123](https://github.com/devmello/psyche/pull/123),
  cherry-picked here), the session controller stores it on the message and puts the quoted text
  ahead of the turn for the agent (`[Replying to your earlier message <id>]` + a `>` quote of up
  to 280 characters), for direct sends and steers. "Edit and resend" on a user message opens an
  inline editor; sending forks a side chat just before that message (or starts a fresh side chat
  when it was the first), sends the edited text there and opens it; the original transcript is
  untouched. Gateway tests (3) and kit tests (2).
- **E9 incognito threads**: `/incognito [first message]` in the composer creates a `kind:
  "incognito"` side chat (the Gateway sets `expiresAt` 24 h out) and sends the rest there; the
  palette has "New incognito chat"; the shell's thread rows and the agent header show the state.
  The composed Gateway now passes `isIncognito` to the loop, so incognito threads are never
  flushed to memory (the search indexer already skips them, S16).
- **E11 transcript view modes**: Normal / Thinking / Verbose above the chat column map onto the
  kit's disclosure levels 0 / 1 / 2, ⌃O cycles them, and the mode persists per user in the
  cosmetic setting `ui.transcriptMode`. The kit's `DisclosureProvider` and `ChatThread` accept a
  controlled level.

Ownership notes for this slice: `apps/gateway/src/session/controller.ts` and
`handlers/chat.ts` (S01: `replyToMessageId`, `withQuote`), `apps/gateway/src/compose/index.ts`
(INT: `isIncognito`), `packages/ui` `data/hooks.ts`, `chat/Thread.tsx`, `chat/MessageView.tsx`,
`blocks/disclosure.tsx` (S12: reply id on `chat.send`, `onEdit`, `/incognito`, controlled
disclosure). No approval, question or wrap-up card file is touched.

## Composer slash commands, C9 (branch `ws/s11-slash-commands`, stacked on #126, 2026-10-20)

- **Autocomplete**: typing `/` in the kit's composer opens a listbox of the twelve C9 commands
  (name, argument hint, description) filtered by the partial name; ↑ / ↓ move, Tab or Return
  completes, Escape closes. This meets C9's "commands show in the composer with autocompletion",
  which the kit's `SLASH_COMMANDS` constant never rendered.
- **Execution** (`packages/ui/src/chat/commands.ts` mirrors `agent-core`'s grammar; the chat
  column runs them with protocol methods): `/model [ref]` and `/plan [goal]` through
  `threads.update` (#146/#147; "needs a newer Gateway" until then), `/new`, `/btw <question>`
  (a side chat with the question), `/fork [message]`, `/incognito [message]`, `/remember <fact>`
  (`memory.remember`), `/forget <subject>` (dry run, then a Forget button), `/status`,
  `/export [md | json]` (`chat.export`, downloaded), `/stop` (`chat.cancel`), and `/schedule
  <when and what>`, which asks the agent to create the automation with its `schedule` tool, so
  the usual approval card appears. Unknown commands and usage errors show a notice and send
  nothing; `//text` sends a literal slash. Results show in a dismissible notice above the
  composer. The kit's mock Gateway gains `threads.update` and `memory.remember`.
- Channels (Telegram and others) do not run these commands; that is S10's.

## Objections to the docs

- Spike 01 had the desktop listening on the bridge socket, but the protocol has the desktop send `bridge.hello`. S11 follows the protocol: the Gateway listens.
- docs/06 §3.20 shows Approve/Deny on OS notifications. The Electron fallback omits them, because Touch ID and device-only enforcement live on the helper path; a click opens the card instead.
