# S11 status: desktop and web shells

Updated 2026-10-19. Branch `ws/s11-desktop-web-shell`; protocol PR [devmello/psyche#14](https://github.com/devmello/psyche/pull/14) (`ws/s11-protocol-bridge`) is cherry-picked onto it until it merges. Plan: [docs/plans/s11.md](../plans/s11.md).

## Works (tested)

- **Shared client** (`@psyche/web/client`): one `GatewayConnection` for desktop main and web. The duplicated bootstrap helpers are gone (S00's request).
- **Shell** (`@psyche/web/shell`), one React app for both hosts:
  - rail and bottom tabs, thread list, chat with streaming
  - approval dock (Deny first, 400 ms arming, ⌘Return and ⌘D)
  - composer: slash commands, attachments, follow-up queue, mode and model pills, dictation
  - palette, shortcut sheet, offline and pairing banners, quick entry, pop-out routes
- **Pane layout engine**:
  - per-thread tab strips, split at ≥ 1440 px, resize with clamping, pop-out, ⌘\ with focus returning to the opener
  - `view.command` validated against the protocol, `view.report` sent after every change
  - persisted per thread (69 tests)
- **Desktop main**:
  - app:// renderer, typed preload, IPC payload validation, microphone only for app renderers
  - menu-bar item (Quit vs Quit entirely), ⌥Space quick entry, `psyche://` deep links (routes only)
  - notification relay that defers to the mac helper
- **Gateway lifecycle**: dev child, LaunchAgent `com.psyche.gateway` via launchctl, or external; never starts a second Gateway.
- **Embedded browser**:
  - `WebContentsView` per tab in `persist:agent-<profile>` (symlinked under `$PSYCHE_HOME/browser/profiles`) or a clean per-task partition, `backgroundThrottling: false`
  - popups adopted as tabs, downloads and inline PDFs quarantined
  - status pill and Overlay highlight, pop-out and full screen, clear browsing data
- **CDP bridge client**:
  - `bridge.hello`, 16 MiB frames, reconnect, socket ownership check
  - spike 01 allowlist: isolated-world-only script, no cookies, Storage or Target
  - Take control arbiter: keyboard via `before-input-event`, mouse only outside agent input; agent input refused with `user_in_control`
- **Terminal**: node-pty sessions for exactly the argv the Gateway returns from `terminal.open`, with a minimal env and no host fallback; xterm tabs.
- **Packaging**:
  - fuses: RunAsNode, NODE_OPTIONS, inspect and GrantFileProtocolExtraPrivileges off; ASAR integrity and cookie encryption on
  - signing and notarization from env only ([apps/desktop/docs/signing.md](../../apps/desktop/docs/signing.md))
  - entitlements, `psyche://` in Info.plist, update placeholder
- **Tests**: desktop 198 vitest, web 104 vitest (including the production web build served by `startGateway`), and 7 Playwright-for-Electron smoke tests against the mock Gateway.
  - The smoke tests cover: launch and pair, chat.send, view.* panes, keyboard shortcuts, the browser tab lifecycle over the bridge, Take control, and the download toast.
  - They pass locally on macOS 27 / M5.

## Objections to the docs

- Spike 01 had the desktop listening on the bridge socket, but the protocol has the desktop send `bridge.hello`. S11 follows the protocol: the Gateway listens.
- docs/06 §3.20 shows Approve/Deny on OS notifications. The Electron fallback omits them, because Touch ID and device-only enforcement live on the helper path; a click opens the card instead.
