# S11 status: desktop and web shells

Updated 2026-10-19. Branch `ws/s11-desktop-web-shell`; protocol PR [devmello/psyche#14](https://github.com/devmello/psyche/pull/14) (`ws/s11-protocol-bridge`) is cherry-picked onto it until it merges. Plan: [docs/plans/s11.md](../plans/s11.md).

## Works (tested)

- **Shared client** (`@psyche/web/client`): one `GatewayConnection` for desktop main and web. The duplicated bootstrap helpers are gone (S00's request).
- **Shell** (`@psyche/web/shell`), one React app for both hosts:
  - rail and bottom tabs, thread list, chat with streaming
  - approval dock (Deny first, 400 ms arming, ⌘Return and ⌘D)
  - composer: slash commands, attachments, follow-up queue, mode and model pills, dictation
  - palette, shortcut sheet, offline and pairing banners, quick entry, pop-out routes
- **Pane layout engine**:
  - per-thread tab strips, split at ≥ 1440 px, resize with clamping, pop-out, ⌘\ with focus returning to the opener
  - `view.command` validated against the protocol, `view.report` sent after every change
  - persisted per thread (69 tests)
- **Desktop main**:
  - app:// renderer, typed preload, IPC payload validation, microphone only for app renderers
  - menu-bar item (Quit vs Quit entirely), ⌥Space quick entry, `psyche://` deep links (routes only)
  - notification relay that defers to the mac helper
- **Gateway lifecycle**: dev child, LaunchAgent `com.psyche.gateway` via launchctl, or external; never starts a second Gateway.
- **Embedded browser**:
  - `WebContentsView` per tab in `persist:agent-<profile>` (symlinked under `$PSYCHE_HOME/browser/profiles`) or a clean per-task partition, `backgroundThrottling: false`
  - popups adopted as tabs, downloads and inline PDFs quarantined
  - status pill and Overlay highlight, pop-out and full screen, clear browsing data
- **CDP bridge client**:
  - `bridge.hello`, 16 MiB frames, reconnect, socket ownership check
  - spike 01 allowlist: isolated-world-only script, no cookies, Storage or Target
  - Take control arbiter: keyboard via `before-input-event`, mouse only outside agent input; agent input refused with `user_in_control`
- **Terminal**: node-pty sessions for exactly the argv the Gateway returns from `terminal.open`, with a minimal env and no host fallback; xterm tabs.
- **Packaging**:
  - fuses: RunAsNode, NODE_OPTIONS, inspect and GrantFileProtocolExtraPrivileges off; ASAR integrity and cookie encryption on
  - signing and notarization from env only ([apps/desktop/docs/signing.md](../../apps/desktop/docs/signing.md))
  - entitlements, `psyche://` in Info.plist, update placeholder
- **Tests**: desktop 110 vitest, web 207 vitest (including the production web build served by `startGateway`), and 8 Playwright-for-Electron smoke tests against the mock Gateway.
  - The smoke tests cover: launch and pair, chat.send, view.* panes, keyboard shortcuts, the browser tab lifecycle over the bridge, Take control, and the download toast.
  - They pass locally on macOS 27 / M5.

## M2 slice (branch `ws/s11-m2-settings`, 2026-10-19)

- **Settings in the composed app**: `/settings/:section` renders the kit's `SettingsScreen`
  (every §3.18 section); the rail and palette open `/settings/model`. The old
  `/settings/general` route falls back to the first section.
- **Folder picker** (closes the README gap): S11's own File access section
  (`apps/web/src/compose/settings.tsx`) reads and writes `permissions.policy.folders`, the key
  the composed Gateway applies to the broker, instead of the kit's UI-local `permissions.folders`.
  On the desktop a "Choose a folder…" button opens `dialog.showOpenDialog` through the new
  `ShellPlatform.dialogs.pickFolder` port (`psyche:dialog:pick-folder`); main returns the real
  path, since the broker matches real paths. New grants are read only until changed in the list.
  The web host keeps the typed-path input. A refused write (the desktop auto-pairs without
  `operator.admin`) shows the kit's "Needs approval on this device" hint.
- **Tests**: 5 web tests (policy mapping, picker and typed-path writes against the kit's
  `MockGateway`) and an 8th Playwright-for-Electron smoke test that stubs the OS dialog in main
  and checks the `settings.set` the Gateway receives. The smoke mock's `settings.get` now has the
  protocol's shape (`settings`, `stateVersion`) and reports onboarding as done.

- **U4 backups** (Settings → Data controls, below the kit's section): `apps/web/src/compose/backups.tsx`
  lists `backup.list`, creates with "Back up now" (passphrase of 12+ characters sent once and
  cleared, or "Skip encryption"), verifies and deletes per archive, stores the schedule under
  `backup.schedule` (`{interval: off | daily | weekly, keep}`), and shows the restore command
  (restore stays a CLI step with the Gateway stopped).
- **U5 logs** (Settings → About, below the kit's section): `apps/web/src/compose/logs.tsx` is
  the in-app log viewer over `logs.tail`: minimum level, subsystem (from the Gateway's list),
  search, line count; each line shows its fields in a disclosure, so a failed tool call shows its
  tool, code and ids.
- Both panels say "needs a newer Gateway" (with the CLI command) while the Gateway lacks the
  methods. Protocol PR [devmello/psyche#110](https://github.com/devmello/psyche/pull/110)
  (`protocol/s11-backup-logs`) adds `backup.*` and `logs.tail`; it is cherry-picked onto this
  branch until it merges. 7 web tests cover both panels against a handler-table `GatewayClient`.

Ownership notes: `packages/ui/src/screens/settings/SettingsScreen.tsx` gains an additive
`sections` prop on `SettingsShellProps` (a host-rendered section body) so the composed app can
replace one section without a second nav. Request to **S12**: `FileAccessSection` and the folder
summary in `PermissionsSection` read `permissions.folders`, which nothing writes; read
`permissions.policy.folders` (the Gateway's key) so the kit's own section and stories match the app.

## Renderer zoom as a setting (branch `ws/s11-zoom-setting`, stacked on #104, 2026-10-19)

- `appearance.zoom` (percent, default 100, clamped 67–200, cosmetic key) is the one source of
  renderer zoom: View → Zoom In / Zoom Out / Actual Size step along Chrome's presets and store
  it through `settings.set`; main applies the stored value to every app renderer on launch and
  on `did-finish-load` (so Electron's own per-origin zoom memory never wins) and follows
  `settings.changed` from any device; Settings → Appearance (desktop) shows the value with
  −, + and "Actual size" (`apps/web/src/compose/ZoomSetting.tsx`). Shared ladder in
  `apps/web/src/compose/zoom.ts`, controller in `apps/desktop/src/lib/zoom.ts` (5 unit tests),
  a web test for the control and an Electron smoke test (stored 125 % applied at launch, menu
  reset stores 100, `settings.changed` to 150 % applies).

## Objections to the docs

- Spike 01 had the desktop listening on the bridge socket, but the protocol has the desktop send `bridge.hello`. S11 follows the protocol: the Gateway listens.
- docs/06 §3.20 shows Approve/Deny on OS notifications. The Electron fallback omits them, because Touch ID and device-only enforcement live on the helper path; a click opens the card instead.
