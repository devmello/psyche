Updated 2026-10-19 (M2: mail). Plans: [docs/plans/s09.md](../plans/s09.md) (M1), [docs/plans/s09-m2.md](../plans/s09-m2.md) (M2).

## Works

- **`@psyche/mcp-host`** (M1, M2): `PsycheMcpHost` implements `McpHost` on `@modelcontextprotocol/client` 2.3.1. 2026-07-28 via `server/discover` with the 2025-11-25 fallback, MRTR elicitation, Streamable HTTP with OAuth 2.1 (CIMD client id, PKCE, loopback redirect, no DCR), stdio with vault env injection and a mandatory sandboxing launcher for non-bundled servers (`srt`), `tools/list` hashing with rug-pull revocation and change diffs, annotation downgrade, tool-poisoning warnings, MCP Apps resources, agent-core registration. 56 tests against an HTTP echo server, the filesystem reference server over stdio, and a mock authorization server. See the package README.
- **`@psyche/connectors` framework** (M4 data, M11): `ConnectorRegistry` (connect / disconnect / status / sync / action matrix), tools registered as `mcp__<connector>__<tool>` with `describeCall`. The executor wrapper enforces `deny`, read-only scope and `ask` without approval (fail closed). It re-verifies approvals with `verifyBinding` right before dispatch and records `ok` / `failed` / `uncertain` receipts. `allow` is refused for destructive and financial rows. `invalidated` events fire on account change, scope narrowing, disconnect and token revocation. The catalogue holds the Slack / Notion / Linear / GitHub remote MCP presets. `connectors.*` handlers are in place.
- **Google** (M5): desktop OAuth (loopback, PKCE, `state`; every reconnect revokes the old grant; granted scopes are checked both ways). Gmail search / read with hardened MIME parsing and DOM-based hidden-text removal, attachments to the Library (25 MB limit), labels, drafts and send (`send_email` binding per §3.5). `history.list` sync with 404 full resync. Calendar list / bounded events / free-busy / create / update / delete (`calendar_write` binding; invites target the attendee set) with `syncToken` sync and 410 resync. Drive `drive.file` upload (text) and download (Docs as PDF). Revoked tokens move the connector to `needs_auth`, naming the 7-day Testing expiry when it fits. The setup guide is in the package README; the copy is in docs/copy.
- **Redirect hops (#72)**: `safeFetch` takes an `allowHop` policy checked on every redirect before it is resolved or contacted; `web_fetch` allows the request's own origin plus the Task's origin set (`WebFetchFactoryOptions.allowedOrigins`, from the Gateway), and refuses other hops with `redirect_not_allowlisted`. The V7 scenario world now uses the real check. The composed Gateway passes the Task's approved origins (`apps/gateway/src/compose/fetch-origins.ts`: live `new_origin` grants for the call's Task plus `site` / `always` grants; `session` grants are left out because a grant does not name its thread), tested end to end in `tests/integration/fetch-redirects/`. When Tasks store `readOnlyOrigins` / `readWritableOrigins` (S04, S08), add them there.
- **Web search and fetch** (M8): Brave / Exa / Tavily / SearXNG with vault-held keys (never forwarded on redirects). `safeFetch` blocks private, loopback and link-local targets, pins the vetted address against DNS rebinding, re-vets each redirect, caps size and time, converts HTML to Markdown with hidden content dropped, and tags results `untrusted`.

## Doc notes

- Security §5.3 allows stdio MCP servers writes only to a per-process scratch directory, so `srtLauncher` refuses any configured `allowWrite`. A filesystem-style server that must edit the owner's folders therefore cannot run under srt; the M3 container launcher does not mount host folders either (security §5.1: no host mounts besides `/workspace`). It needs a doc change allowing owner-approved, folder-granted mounts for MCP servers.

- Security §11 says annotations are "actionable only for `bundled`". The host still lets `destructiveHint` raise any tool to `destructive` (it only makes policy stricter).
- `@modelcontextprotocol/server-filesystem` 2.0.0 was published today and is blocked by pnpm's release-age gate; tests use 2026.8.31 (SDK v1), which also covers the legacy fallback over stdio. Its npm license field is "SEE LICENSE IN LICENSE" without the file; the README says MIT. Dev dependency only.
