# S16 status — Search and skills

Updated 2026-10-19. Branch `ws/s16-search-skills`. Owner paths: `packages/search/**`, `packages/skills/**`, the `skills` migration and its drizzle mirror, this file. Plan: `docs/plans/s16.md`.

## What works (M1)

- **Unified search (S1)** — `@psyche/search`: FTS5 index (porter, diacritics folded, prefix indexes) in `state/search.sqlite`; query language (`in:`, `type:`, `from:`, `before:`/`after:`/`on:` with relative dates, `has:approval|receipt|attachment`, `is:<provenance>`, `thread:`, phrases, `OR`, `-x`, prefix on the last word) that can never emit FTS5 syntax; BM25 × 30-day recency boost; grouped results in UI order with counts, collapsing messages onto threads and actions onto tasks; plain snippets with highlight ranges; memory fused live from `MemoryStore` by reciprocal rank fusion; adapters for threads, messages, tasks, actions, Library, feed, ideas, goals, connector caches; `SearchIndexer` for `thread.updated|deleted`, `chat.message`, `task.updated`, `task.action`, `approval.created`, `receipt.created`, `feed.post|updated`, `idea.updated`, `goal.updated`; `search.query` handler with deep-link routes. Passes the `SearchIndex` conformance suite.
- **Permissions in search**: incognito content is never stored (and removed when a thread turns incognito); designated-person threads are scoped to their session key and a delegated viewer sees only that scope and never memory; provenance on every hit.
- **Performance**: 100 000 documents, worst query ~130 ms (term in 70 % of the corpus), filtered and rare queries < 25 ms.
- **Skills loader (T1)** — `@psyche/skills`: discovery workspace → `$PSYCHE_HOME/skills` → bundled with precedence and "overrides"; frontmatter validation (Agent Skills fields, OpenClaw metadata, S20's `requires.tools` / `anyTools` globs); gating on bins / env / OS / tools; statuses (`active, disabled, ineligible, blocked, draft, unlocked, hash_mismatch, invalid, shadowed`); `<available_skills>` index under a character budget with an explicit omission marker; `skills_search` / `skills_read` tools; `$skill` references (max 8); slash commands; hot reload. S20's twelve bundled skills load, list and fit in ~3 800 characters.
- **Install and trust (T2)**: local folder, `.zip` / `.skill`, git at a ref pinned to a commit (no checkout); limits, symlink and traversal refusal; static scanner (pipe-to-shell, prerequisites that fetch or install, Gatekeeper bypass, persistence, credential access, exfiltration endpoints, secrets, encoded payloads, invisible characters, agent-directed instructions); optional VirusTotal by hash; `skill_install` approval (device-only, once) bound to name + scope + source + whole-tree hash; install writes exactly the scanned tree, lock file with pins, receipt; high findings install disabled and cannot be enabled; whole-tree hash re-verified on every load; update with per-file diff and re-approval; disable / remove; `skills.*` handlers.
- **`skills` table** (data model §10): migration `202610191300_skills_init.sql`, mirror `schema-s16.ts`, `SqliteSkillStateStore`.
- Tests: search 39 (parser, ranking, filters, scoping, grouping, events, handler, conformance, 100k performance); skills 72 (frontmatter, gating, scanner incl. bundled skills clean, prompt budget, references, diff, precedence, drafts, hash mismatch, state, tools, install via path / zip / git, approvals, lock, update diff, VirusTotal, handlers, hot reload).

## Decisions and doc deviations

- **Search index in its own file** (`state/search.sqlite`) instead of `psyche.sqlite` (ADR-004 says one file): it is derived and rebuildable, and its write volume should not contend with the transcript writer. `docs/02` §12 and `docs/04` §10 updated. S01 may ask to move it into the main DB; the package accepts any connection (`db` option).
- **Workspace skills need the owner's approval** (review design-02, Critical): architecture §13 says workspace skills are discovered; they still are, but load only with an owner approval in the lock file. `requireWorkspaceApproval: false` disables this.
- **Third-party skill text is `untrusted`** when read through `skills_read` (review design-24); bundled and owner-approved local skills are trusted.
- **`skill_install` cards use side-effect class `destructive`** so they are `once`-only and device-only, although installing is reversible. Binding fields: `{name, scope, source, treeHash}`; grant key `skill_install|<name>`. Docs 04 §4.2 / 05 §3.5 have no row for `skill_install`; proposed text is in `packages/skills/README.md`.
- `acceptance.md` files are hashed and scanned (they ship in the folder) but never given to the model. S20's acceptance fixtures contain injected-instruction text on purpose, so a scan of the whole bundled folder has `agent-directed-instruction` findings in `acceptance.md`; bundled skills are not scanned at load.
