# Background specialists: how other frameworks delegate to child agents

Research for the Psyche "background specialists" design (researcher, shopper, coder, organizer, writer, planner). Sources were read on 2026-10-25. Versions at that date: Claude Code docs reference releases up to v2.1.309 ([agent teams](https://code.claude.com/docs/en/agent-teams)); `openai-agents` 0.24.0, released 2026-10-15 ([PyPI](https://pypi.org/project/openai-agents/)); `crewai` 1.15.30, released 2026-10-24 ([PyPI](https://pypi.org/project/crewai/)); `langgraph` 1.2.17, released 2026-10-24 ([PyPI](https://pypi.org/project/langgraph/)). The Microsoft AutoGen repository is archived and points new users to Microsoft Agent Framework ([microsoft/autogen README](https://github.com/microsoft/autogen)).

## Takeaways for Psyche

- **Start each specialist fresh, from a structured brief.** Claude Code subagents see their system prompt, the delegation message and project instructions, not the parent conversation ([sub-agents](https://code.claude.com/docs/en/sub-agents)). `Agent.as_tool` does not inherit the parent's history either ([tools](https://openai.github.io/openai-agents-python/tools/)). Anthropic found vague briefs caused duplicated work; a brief needs an objective, output format, tools and sources, and boundaries ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)). Psyche should require those fields plus budget and deadline.
- **Return a short result plus artifact references, not the transcript.** Claude Code returns only the final message ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). Anthropic has subagents write to external storage and pass lightweight references back ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).
- **Enforce budgets in the runtime, not the prompt.** `maxBudgetUsd` refuses new spawns, stops background subagents and ends the query with `error_max_budget_usd` ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). OpenAI tracks usage but has no spend cap ([usage](https://openai.github.io/openai-agents-python/usage/)). AutoGen composes token, time and message limits with `|` and `&` ([termination](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html)). Psyche should cap turns, tokens, dollars and wall-clock time together.
- **Make "partial" a result state.** Claude Code marks `maxTurns` output partial and resumable, and a background subagent killed by an API error still delivers its last output ([sub-agents](https://code.claude.com/docs/en/sub-agents)). `/deep-research` reports unchecked claims as "unverified", not refuted ([workflows](https://code.claude.com/docs/en/workflows)). Result cards need `complete | partial | failed | cancelled`.
- **Approvals must survive a long wait.** AutoGen's `UserProxyAgent` blocks the team, which then cannot be saved ([human-in-the-loop](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/human-in-the-loop.html)). OpenAI serializes `RunState` with pending interruptions ([HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)), LangGraph checkpoints at `interrupt()` ([interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)), and Claude's SDK has a `defer` hook decision so the process can exit and resume ([user input](https://code.claude.com/docs/en/agent-sdk/user-input)). Psyche should park a waiting specialist durably.
- **Relay approvals to the owner under the child's name; agent text is never consent.** Claude Code labels background-subagent prompts with the subagent's name ([sub-agents](https://code.claude.com/docs/en/sub-agents)) and marks inter-agent messages as not from the user, so an agent cannot approve on the user's behalf ([agent teams](https://code.claude.com/docs/en/agent-teams)). OpenAI surfaces nested approvals on the outer run ([HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)).
- **Treat specialist output as untrusted.** Since v2.1.210, Claude Code neutralizes instruction-shaped text (fake control tags, turn markers) in a subagent's report before the parent reads it ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)).
- **One checkpoint mechanism for pause, resume and crash recovery.** LangGraph checkpoints each super-step and keeps successful nodes' writes when another fails ([checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)). Claude workflows replay completed agents from saved results ([workflows](https://code.claude.com/docs/en/workflows)). Anthropic resumes from checkpoints rather than restarting ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).
- **Hard caps on concurrency and depth, with low defaults.** Claude Code: 20 concurrent subagents, 3 nesting levels ([sub-agents](https://code.claude.com/docs/en/sub-agents)); workflows: 16 concurrent, 1,000 per run ([workflows](https://code.claude.com/docs/en/workflows)); teams: start with 3–5 ([agent teams](https://code.claude.com/docs/en/agent-teams)). Psyche: a per-owner cap, no nesting by default, a queue beyond the cap.
- **Effort-scaling rules in the main agent's prompt, backed by caps.** Anthropic: 1 agent and 3–10 tool calls for a fact, 2–4 subagents for a comparison, 10+ for complex research; early versions spawned 50 subagents for simple queries ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).
- **Show cost before and during a run.** Multi-agent used about 15 times chat's tokens ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)). Claude Code warns above 25 agents or 1.5M projected tokens and shows per-agent tokens live ([workflows](https://code.claude.com/docs/en/workflows)).
- **Separate graceful stop from hard cancel.** AutoGen's `ExternalTermination` stops after the current turn; a cancellation token aborts at once ([teams](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html)). OpenAI's `cancel(mode="after_turn")` stays resumable ([running agents](https://openai.github.io/openai-agents-python/running_agents/)).

## 1. Claude Code subagents and the Claude Agent SDK

**Definition.** A subagent is a Markdown file with YAML frontmatter, and the body becomes the system prompt. Only `name` and `description` are required. Optional fields include `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `background`, `effort` and `isolation: worktree` ([sub-agents](https://code.claude.com/docs/en/sub-agents)). The SDK accepts the same shape as `AgentDefinition` in the `agents` option, and programmatic definitions override file-based ones ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). Larger patterns build on this primitive. Agent teams are peer sessions with a shared task list and mailboxes ([agent teams](https://code.claude.com/docs/en/agent-teams)). Dynamic workflows are JavaScript scripts that call `agent()`, `parallel()` and `pipeline()` ([workflows](https://code.claude.com/docs/en/workflows)).

**Context scoping.** A non-fork subagent starts fresh. Its only input from the parent is the Agent tool's prompt string, so file paths, errors and decisions must be written into that prompt. It does not receive the parent's history, tool results or system prompt ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). A fork instead inherits the whole conversation and the parent's tool pool ([sub-agents](https://code.claude.com/docs/en/sub-agents)). Teammates load project context but not the lead's history ([agent teams](https://code.claude.com/docs/en/agent-teams)).

**Tool allowlists.** `tools` is an allowlist, `disallowedTools` applies first, and omitting `tools` inherits the parent's. `AskUserQuestion` and a few others are always removed, so a subagent cannot question the user directly. Background subagents get a reduced built-in set ([sub-agents](https://code.claude.com/docs/en/sub-agents)). SDK permission checks run: hooks, deny rules, ask rules, permission mode, allow rules, `canUseTool`. Deny rules hold even in `bypassPermissions`; parent plan mode forces plan mode on subagents ([permissions](https://code.claude.com/docs/en/agent-sdk/permissions)).

**Model choice.** Per-call `model`, then the definition's `model` (`inherit` = parent's), then `CLAUDE_CODE_SUBAGENT_MODEL`, then the parent's model. Routing simple work to Haiku is the documented cost lever ([sub-agents](https://code.claude.com/docs/en/sub-agents)).

**Budgets and stop conditions.** `maxTurns` stops a subagent and marks its output as partial. In the SDK, `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20) and `maxBudgetUsd` (no default) bound the tree of agents ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). In workflows, an agent that produces no output for its stall window (`stallMs`) restarts, at most five times ([workflows](https://code.claude.com/docs/en/workflows)).

**Result handoff.** The parent receives only the final message, and may summarize it further ([Agent SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). Workflow agents can return JSON that must match a `schema`, and a call fails after five validation attempts ([workflows](https://code.claude.com/docs/en/workflows)). The docs warn that parallel subagents returning detailed reports can use a lot of the main conversation's context ([sub-agents](https://code.claude.com/docs/en/sub-agents)).

**Progress.** Background results arrive as a completion notification in a later turn; `/tasks` lists and stops work, the SDK sends `stop_task`, and Claude can call `TaskStop` ([sub-agents](https://code.claude.com/docs/en/sub-agents)). Subagent messages carry `parent_tool_use_id` (and `agent_id` in TypeScript); `SubagentStart`/`SubagentStop` hooks receive `agent_id`, `agent_type` and a transcript path ([hooks](https://code.claude.com/docs/en/agent-sdk/hooks)). `/workflows` shows phases, agent counts, and each agent's prompt, recent tool calls and result ([workflows](https://code.claude.com/docs/en/workflows)).

**Approvals.** `canUseTool` can allow (optionally with modified input), deny with a message Claude reads, or approve-and-remember via `updatedPermissions`. It may wait indefinitely; for long waits, a `PreToolUse` hook returns `defer` ([user input](https://code.claude.com/docs/en/agent-sdk/user-input)). A `Notification` hook fires after a request waits about six seconds ([hooks](https://code.claude.com/docs/en/agent-sdk/hooks)).

**Failure handling.** A foreground subagent cut off after producing text returns that text with a note; a background one is marked failed and delivers its last output ([sub-agents](https://code.claude.com/docs/en/sub-agents)). In workflows a failed agent inside `parallel()`/`pipeline()` yields `null`; on relaunch it and every later-started agent rerun ([workflows](https://code.claude.com/docs/en/workflows)). `SendMessage` resumes a subagent with full history; transcripts persist 30 days by default ([sub-agents](https://code.claude.com/docs/en/sub-agents)).

**Parallelism and cost.** Defaults: 20 concurrent subagents; in workflows 16 concurrent agents, 4,096 items per `parallel()`, 1,000 agents per run. Matching fan-out agents share a prompt-cache prefix, with siblings held up to 5 seconds so they read it ([workflows](https://code.claude.com/docs/en/workflows)). Teams cost more because each teammate is a full instance ([agent teams](https://code.claude.com/docs/en/agent-teams)).

## 2. OpenAI Agents SDK (Python 0.24.0)

**Definition.** There are two composition styles. A **handoff** transfers control: it appears to the model as a tool such as `transfer_to_refund_agent`, and `handoff()` accepts `on_handoff`, `input_type`, `input_filter` and `is_enabled` ([handoffs](https://openai.github.io/openai-agents-python/handoffs/)). With **agents as tools** (`Agent.as_tool`), the caller stays in charge and receives the specialist's output ([multi-agent](https://openai.github.io/openai-agents-python/multi_agent/)). The docs also describe code-driven orchestration: chaining, evaluator loops and `asyncio.gather` fan-out ([multi-agent](https://openai.github.io/openai-agents-python/multi_agent/)).

**Context scoping.** By default, the receiving agent of a handoff sees the full prior conversation. `input_filter` can trim it, for example with `remove_all_tools`. An opt-in beta, `nest_handoff_history`, condenses earlier turns into a summary block, and the docs note that this does not redact sensitive data ([handoffs](https://openai.github.io/openai-agents-python/handoffs/)). An `as_tool` run does not inherit the parent's state. It gets either a single `input` string or a typed `parameters` model, and history is shared only if both runs are given the same `session` ([tools](https://openai.github.io/openai-agents-python/tools/)).

**Tools and model.** Each agent declares its own tools and `model`. `RunConfig.model` overrides every agent's model for a run ([running agents](https://openai.github.io/openai-agents-python/running_agents/)). `is_enabled` can hide a tool or handoff at runtime ([tools](https://openai.github.io/openai-agents-python/tools/)).

**Budgets and stop conditions.** `max_turns` defaults to 10 (`DEFAULT_MAX_TURNS`) and `None` disables it ([0.16.0 release notes](https://newreleases.io/project/pypi/openai-agents/release/0.16.0), secondary source). Exceeding it raises `MaxTurnsExceeded`, unless an `error_handlers["max_turns"]` handler returns a controlled final output ([running agents](https://openai.github.io/openai-agents-python/running_agents/)). There are `ModelSettings.timeout` and tool timeouts. Usage is tracked in `result.context_wrapper.usage`, but there is no built-in spend cap ([usage](https://openai.github.io/openai-agents-python/usage/)).

**Result handoff.** By default, a nested run's final output becomes the tool result. `custom_output_extractor` can reshape it or pull a JSON payload out of it ([tools](https://openai.github.io/openai-agents-python/tools/)).

**Progress.** `on_stream` receives the nested agent's streaming events ([tools](https://openai.github.io/openai-agents-python/tools/)). Tracing is on by default, with spans for agents, generations, function calls, guardrails and handoffs. A `group_id` links the traces of one thread, and `trace_include_sensitive_data` defaults to true ([tracing](https://openai.github.io/openai-agents-python/tracing/)).

**Approvals and guardrails.** `needs_approval` (boolean or async policy) pauses the run; pending `ToolApprovalItem`s appear in `result.interruptions`, resolved with `state.approve()`/`state.reject()` before resuming. Nested `as_tool` approvals surface on the outer run. `RunState` serializes to JSON, but unauthenticated, so the docs say to store it server-side and prevent replayed resumes ([HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)). Input guardrails run only for the first agent, output guardrails only for the last; a parallel input guardrail may let tokens or tools run before it trips. Tool guardrails skip handoffs and `Agent.as_tool` ([guardrails](https://openai.github.io/openai-agents-python/guardrails/)).

**Failure handling.** A failing tool sends the model an error message, which `failure_error_function` can customize ([tools](https://openai.github.io/openai-agents-python/tools/)). The `invalid_final_output` and `model_refusal` handlers substitute a fallback output without retrying ([running agents](https://openai.github.io/openai-agents-python/running_agents/)).

**Parallelism.** No built-in cap. The SDK runs within one process, and parallel work uses `asyncio.gather` ([multi-agent](https://openai.github.io/openai-agents-python/multi_agent/)).

## 3. Anthropic, "How we built our multi-agent research system" (2025-06-13)

**Architecture.** An orchestrator-worker design: an Opus 4 lead and Sonnet 4 subagents. On Anthropic's internal research eval it scored 90.2% higher than single-agent Opus 4. A separate CitationAgent attaches sources to the final report ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

**Token use and performance.** On BrowseComp, three factors explained 95% of the variance in performance. Token usage alone explained 80%; tool-call count and model choice explained the rest. Agents use about 4 times the tokens of chat, and multi-agent systems about 15 times. The task's value has to justify that cost ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

**Number of subagents and effort scaling.** The lead starts 3–5 subagents in parallel, and each subagent calls 3 or more tools in parallel. This cut research time by up to 90% on complex queries. The scaling rules: simple fact-finding uses 1 agent with 3–10 tool calls, direct comparisons use 2–4 subagents with 10–15 calls each, and complex research uses more than 10 subagents with divided responsibilities ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

**Lead and subagent prompt lessons.** Simulate agents step by step with the exact prompts and tools they will get. Give the lead detailed delegation instructions: objective, output format, tools and sources, and boundaries. Embed effort-scaling rules. Give tools distinct purposes and clear descriptions; a tool-testing agent that rewrote tool descriptions cut later task time by 40%. Search broad first, then narrow. Use extended thinking for the lead's planning and interleaved thinking in subagents. Parallelize both spawning and tool calls. Prompts should encode heuristics rather than rigid rules. The lead saves its plan to memory because context beyond 200,000 tokens is truncated ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

**Evaluation.** Start immediately with small samples; about 20 real queries were enough to detect large effects. One LLM-judge prompt scored factual accuracy, citation accuracy, completeness, source quality and tool efficiency, outputting 0.0–1.0 scores and a pass/fail grade. It agreed most closely with human judgment. Judge the end state, not the path taken. Human testers caught agents preferring SEO content farms over authoritative sources ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

**Failure modes.** Early versions spawned 50 subagents for simple queries, searched endlessly for sources that did not exist, distracted each other with excessive updates, and duplicated work when briefs were vague. Small changes to the lead could change subagent behavior unpredictably. Because agents are stateful, errors compound. The remedies were resuming from checkpoints, retry logic combined with letting the agent adapt to tool failures, full production tracing, and rainbow deployments so running agents are not broken by updates. Execution is synchronous: the lead waits for each batch, cannot steer subagents mid-run, and one slow subagent blocks the rest ([research system](https://www.anthropic.com/engineering/multi-agent-research-system)).

## 4. CrewAI, AutoGen / AG2, LangGraph

### CrewAI (1.15.30)

**Definition and context.** Agents have a `role`, `goal`, `backstory`, `llm` and `tools`. Defaults include `max_iter=20`, `max_retry_limit=2`, `allow_delegation=False` and `respect_context_window=True`, which summarizes rather than errors when the context limit is reached. `max_execution_time` sets a time limit in seconds ([agents](https://docs.crewai.com/en/concepts/agents)). Tasks pass earlier results forward through `context=[...]`, and task-level `tools` override the agent's tools ([tasks](https://docs.crewai.com/en/concepts/tasks)). An agent with delegation enabled gets "Delegate work to coworker" and "Ask question to coworker" tools, each taking `task` or `question`, `context` and `coworker` strings. The docs advise disabling delegation on specialists to prevent delegation loops ([collaboration](https://docs.crewai.com/en/concepts/collaboration)).

**Hierarchical process and flows.** `Process.hierarchical` adds a manager, set via `manager_llm` or `manager_agent`, that assigns tasks and validates results ([hierarchical process](https://docs.crewai.com/en/learn/hierarchical-process)). Flows add `@start`, `@listen` and `@router`, typed state, `@persist` (SQLite by default) with resume by `id`, and `@human_feedback` from 1.8.0 ([flows](https://docs.crewai.com/en/concepts/flows)).

**Results, approvals, failure, cost.** `TaskOutput` carries `raw`, plus `json_dict` or `pydantic` when an output model is set. `human_input=True` sends a task's final answer to a person for review. Guardrails validate output with up to `guardrail_max_retries=3` retries ([tasks](https://docs.crewai.com/en/concepts/tasks)). `CrewOutput.token_usage` and `crew.usage_metrics` report tokens; the limits are `max_rpm` and the iteration and time caps ([crews](https://docs.crewai.com/en/concepts/crews)). Parallel work uses `async_execution` on tasks and `akickoff_for_each` ([crews](https://docs.crewai.com/en/concepts/crews)).

### Microsoft AutoGen (AgentChat) and AG2

**Status.** The AutoGen README says the project is archived, accepts only bug fixes and security patches, and directs new users to Microsoft Agent Framework ([microsoft/autogen](https://github.com/microsoft/autogen)). Secondary sources date Agent Framework's general availability to 2026-04-02; I did not confirm this on a Microsoft page ([Atlan](https://atlan.com/know/ai-agent/what-is-autogen/)). AG2 is the community fork ([Atlan](https://atlan.com/know/ai-agent/what-is-autogen/)).

**Group chat and context.** AutoGen presets: `RoundRobinGroupChat`, `SelectorGroupChat` (a model picks the next speaker), `Swarm` (handoffs), `MagenticOneGroupChat`. In round-robin every agent sees every response; `run_stream()` yields messages, then a `TaskResult` with stop reason ([teams](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html)). AG2 group chat shares one conversation plus context variables ([AG2 group chat](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/introduction)).

**Nested chats.** AG2's `register_nested_chats(chat_queue, trigger)` runs inner chats when a trigger matches; the outer agent replies with a summary of the last one (`summary_method`, e.g. `last_msg`), and each inner chat has its own `max_turns` ([AG2 nested chat](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/nested-chat/)). Outer context reaches it only through carryover ([AG2 swarm nested chat](https://docs.ag2.ai/docs/user-guide/advanced-concepts/swarm/nested-chat)).

**Termination.** AutoGen has 11 built-in conditions, including `MaxMessageTermination`, `TokenUsageTermination`, `TimeoutTermination`, `HandoffTermination`, `ExternalTermination` and `FunctionCallTermination`. Conditions combine with `|` and `&` and are checked after each agent response ([termination](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html)). AG2 caps runs with `max_rounds` ([AG2 patterns](https://docs.ag2.ai/0.9/docs/user-guide/advanced-concepts/orchestration/group-chat/patterns)).

**Approvals.** There are two modes: a blocking `UserProxyAgent` inside the run, or ending the run (via `max_turns` or `HandoffTermination(target="user")`) and passing feedback into the next `run()`, with state preserved ([human-in-the-loop](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/human-in-the-loop.html)).

### LangGraph (1.2.17)

**Supervisor and subagents.** LangChain lists five patterns: subagents (called as tools by a supervisor), handoffs, skills, router, custom workflow. Subagents are stateless and start fresh each call; in the guide's illustrative comparison they finish a multi-domain request in 5 calls and ~9K tokens versus 7+ calls and 14K+ for handoffs ([multi-agent](https://docs.langchain.com/oss/python/langchain/multi-agent)). `langgraph-supervisor` was archived 2026-09-20 in favor of tool-calling supervisors; it offered `output_mode="full_history"` or `"last_message"` and a `forward_message` tool that passes a worker's answer through verbatim ([langgraph-supervisor-py](https://github.com/langchain-ai/langgraph-supervisor-py)).

**Subgraphs.** Add a subgraph as a node sharing state keys, or invoke it inside a node with mapped state. Checkpointing is per-invocation (default), per-thread, or off; per-thread subgraphs cannot run in parallel ([subgraphs](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)).

**Fan-out and limits.** Conditional edges return `Send(node, state)` objects for map-reduce. `Command(goto=..., update=..., graph=Command.PARENT)` routes from a subgraph to its parent. `recursion_limit` defaults to 1000 super-steps (since 1.0.6) and raises `GraphRecursionError` ([graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)).

**Interrupts and checkpointing.** `interrupt(value)` pauses and saves state. This requires a checkpointer and a `thread_id`, and `Command(resume=...)` continues the run. On resume the node re-runs from its start, so side effects before the interrupt must be idempotent ([interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)). Checkpoints are saved per super-step, can be replayed or forked, and keep pending writes when a node fails. Durability modes are `exit`, `async` and `sync` ([checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)). Progress streams per subgraph with `stream_events(..., version="v3")` ([subgraphs](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)).

## Patterns compared

| Facet | Claude Code / Agent SDK | OpenAI Agents SDK | Anthropic research system | CrewAI | AutoGen / AG2 | LangGraph |
|---|---|---|---|---|---|---|
| Context scoping | Fresh context; prompt string only; fork opt-in | Handoff: full history unless filtered; `as_tool`: fresh | Fresh subagents; lead keeps plan in memory | Task `context` outputs; delegation `context` string | Shared group transcript; nested chats via carryover | Stateless subagents; subgraph state mapping |
| Tool scoping | `tools` allowlist, `disallowedTools` first; some tools always removed | Per-agent tools; `is_enabled` | Distinct tools per purpose; descriptions tuned | Agent tools, task tools override | Per-agent tools | Per-agent tools; nodes are code |
| Budget | `maxTurns`, `maxBudgetUsd`, depth 3, concurrency 20, stall restarts | `max_turns` 10; timeouts; usage tracked, no spend cap | Effort-scaling rules in prompt | `max_iter` 20, `max_execution_time`, `max_rpm` | Composable token/time/message conditions | `recursion_limit` 1000 |
| Result handoff | Final message only; optional JSON schema | Final output; `custom_output_extractor` | Condensed findings; references to stored outputs | `raw` / JSON / Pydantic `TaskOutput` | Summary of last nested chat | `last_message` or full history; `forward_message` |
| Progress | Completion notification, `/tasks`, `/workflows`, hooks, `agent_id` | `on_stream`, tracing spans | Production tracing | `step_callback`, `task_callback` | `run_stream()` messages | Subgraph event streaming |
| Approvals | Prompts relayed to owner with agent name; `canUseTool`; `defer` | `needs_approval`, serializable `RunState`, nested approvals bubble up | Not covered | `human_input`, `@human_feedback` | Blocking `UserProxyAgent` or end-run handoff | `interrupt()` + checkpointer |
| Failure | Partial output kept; resumable; `null` in fan-out | Error handlers; tool error messages | Checkpoint resume, retries, rainbow deploys | `max_retry_limit` 2, guardrail retries 3 | Stop reason in `TaskResult` | Pending writes; replay or fork |
| Parallelism | 20 subagents, 16 workflow agents, 1,000 per run | `asyncio.gather`, no cap | 3–5 subagents, 3+ parallel tools | Async tasks, `akickoff_for_each` | Sequential turns | `Send` fan-out |
