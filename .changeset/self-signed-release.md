Releases now use Psyche's own self-signed certificate instead of a paid Apple Developer ID. `deploy/macos/make-signing-cert.sh` makes the certificate once (a password you type, a `.p12`, nothing imported into your keychain). The release signs the app, helper, Node runtime and every addon with it and the hardened runtime, skips notarization, and checks `codesign --verify --deep --strict`, the pinned designated requirement (`deploy/macos/designated-requirements.txt`), the hardened runtime and entitlements, the fuses and the size budgets. The build jobs have no signing secrets: one small `sign` job (environment `release`) signs with `deploy/macos/sign-bundle.sh`, the same script `build-local.sh` uses, running only Apple's tools and our own scripts while its keychain is unlocked. A publishing run fails rather than ship an ad-hoc build. Auto-update now runs only when the running app's own signature satisfies the pinned requirement and a release key is embedded; ad-hoc and development builds still never update themselves.

Because a self-signed app has no team ID, the app and psyched's Node runtime carry `disable-library-validation` (the helper does not). That means same-user malware that can write inside the app bundle could swap a library and inherit Psyche's privacy grants. To limit it, the app checks its own signature seal once a day and, if it fails, warns in your language (ten languages) and turns off the microphone, screen, Apple Events, Contacts and Calendar features until you reinstall. psyched's launcher also clears `NODE_OPTIONS` and `NODE_PATH` and skips `~/.node_modules`. The first open of a downloaded copy needs System Settings › Privacy & Security › Open Anyway once; the release notes say so and ask you to check the download against `SHA256SUMS` first.
